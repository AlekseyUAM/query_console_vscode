# Фаза 6.15 — разбор и снижение остатка mismatch (202) — план

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development
> to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Снизить остаток mismatch приёмки `accept:oracle` (202 → минимум),
исправив исправимые категории и задокументировав неустранимые.

**Architecture:** Правки только в pure-TS ядре (`src/core/query/sdblParser.ts`,
`sdblGenerator.ts`, `exprFormatter.ts`). Каждое новое правило канона подтверждается
живым оракулом MCP `1c-md validate_query` и фиксируется фикстурой
`test/fixtures/oracle/NNNN-*.json` (следующий номер — 0106+).

**Tech Stack:** TypeScript, vitest, esbuild, MCP `1c-md`.

---

## Стандартный цикл задачи (обязателен для каждой категории)

1. **Анализ**: взять свою категорию из `tmp/mismatch-classes.json`; для каждого файла
   достать `input`/`query_text` из `tmp/query1c/oracle/golden.jsonl`
   (`python3 -c "import json; ..."`), получить наш рендер:
   `node -e "const{parseBatch}=require('./out/cli/oracleAcceptCli.js')..."` — проще
   собрать мини-скрипт `node out/cli/oracleAcceptCli.js` уже печатает сводку; для
   точечного диффа использовать `npx tsx` со `src/core/query/...` напрямую.
2. **Правило**: сформулировать гипотезу канона; **проверить живым MCP
   `mcp__1c-md__validate_query`** на минимальном синтетическом запросе (вход → канон).
   Зафиксировать вход/выход в фикстуре `test/fixtures/oracle/NNNN-<slug>.json`
   (формат: `{name, input, expected}`; expected = ровно ответ оракула).
3. **Red**: `npx vitest run test/unit/oracleGolden.test.ts` — новая фикстура падает.
4. **Green**: минимальная правка в `src/core/query/*`; фикстура и весь юнит зелёные:
   `npm test`.
5. **Приёмка**: `npm run accept:oracle` — счёт «принято» строго не меньше прежнего,
   у своей категории — снижение. Записать дельту.
6. **YAML-контракт**: если менялись `src/cf/*` (не должны) — `npm run parse`.
7. **Commit**: `git add -A && git commit -m "feat(phase6.15.N): <категория> — <правило>"`.

Если категория оказалась неисправимой без метаданных/реконструкции конструктора —
не править код, а вернуть точный список файлов + причину (войдёт в ROADMAP).

## Задачи

### Task 1: Быстрые одиночки — `v-ierarhii` (1), `trailing-comma` (1)

- [ ] `В ИЕРАРХИИ (` vs `В ИЕРАРХИИ(`: найти место рендера `В ИЕРАРХИИ` (грепнуть
  `ИЕРАРХИИ` в `src/core/query/`), MCP-пробой выяснить канон пробела
  (по `Reports-АнализЖурналаРегистрации-...bsl_1` ожидается `В ИЕРАРХИИ (&Группа)` с пробелом).
- [ ] `trailing-comma` (`CommonModules-УправлениеДоступомСлужебныйВМоделиСервиса-...bsl_2`):
  наш рендер выводит запятую после последнего поля — найти причину (вероятно
  пустое/потерянное следующее поле), починить.
- [ ] Цикл шагов 2–7 для каждой.

### Task 2: `missing-semicolon` (14)

- [ ] На примере `Catalogs-ПроизводственныеКалендари-Ext-ManagerModule.bsl_4`: сравнить
  input/канон — у пакета теряется завершающий `;` (вероятно `;` без следующего запроса).
- [ ] MCP-проба: одиночный запрос с завершающим `;` → как канонизирует оракул.
- [ ] Починить `parseBatch`/`generateBatch` (хранить/восстанавливать признак
  завершающего `;`), фикстура 01xx, цикл 3–7.

### Task 3: `estnull-truncated` (3)

- [ ] `CommonModules-АдресныйКлассификаторСлужебный-...bsl_16`: парсер теряет хвост
  вложенных `ЕСТЬNULL(a, ЕСТЬNULL(b, ЕСТЬNULL(c, ...)))`. Найти ограничение глубины/
  аргументов в парсере выражений, исправить. Фикстура с 4-уровневым `ЕСТЬNULL`,
  подтверждённая MCP. Цикл 3–7.

### Task 4: Квалификация псевдонимом — `alias-prefix-lost` (23) + `alias-prefix-diff` (3)

- [ ] Правило-гипотеза: конструктор квалифицирует неквалифицированные поля
  (`УПОРЯДОЧИТЬ ПО Поле`, `ГДЕ Код = &Код`) псевдонимом единственного источника.
  MCP-пробы: один источник / два источника / виртуальная таблица.
- [ ] `ТАБ.Таб.Ссылка` vs `ТАБ.Ссылка` (`DataProcessors-УдалениеПомеченныхОбъектов-*`):
  сравнение псевдонима должно быть регистронезависимым (`ТАБ` ≡ `Таб`).
- [ ] Реализация в общей точке (вероятно `exprFormatter`/генератор: пройти поля,
  квалифицировать), фикстуры на оба правила. Цикл 3–7.

### Task 5: `v-paren` (21)

- [ ] Случаи: `1 В (подзапрос)` — наш рендер добавляет/сохраняет скобки не как оракул;
  `НЕ ИСТИНА В (...)`. MCP-пробами установить точное правило скобок после `В`
  (список vs подзапрос vs одиночное значение; уже есть правило `В(` без пробела —
  фикстура 0004). Фикстуры, цикл 3–7.

### Task 6: `indent-only` (30)

- [ ] Вложенные `(ВЫБРАТЬ` в выражениях (`В (ВЫБРАТЬ...)`, операнд сравнения) и

  (видно: +1 таб к нашему в части контекстов). Свести к минимальному набору правил
  отступа в генераторе. Фикстуры на каждый контекст. Цикл 3–7.

### Task 7: `paren-only` (4) и пересмотр `po-extra-parens` (16) / `po-missing-parens` (5)

- [ ] `paren-only`: скобки вокруг сравнения с `ВЫРАЗИТЬ(...)` и внутри `И (...)` —

- [ ] `ПО`-скобки: пересмотреть остаток 6.13 (ВТ-затравки, табличные части) — выделить

- [ ] Ожидаемые подгруппы: развёртка `ВЫБРАТЬ *` по метаданным (неисправимо локально),

- [ ] Выход: исправления (если найдены) + точная таблица неустранимого остатка
