# План — Фаза 6.10. Форматер произвольных выражений

Дата: 2026-06-11. Спек: [`specs/2026-06-11-phase6.10-expression-formatter-design.md`](../specs/2026-06-11-phase6.10-expression-formatter-design.md).

## Реверс-инжиниринг (вычитан по оракулу, побайтно проверен)

### Ключевой принцип: рендерим структуру, листья — дословно

Конструктор разбирает выражение в дерево булевой структуры (`ИЛИ` < `И` < `НЕ`) и
оператора `ВЫБОР`, и **переотрисовывает только отступы/переносы/скобки структуры**.
Текст листьев (сравнения, вызовы функций, арифметика, `МЕЖДУ a И b`, `ЕСТЬ НЕ NULL`,
`ПОДОБНО … СПЕЦСИМВОЛ`) сохраняется **дословно** срезом из исходника. Это даёт защиту от
регрессий: листовой текст совпадает с тем, что мы и сейчас выводим.

### Булевы цепочки (И/ИЛИ/НЕ)

Вход для `ГДЕ`/`ИМЕЮЩИЕ`: `render(tree, ind=1, andCont=1, orLvl=0)`. Узлы:

```
render(node, ind, andCont, orLvl):     # ind = табы первой строки узла
  OR:  orDelta = (orLvl==0) ? 2 : 1
       iliInd  = ind + orDelta          # табы строк "ИЛИ x" этой группы
       childAnd = iliInd + 1
       operand0: render(.., ind,    childAnd, orLvl+1)   # на той же строке, префикс "("
       operandK: render(.., iliInd, childAnd, orLvl+1)   # новая строка, префикс "ИЛИ "
       ")" — в конце последней строки группы
  AND: child0: render(.., ind,     andCont,     orLvl)
       childK: render(.., andCont,  andCont+1,   orLvl)  # новая строка, префикс "И "
  NOT: "НЕ " инлайн, render(child, ind, andCont, orLvl)
  LEAF: одна строка дословным текстом на отступе ind
```

Префикс оператора (`ИЛИ `/`И `) печатает РОДИТЕЛЬ на первой строке потомка.

Таблица (ГДЕ, base=1): верхний конъюнкт `И` → 1; `ИЛИ` 1-го уровня → 3; `И` внутри
этой OR-группы → 4; `ИЛИ` 2-го уровня → 4; его `И` → 5. (см. фикстуры).

### Скобки

Каждая многооперандная OR-группа оборачивается в `(…)`: `(` приклеен к первому токену
operand0, `)` — хвост последней строки группы. Верхняя `И`-цепочка в `ГДЕ` **не**
оборачивается целиком. Листовые скобки (вызовы, `В(…)`) — не трогаем.

### `ВЫБОР` (CASE)

Раскладка полностью определяется отступом `E` строки `КОНЕЦ`:
`КОГДА=E+1`, `ТОГДА=E+2`, `ИНАЧЕ=E+1`, `КОНЕЦ=E`. Каждое из них — на своей строке.
`ВЫБОР` печатается инлайн в текущей позиции курсора; за `КОНЕЦ` хвост (`КАК <псевдоним>`,
`,`, `)`, `<оп> …`) идёт на той же строке.

`E` от вида слота:
- **value-слот** (поле выборки, аргумент агрегата, значение после `ТОГДА`/`ИНАЧЕ`): `E = C`.
- **boolean-слот** (`ГДЕ`/`ИМЕЮЩИЕ`/`ПО`, условие после `КОГДА`, после `И`/`ИЛИ`/`НЕ`):
  `E = C + 1`.
где `C` — контентный отступ секции (поля/ГДЕ/ИМЕЮЩИЕ → 1; ПО → 2). Вложенный `ВЫБОР`
после `ТОГДА`@t / `ИНАЧЕ`@t → `E = t+1`; после `КОГДА`@k → `E = k+1` (рекурсия).
Условие после `КОГДА` с `И`/`ИЛИ` переносит продолжения на `КОГДА_indent + 2`.

### Соединения `ПО` (отдельный режим, base=2)

Конструктор трактует условие соединения как И-цепочку, **каждый конъюнкт оборачивает в
`(…)`**: первый конъюнкт `(…)` на строке `ПО ` (контент с отступа 2), каждый следующий
`И (…)` на отступе 3. OR внутри конъюнкта `ПО` использует orDelta +1 (а чистый
верхний OR — +2 от base=2 → `ИЛИ` на 4). Текущее `renderJoinCondition` уже делает
одиночное `(a = b)`; форматер дорабатывает составные/многострочные.

### Токен-уровень (для срезов структуры, листья — дословно)

Внутри структуры между токенами: `func(` — без пробела; `, ` после запятой; `.` без
пробелов; операторы сравнения/арифметики — по пробелу с каждой стороны; `КАК` в пробелах;
`НЕ ` префикс. Это уже соблюдается дословными листьями; форматер их не переписывает.

## Архитектура

Новый модуль `src/core/query/exprFormatter.ts`:

```ts
export type ExprSlot = 'where' | 'having' | 'join' | 'select';
// Печатает выражение в каноническом виде конструктора. Первая строка БЕЗ ведущего
// отступа (его добавляет вызывающий); продолжения — с абсолютными табами.
export function formatExpression(raw: string, slot: ExprSlot): string;
// Содержит ли выражение структуру, требующую форматирования (ИЛИ/ВЫБОР/верхнеур. скобки).
export function needsFormatting(raw: string): boolean;
```

- **Лексер**: переиспользуем `sdblLexer.tokenize`, но **не меняем общий лексер**.
  `ИЛИ`/`НЕ`/`ВЫБОР`/`КОГДА`/`ТОГДА`/`ИНАЧЕ`/`КОНЕЦ`/`ЕСТЬ` не входят в `KEYWORDS` и
  токенизируются как `ident`; форматер распознаёт их по `.value.toUpperCase()` в
  собственном наборе. Так модуль самодостаточен — правки только в `sdblGenerator.ts`,
  парсер/лексер не трогаем (нулевой риск регрессий разбора). Текст листьев берём срезом
  исходной строки по позициям токенов (`pos`).
- **Парсер выражения**: рекурсивный спуск по приоритетам `ИЛИ < И < НЕ < <первичное>`.
  Первичное: `ВЫБОР … КОНЕЦ` (структурный узел), либо **лист** — диапазон токенов до
  следующего верхнеуровневого `И`/`ИЛИ`/конца, сохраняемый дословным срезом исходника
  (включая внутренние скобки, вызовы, `МЕЖДУ … И …` не дробим — `И` внутри `МЕЖДУ`/
  `ЕСТЬ НЕ NULL`/`ПОДОБНО` не булев). Скобочная группа верхнего уровня раскрывается в
  под-дерево (для нормализации скобок OR).
- **Принтер**: воспроизводит отступы/скобки/`ВЫБОР` по правилам выше.

Не дробить `И`/`НЕ` внутри листьев: лексер уже различает ключевые слова, но `МЕЖДУ`,
`ЕСТЬ`, `ПОДОБНО`, `СПЕЦСИМВОЛ` — внутрилистовые; при спуске лист поглощает всё до
верхнеуровневого булева `И`/`ИЛИ` или конца/закрывающей скобки, поэтому `И` из `МЕЖДУ a И b`
не воспринимается как разделитель (оно идёт за оператором сравнения, без начала нового
сравнения — лист продолжается).

## Точки интеграции (`sdblGenerator.ts`)

1. `buildConditionStrings` (ГДЕ/ИМЕЮЩИЕ): для `custom`-условия, если `needsFormatting`,
   подставить `formatExpression(expr, 'where'|'having')` вместо сырого `expr`.
2. `renderJoinCondition` (ПО): составное условие через форматер (`'join'`).
3. `buildFieldLines`/`trailingFields` (поле выборки с `expression`): если содержит `ВЫБОР`
   или структуру — `formatExpression(expr, 'select')`.

## Порядок реализации (инкрементально, оракул после каждого шага)

1. **Скелет + лексер-обёртка + парсер выражения** (дерево OR/AND/NOT/CASE/LEAF) с юнит-
   тестами разбора (без печати). `npm run test:unit` зелёный.
2. **Булевы цепочки в `ГДЕ`/`ИМЕЮЩИЕ`** (без CASE). Фикстуры (a)–(g) из ресёрча. Оракул:
   принято растёт, регрессий 0. Если регрессии — сузить `needsFormatting`.
3. **`ВЫБОР` в полях выборки** (value-слот). Фикстуры A,B. Оракул.
4. **`ВЫБОР` в `ГДЕ`/`ИМЕЮЩИЕ`** (boolean-слот) + вложенность. Фикстуры C,D,E,G. Оракул.
5. **Соединения `ПО`** (составные/многострочные + OR/CASE внутри). Фикстуры H,I,F. Оракул.
6. Курируемые фикстуры `test/fixtures/oracle/*.json` на каждый класс; финальный прогон.

После каждого шага: **множество принятых только растёт**. Любой шаг с регрессией —
откатываем/сужаем условие включения форматера.
