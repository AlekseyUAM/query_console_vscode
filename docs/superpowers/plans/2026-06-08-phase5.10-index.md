# Фаза 5.10 — Вкладка «Индекс» (план)

Спек: [`specs/2026-06-08-phase5.10-index-design.md`](../specs/2026-06-08-phase5.10-index-design.md).

Вертикальный срез по образцу 5.6 «Порядок» / 5.7 «Итоги»: core (модель + генератор) →
store → UI. TDD на каждом шаге.

## Задача 1 — Ядро: модель `Indexing` + генератор `renderIndex`

Файлы: `src/core/query/queryModel.ts`, `src/core/query/sdblGenerator.ts`,
`test/unit/sdblGenerator.test.ts`.

1. В `queryModel.ts` добавить типы `QueryIndex` и `Indexing` (см. спек) и поле
   `indexing?: Indexing` в `QueryModel` (рядом с `totals`/`builder`). `FieldRef`
   переиспользуется.
2. (TDD — тесты первыми) В `sdblGenerator.ts` добавить экспортируемую
   `renderIndex(indexing, model): string[]`:
   - `[]` если `!indexing` или `model.queryType !== 'createTemp'`;
   - отфильтровать индексы с `fields.length > 0`; если пусто → `[]`;
   - 1 индекс → `['ИНДЕКСИРОВАТЬ ПО', ...поля '\t<alias>' с запятыми кроме последнего]`;
   - ≥2 → `'ИНДЕКСИРОВАТЬ ПО НАБОРАМ'`, `'('`, наборы, `')'`. Набор:
     одно поле — `\t(<alias>)<уник?>< ,если не последний>`; несколько — первое
     `\t(<alias>,`, средние `\t<alias>,`, последнее `\t<alias>)<уник?>< ,>`. `<уник?>` =
     ` УНИКАЛЬНО` при `unique`. Псевдоним = `selectAliasFor(model, tableId, path)`.
3. В `generate()` после блока `renderTotals` дописать секцию через `'\n\n' + join('\n')`.
4. Тесты (`describe('ИНДЕКСИРОВАТЬ')`): эталоны из скриншотов (полный текст запроса
   Справочник.Валюты, ПОМЕСТИТЬ `ааа`):
   - **НАБОРАМ** (две закладки, второй уникальный):
     ```
     ВЫБРАТЬ
     	Валюты.Ссылка КАК Ссылка,
     	Валюты.ВерсияДанных КАК ВерсияДанных,
     	Валюты.ПометкаУдаления КАК ПометкаУдаления,
     	Валюты.Наименование КАК Наименование,
     	Валюты.НаименованиеПолное КАК НаименованиеПолное
     ПОМЕСТИТЬ ааа
     ИЗ
     	Справочник.Валюты КАК Валюты

     ИНДЕКСИРОВАТЬ ПО НАБОРАМ
     (
     	(Ссылка),
     	(ПометкаУдаления,
     	Наименование) УНИКАЛЬНО
     )
     ```
   - **ПО** (один индекс Ссылка/Наименование) — хвост:
     ```

     ИНДЕКСИРОВАТЬ ПО
     	Ссылка,
     	Наименование
     ```
   - пустые индексы пропускаются; нет непустых → текст без секции;
   - `queryType: 'select'` с тем же `indexing` → секции нет.

   Модель для тестов собирать вручную (`tables`/`fields` с явными `alias`,
   `queryType: 'createTemp'`, `tempTableName: 'ааа'`, `indexing`). Поля выборки —
   `{ tableId: 't1', path, alias: path }` с теми же `Валюты`-таблицей.

Проверка: `npm run test:unit`.

## Задача 2 — Store: состояние, действия, редьюсер, пруны, снимок

Файлы: `src/webview/state/queryStore.ts`, `test/unit/queryStore.test.ts`.

1. Импортировать `Indexing`, `QueryIndex`, `FieldRef` из модели.
2. `QueryState` и `SavedQuery` → `indexing: Indexing`. `initialState()` →
   `indexing: { indexes: [] }`. `snapshotActive`, `restoreSaved` (и его default-объект
   при `null`), `buildModelFromFlat` → пробросить `indexing`. В `restoreSaved` default —
   `{ indexes: [] }`.
3. Пруны: в `REMOVE_FIELD` и `REMOVE_TABLE` отфильтровать удаляемое поле из
   `indexing.indexes[*].fields` (в `REMOVE_TABLE` — по `tableId`, в `REMOVE_FIELD` — по
   `tableId+path`). Пустые индексы сохранять.
4. Действия (`QueryAction`) + кейсы редьюсера (все иммутабельно):
   `ADD_INDEX`, `COPY_INDEX{index}`, `REMOVE_INDEX{index}`, `MOVE_INDEX{index,dir}`,
   `SET_INDEX_UNIQUE{index,unique}`, `ADD_INDEX_FIELD{index,tableId,path}`,
   `ADD_ALL_INDEX_FIELDS{index,fields:FieldRef[]}`,
   `REMOVE_INDEX_FIELD{index,tableId,path}`, `CLEAR_INDEX_FIELDS{index}`,
   `MOVE_INDEX_FIELD{index,tableId,path,dir}`. Семантика — см. спек (add-field без
   дублей в пределах индекса; addAll — добавить отсутствующие из переданного списка;
   move с проверкой границ).
5. Тесты в `queryStore.test.ts` (по образцу существующих order/totals тестов):
   каждое действие; пруны при `REMOVE_FIELD`/`REMOVE_TABLE`; snapshot→restore
   сохраняет `indexing`.

Проверка: `npm run test:unit`.

## Задача 3 — UI: `IndexTab.tsx` + проводка `App.tsx` + `TabsBar.tsx`

Файлы: новый `src/webview/components/IndexTab.tsx`,
`src/webview/components/TabsBar.tsx`, `src/webview/App.tsx`.

1. `TabsBar.tsx`: добавить `'Индекс'` в `TABS` после `'Дополнительно'`.
2. `IndexTab.tsx` (образец — `OrderTab.tsx`): props — `selectedTables`,
   `selectedFields`, `indexing`, и колбэки по каждому действию задачи 2. Локальный
   `useState<number>` для текущего индекса; при удалении/перемещении — поджать индекс в
   допустимые границы. Три панели:
   - **Индексы** (тулбар ⊕ ⧉ ✕ ↑ ↓): строки `Индекс ${i+1}` + чекбокс «Уникальный»;
     клик выбирает текущий. Тулбар-кнопки активны по состоянию выделения.
   - **Поля**: `selectedFields.filter(f => !f.expression && f.path)`, исключая поля
     текущего индекса (по `tableId+path`); draggable; выделение; кнопки `>` (выбранное),
     `>>` (все → `ADD_ALL_INDEX_FIELDS` с `fields` из доступных). Лейбл — псевдоним
     выборки (последний сегмент `path` или явный alias из `selectedFields`).
   - **Поля выделенного индекса** (тулбар ↑ ↓): поля текущего индекса; drop-зона
     (`ADD_INDEX_FIELD`); выделение; кнопки `<` (выбранное → `REMOVE_INDEX_FIELD`),
     `<<` (все → `CLEAR_INDEX_FIELDS`).
   Стили — переиспользовать из `OrderTab` (`SECTION_HEADER`, `panelBox`, `dropZone`,
   `dragStart`/`parseDrop`/`allowDrop`).
3. `App.tsx`:
   - `const showIndexTab = state.queryType === 'createTemp';`
   - Вставить `'Индекс'` в `visibleTabs` сразу после `'Дополнительно'`, когда
     `showIndexTab`, согласовав с ветками `dropTemp` и `Связи` (в `dropTemp` индекса
     нет; при `showJoinsTab` сохраняется и `'Связи'`). Реализовать как пост-обработку
     массива `visibleTabs`: если `showIndexTab` и массив содержит `'Дополнительно'` —
     вставить `'Индекс'` после него (если ещё нет).
   - `useEffect`: `if (!showIndexTab && activeTab === 'Индекс') setActiveTab('Дополнительно');`
   - Блок `{activeTab === 'Индекс' && (<IndexTab … />)}` с проводкой всех действий.
   - В финальном fallback-условии добавить `&& activeTab !== 'Индекс'`.

Проверка: `npm run test:unit && npm run build`.
