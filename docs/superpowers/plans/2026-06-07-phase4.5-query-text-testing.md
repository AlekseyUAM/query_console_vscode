# Фаза 4.5 — Тестирование текстов запросов: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Сквозной golden-сьют, доказывающий, что конвейер метаданные → генератор SDBL воспроизводит вывод штатного конструктора 1С (эталоны `tmp/meta1c/`), с `validate_query` как оракулом валидности; найденные разрывы исправляются в `src/core` до зелёных тестов.

**Architecture:** Новый тест-хелпер `buildSelectAllModel` строит «выбрать все поля» `QueryModel` в порядке 1С (стандартные → реквизиты → общие реквизиты → ТЧ → хвостовые стандартные `Предопределенный`/`ИмяПредопределенныхДанных`; для ВТ — измерения → период-поля → ресурсы). Golden-сьют грузит `tmp/parser_data/cf/configuration.yaml` через `loadMetadataFromYaml`, генерирует SDBL и сравнивает с эталоном без BOM. Общие реквизиты добавляются в конвейер: парсер cf → YAML → слияние в таблицы-члены состава.

**Tech Stack:** TypeScript, vitest, пакет `yaml`, MCP `1c-md` (`validate_query`).

**Спек:** [`specs/2026-06-07-phase4.5-query-text-testing-design.md`](../specs/2026-06-07-phase4.5-query-text-testing-design.md)

**Команды:** тест одного файла — `npx vitest run test/unit/<file>.test.ts`; парсер — `npm run parse` (регенерация `tmp/parser_data`); сборка — `npm run compile`.

## Установленные факты (выведены из анализа эталонов и YAML)

1. **Порядок полей реального объекта (1С) ≠ порядок в YAML.** YAML кладёт
   `Предопределенный`, `ИмяПредопределенныхДанных` сразу после `ПометкаУдаления`; 1С — в
   самый конец, после табличных частей. Правило восстановления порядка 1С:
   `[стандартные YAML-порядка КРОМЕ пары предопределённых] + [реквизиты] + [общие реквизиты] + [ТЧ] + [Предопределенный, ИмяПредопределенныхДанных если есть]`.
   В YAML стандартные поля идут группой раньше реквизитов — порядок внутри групп сохраняется.
2. **Общие реквизиты** добавляются после собственных реквизитов и перед ТЧ (эталон
   `СправочникЗначенияСвойствОбъектов`: `…Вес, ПолноеНаименование, НаименованиеЯзык1, НаименованиеЯзык2, Представления(…)`).
   Состав хранится в `src/cf/CommonAttributes/<Имя>.xml` → `<Content>/<xr:Item>` с
   `<xr:Metadata>Catalog.X</xr:Metadata>` и `<xr:Use>Use</xr:Use>`. Порядок общих реквизитов
   между собой — порядок их объявления в конфигурации (для `НаименованиеЯзык1/2` совпадает с
   алфавитным). В текущем YAML общие реквизиты не парсятся вовсе.
3. **ВТ Обороты/ОстаткиИОбороты:** порядок = `измерения → период-поля(периодичность) → развёрнутые ресурсы`
   (эталон `…ОстОборотыЗапись`: `Измерение1, Период, Регистратор, НомерСтроки, Ресурс1Оборот, Ресурс1Приход, Ресурс1Расход`).
4. **БАГ в `buildAccumRegSlices`:** суффиксы `ОстаткиИОбороты` заданы как
   `['НачальныйОстаток','КонечныйОстаток','Оборот','Приход','Расход']`, а 1С даёт порядок
   `НачальныйОстаток, Оборот, Приход, Расход, КонечныйОстаток` (эталон `…ОстОстаткиИОборотыПериод`).
5. **Срезы РС** уже строятся в `buildInfoRegSlices` (порядок: стандартные служебные → остальные поля базы).
6. **Непериодические регистры** не имеют файлов-эталонов срезов/ВТ — golden-кейсы для них не заводим.

- [ ] **Step 1: Написать хелпер `buildSelectAllModel`**

```ts
import type { MetaTable } from '../metadata/types';
import type { QueryModel, SelectedField, SelectedTabSectionField } from './queryModel';
import { accumPeriodFields } from './accumVirtualFields';

const TRAILING_STD = ['Предопределенный', 'ИмяПредопределенныхДанных'];

/** Поля реального объекта в порядке штатного конструктора 1С. */
function realObjectFields(t: MetaTable): SelectedField[] {
  const std = t.fields.filter(f => f.kind === 'standard' && !TRAILING_STD.includes(f.name));
  const trailing = t.fields.filter(f => f.kind === 'standard' && TRAILING_STD.includes(f.name));
  const rest = t.fields.filter(f => f.kind !== 'standard'); // реквизиты + общие реквизиты (порядок YAML)
  return [...std, ...rest, ...trailing].map(f => ({ tableId: 't1', path: f.name }));
}

/** Поля ВТ накопления/бухгалтерии: измерения → период-поля → ресурсы (порядок 1С). */
function accumVtFields(t: MetaTable, periodicity?: string): SelectedField[] {
  const dims = t.fields.filter(f => f.kind === 'dimension');
  const resources = t.fields.filter(f => f.kind === 'resource');
  const periods = (t.virtual?.slice === 'Обороты' || t.virtual?.slice === 'ОстаткиИОбороты')
    ? accumPeriodFields(periodicity) : [];
  return [...dims, ...periods, ...resources].map(f => ({ tableId: 't1', path: f.name }));
}

export function buildSelectAllModel(t: MetaTable, periodicity?: string): QueryModel {
  const isAccumVt = !!t.virtual &&
    ['Остатки', 'Обороты', 'ОстаткиИОбороты'].includes(t.virtual.slice);
  const fields = isAccumVt ? accumVtFields(t, periodicity) : realObjectFields(t);

  const tabSectionFields: SelectedTabSectionField[] = (t.tabularSections ?? []).map(ts => ({
    tableId: 't1', tsName: ts.name, tsFullName: ts.fullName,
    fields: ts.fields.map(f => f.name),
  }));

  return {
    tables: [{ id: 't1', fullName: t.fullName, ...(t.virtual ? { virtual: {} } : {}) }],
    fields,
    ...(tabSectionFields.length ? { tabSectionFields } : {}),
  };
}
```

- [ ] **Step 2: Парсер `commonAttribute.ts` (TDD)**

Структура XML (см. `src/cf/CommonAttributes/НаименованиеЯзык1.xml`): корень `CommonAttribute`,
имя в `Properties/Name`, состав в `Content/xr:Item` (`xr:Metadata` вида `Catalog.X`,
`xr:Use` = `Use`/`DontUse`). Маппинг англ→рус префиксов берётся из существующего
`typeParser`/`dom` (Catalog→Справочник, Document→Документ, ChartOfCharacteristicTypes→ПланВидовХарактеристик и т.д.).

```ts
import { firstByLocal, childrenByLocal, textOf } from './dom'; // использовать существующие хелперы dom.ts
import { mapEnPrefixToRu } from './typeParser';               // или локальная карта, если такой функции нет

export function parseCommonAttribute(rootEl: Element): ParsedCommonAttribute | null {
  const ca = firstByLocal(rootEl, 'CommonAttribute');
  if (!ca) return null;
  const name = textOf(firstByLocal(ca, 'Name'));
  if (!name) return null;
  const content: string[] = [];
  const contentEl = firstByLocal(ca, 'Content');
  for (const item of childrenByLocal(contentEl, 'Item')) {
    const use = textOf(firstByLocal(item, 'Use'));
    if (use && use !== 'Use') continue;
    const meta = textOf(firstByLocal(item, 'Metadata')); // 'Catalog.ЗначенияСвойствОбъектов'
    const dot = meta.indexOf('.');
    if (dot < 0) continue;
    const ru = mapEnPrefixToRu(meta.slice(0, dot));
    if (ru) content.push(`${ru}.${meta.slice(dot + 1)}`);
  }
  return { name, content };
}
```

- [ ] **Step 6: Слияние в `yamlLoader.ts`**

После сборки `tables` пройти по `index.commonAttributes`; для каждого объекта состава
найти соответствующую `MetaTable` по `fullName` и **дописать** поле общего реквизита
(`kind: 'attribute'`, `types: []`) ПОСЛЕ собственных реквизитов и ДО ТЧ. Поскольку
`buildSelectAllModel` ставит ТЧ из `tabularSections` (а не из `fields`) и кладёт реквизиты
в группу `kind !== 'standard'`, достаточно `push` в конец `fields` — порядок общих
реквизитов между собой = порядок их в `commonAttributes`. Поле общего реквизита не должно
дублироваться, если объект уже имеет такое имя.

```ts
const caByName = index.commonAttributes ?? [];
const tableByFull = new Map(tables.map(t => [t.fullName, t]));
for (const ca of caByName) {
  for (const fullName of ca.content) {
    const t = tableByFull.get(fullName);
    if (!t || t.fields.some(f => f.name === ca.name)) continue;
    t.fields.push({ name: ca.name, kind: 'attribute', types: [] });
  }
}
```
