# Фаза 6.12 — план зачистки остатка (TDD, субагентами, последовательно)

Спек: [`specs/2026-06-11-phase6.12-remainder-cleanup-design.md`](../specs/2026-06-11-phase6.12-remainder-cleanup-design.md)

## Метод

Последовательные субагенты, по одному классу. После каждого: `npm run accept:oracle`
(accepted строго растёт, ноль регрессий) + `npm run test:unit` (зелёный) ⇒ коммит
`feat(phase6.12.N): …` в master. Гейт всех шагов — приёмочный CLI; курируемые фикстуры
в `test/fixtures/oracle/` фиксируют конкретные правила.

Стартовый базлайн: **1444 принято** (parse-exception 94, mismatch 438).

## Задачи (каждая — отдельный субагент + коммит)

### C1. Регистр функций/литералов/типов в листьях (метаданно-независимо)
- Лист `exprFormatter`/генератора хранит срез дословно ⇒ `Представление(`,
  `ДатаВремя(`, `Неопределено`, `Строка(N)` в `ВЫРАЗИТЬ` остаются в исходном регистре.
- Добавить нормализатор листа: ре-токенизировать срез, привести к **верхнему регистру**
  только распознанные имена функций (из `FUNCTION_CATALOG`), литералы (`НЕОПРЕДЕЛЕНО`,
  `ИСТИНА`, `ЛОЖЬ`, `NULL`), периоды (`ДЕНЬ`, `МЕСЯЦ`, …) и имена типов в `ВЫРАЗИТЬ(… КАК
  <Тип>)`/`ТИП(<Тип>)`; регистр **идентификаторов сохранять**.
- Применить во всех точках вывода листа (выборка, ГДЕ/ИМЕЮЩИЕ, ПО, порядок, итоги).
- Цель: класс C-case (~31) → 0, ноль регрессий.

### C2. Скобки одиночных условий (`ПО`, `НЕ`, OR-группа)
- Правило R5 `ПО`: одиночное условие соединения то `ПО (a = b)`, то `ПО a = b` —
  вывести по оракулу точное условие оборачивания и применить.
- `НЕ`-конъюнкт: `И НЕ x` ¦ `И (НЕ x)` контекстно.
- Ведущая скобка OR-группы (`(X = ЛОЖЬ` ¦ `X = ЛОЖЬ`).
- Цель: классы C-paren (~70) → 0.

### C3. Оператор `В`: пробел списка и перенос подзапроса
- Список значений: `В(&a, &b)` → `В (&a, &b)` (пробел после `В` у списка, в отличие от
  одиночного `В(&Список)`).
- Подзапрос: `В(ВЫБРАТЬ …` → `В\n\t\t(ВЫБРАТЬ …` (перенос как у оракула).
- Цель: класс C-in (~45) → 0.

### C4. Хвостовые/пробельные/секционные мелочи
- Хвостовой `;`/разделитель пакета (~7), хвостовой пробел листа (`ЕСТЬ НЕ NULL `),
  нормализация пробелов оператора в модельных условиях (`a =b`→`a = b`), `РАЗРЕШЕННЫЕ`,
  МЕЖДУ, ИТОГИ, ВЫРАЗИТЬ-хвост.
- Цель: класс C-misc (~50) → 0.

### C5. Краевые случаи `ВЫБОР`/`ИЛИ` форматера 6.10
- Добить структуру `ВЫБОР`-остатка и `ИЛИ`-остатка.
- Цель: класс C-bool/case (~30) → 0.

### A1. parse-exception: нетиповые источники «ожидалось ИЗ»
- Разобрать конструкции, где конструктор дошёл до источника, а наш парсер нет.
- Цель: класс A-from (~40) → 0.

### A2. parse-exception: группировка по выражению `(`
- `СГРУППИРОВАТЬ ПО (выражение)`/функция как поле группировки.
- Цель: класс A-group (~20) → 0.

### A3. parse-exception: цепочки соединений / `КАК`
- «ожидалось ПО (получено ВНУТРЕННЕЕ/ЛЕВОЕ)», «ожидалось КАК».
- Цель: классы A-join + A-as (~25) → 0.

### B1. Резолвер метаданных (квалификация полей, авто-псевдонимы)
- Необязательный резолвер схемы (грузит YAML/`src/cf`-схему, ту же, что вебвью отдаёт
  через `SET_METADATA`), инъекция в `parseBatch`; headless-оракул грузит ту же схему.
- Квалификация бара́ поля `Поле`→`Таблица.Поле`, авто-псевдоним по имени поля,
  `УПОРЯДОЧИТЬ ПО Поле`→`Таблица.Поле`. Парсер по умолчанию остаётся чистым.
- Цель: класс B-meta (~172) → 0.

### D1. Границы пакетов/объединений
- Файлы, где расходится весь запрос (иной источник/границы пакета). Перепроверить
  `parseBatch`/`parseDocument`.
- Цель: класс D-struct (~40) → 0.
