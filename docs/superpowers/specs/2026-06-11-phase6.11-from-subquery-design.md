# Спек — Фаза 6.11. Подзапрос в источнике «ИЗ» (вложенный запрос как узел модели)

Дата: 2026-06-11. Принцип итерации: спек → план → реализация по TDD. Ядро — pure-TS.
Опирается на 6.10 (форматирование вложенного текста), 6.2/6.3 (обратный парсер,
round-trip-оракул), 6.7 (oracle-приёмка `npm run accept:oracle`).

## 1. Цель

1С разрешает писать в `ИЗ` не таблицу, а **вложенный запрос**:
`ИЗ (ВЫБРАТЬ … ) КАК Данные`, в том числе с `ОБЪЕДИНИТЬ` внутри. Сейчас модель
источника (`SelectedTable`) — только таблица, поэтому такие запросы **не парсятся**:
парсер явно отклоняет их в `parseTableSource` (строка с `throw … «подзапрос в
источнике ИЗ (…) не поддерживается визуальной моделью»`). В корпусе таких запросов
**65, все отклонены** (класс A из 6.12, крупнейший parse-exception).

Что нужно: ввести **источник-подзапрос как полноценный узел модели** (запрос внутри
запроса), научить парсер и генератор работать рекурсивно. Самая объёмная и
структурная итерация фазы 6.

## 2. Область

**В области (6.11):**
- Подзапрос в любом источнике секции `ИЗ`: одиночный источник, элемент списка через
  запятую, участник цепочки соединений (затравка или присоединяемая).
- Внутри подзапроса — полный спектр уже поддерживаемых конструкций, включая
  `ОБЪЕДИНИТЬ [ВСЕ]` (рекурсивно через `parseDocument`/`generateDocument`).
- Алиас подзапроса (`) КАК <Имя>`) — обязателен (так выводит конструктор 1С).
- Поля/условия/порядок внешнего запроса, адресующие подзапрос по его алиасу
  (`Данные.Роль`), резолвятся существующим механизмом `alias → tableId`.

**Вне области (передаётся в 6.12-C, «доводка форматера»):**
- Подзапрос после оператора `В (ВЫБРАТЬ …)` в условиях `ГДЕ`/`ИМЕЮЩИЕ`. Хотя ROADMAP
  упоминает его рядом, его форматирование **контекстно-зависимо** (отступ `(ВЫБРАТЬ`
  зависит от позиции `В` в произвольном выражении — внутри `ВЫБОР`, цепочки `И`,
  отрицания `НЕ`), завязано на форматер произвольных выражений 6.10 и не сводится к
  чистому правилу. Эти случаи остаются `custom`-выражениями и закрываются в 6.12-C
  вместе с остальным форматерным остатком. См. §7.

## 3. Модель

`SelectedTable` получает необязательное поле:

```ts
export interface SelectedTable {
  id: string;
  fullName: string;           // для подзапроса — '' (не используется)
  alias?: string;
  virtual?: VirtualParams;
  /** Источник-подзапрос: `ИЗ (<подзапрос>) КАК <alias>`. Если задан — fullName/virtual
   *  игнорируются, источник рендерится как вложенный запрос. alias обязателен. */
  subquery?: QueryDocument;   // QueryDocument → поддержка ОБЪЕДИНИТЬ внутри
}
```

`QueryDocument` импортируется **типом** из `unionModel` (`import type`), цикла рантайма
нет (`queryModel` не использует значения из `unionModel`).

Инвариант: если `subquery` задан, то `alias` задан, а `fullName === ''`. Поля
выборки/условия резолвятся по алиасу подзапроса как по обычной таблице — `tableId`
синтетический (`t0,t1,…`), внутренние псевдонимы подзапроса в карту внешних алиасов
**не попадают** (изолированы внутри `parseDocument`).

## 4. Генератор (`renderSource`)

Единственная точка вызова `renderSource` — `sourceLine` в `renderFrom`
(`${renderSource(t)} КАК ${alias}`). При наличии `t.subquery` `renderSource` отдаёт
**многострочный блок** `(…)`, который `renderFrom`/`sourceLine` дополняют ` КАК <alias>`
и ведущим `\t` первой строки.

Правило отступа (вычитано побайтно по оракулу, см. фикстуру в §6):
- `inner = generateDocument(t.subquery)` — канонический текст подзапроса с базой 0.
- Каждая строка `inner` (включая пустые) реиндентируется на **+1 таб**.
- Первая строка получает `(` вместо ведущего таба (его добавит `renderFrom`).
- К самой последней строке дописывается `)`.

```ts
const inner = generateDocument(t.subquery).split('\n');
return inner.map((l, k) => (k === 0 ? '(' + l : '\t' + l)).join('\n') + ')';
```

(`'\t' + ''` для пустой строки-разделителя `ОБЪЕДИНИТЬ` даёт строку из одного таба —
ровно как выводит конструктор.)

Эталон (`tmp/query1c` → `Catalogs-ГруппыДоступа-Ext-ManagerModule.bsl_11.txt`):

```
ВЫБРАТЬ
	Данные.Роль КАК Роль
ИЗ
	(ВЫБРАТЬ РАЗЛИЧНЫЕ
		РолиПрофилей.Роль КАК Роль,
		-1 КАК ВидИзмененияСтроки
	ИЗ
		Справочник.ПрофилиГруппДоступа.Роли КАК РолиПрофилей
	ГДЕ
		РолиПрофилей.Ссылка = &СтарыйПрофиль
	
	ОБЪЕДИНИТЬ ВСЕ
	
	ВЫБРАТЬ РАЗЛИЧНЫЕ
		РолиПрофилей.Роль,
		1
	ИЗ
		Справочник.ПрофилиГруппДоступа.Роли КАК РолиПрофилей
	ГДЕ
		РолиПрофилей.Ссылка = &НовыйПрофиль) КАК Данные

СГРУППИРОВАТЬ ПО
	Данные.Роль

ИМЕЮЩИЕ
	СУММА(Данные.ВидИзмененияСтроки) <> 0
```

В цепочке соединений `renderFrom` ставит присоединяемый источник на `\t\t` — для
подзапроса-участника это даёт реиндент на один таб меньше нужного на хвостовых
строках. Такие случаи (подзапрос как участник ВНЕШНЕГО соединения) в корпусе крайне
редки; если оракул на них не сойдётся — они остаются rejected (как сейчас), без
регрессии. Доводка отступа join-участника — при необходимости отдельным шагом.

## 5. Парсер (`parseTableSource`)

Заменить `throw` на разбор подзапроса:

1. `cur.isPunct('(')` → поглотить `(` (запомнить токен), пройти токены со счётчиком
   глубины скобок до парного `)` (запомнить токен). `eof` до закрытия → ошибка
   «незакрытый подзапрос в источнике ИЗ».
2. `innerText = cur.source.slice(open.pos + 1, close.pos)` — сырой срез между скобками.
3. `subquery = parseDocument(innerText)` — рекурсивный разбор (поддерживает
   `ОБЪЕДИНИТЬ`). Внутренние позиции токенов — относительно среза (свежая
   токенизация), внешний курсор не затрагивается.
4. Ожидать `КАК <alias>` (обязателен для подзапроса). Отсутствие → ошибка.
5. Вернуть `{ id: 't'+index, fullName: '', alias, subquery }`.

Карта `alias → tableId` строится в `parseSingleQuery` как раньше; подзапрос-источник
участвует наравне с таблицами. Соединения (`parseFrom`) работают без изменений —
`readSource` уже вызывает `parseTableSource` и для затравки, и для присоединяемых.
