# Phase 4.3 — Виртуальные таблицы регистров накопления: дизайн

**Дата:** 2026-06-03
**Фаза:** 4.3 (см. [ROADMAP](../../ROADMAP.md))
**Статус:** утверждён

Прямое обратносовместимое расширение машинерии [фазы 4.2](2026-06-03-phase4-infreg-virtual-tables-design.md)
(виртуальные таблицы регистров сведений). Те же швы: парсер → `properties` →
`yamlLoader` эмитит виртуальные таблицы → `VirtualParams` → диспетчеризация генератора →
окно «Параметры виртуальной таблицы». Окно «Произвольное выражение» и каталог функций
переиспользуются из 4.2 без изменений.

---

## 1. Цель

Дать конструктору работу с **виртуальными таблицами регистров накопления**:

- `Обороты` — у регистров любого вида (Остатки и Обороты);
- `Остатки`, `ОстаткиИОбороты` — только у регистров вида Остатки;
- параметры виртуальных таблиц в окне «Параметры виртуальной таблицы», включая
  выпадающие списки `Периодичность` и `МетодДополнения`;
- зависимость состава полей виртуальной таблицы от выбранной `Периодичности`;
- генерацию текста запроса с вызовом виртуальной таблицы.

Ядро (`QueryModel`, модель метаданных, генератор) расширяется обратносовместимо;
существующее поведение (в т.ч. срезы регистров сведений из 4.2) не ломается.

## 2. Не входит в 4.3

- Регистр бухгалтерии (движения с субконто, виртуальные таблицы Обороты/Остатки/
  ОстаткиИОбороты/ДвиженияССубконто).
- Виртуальные таблицы регистра расчёта.
- Валидация текста выражения и обратный разбор текста запроса (фаза 6).

## 3. Ключевые решения

| Решение | Выбор | Обоснование |
|---|---|---|
| Вид регистра | `properties.registerType: 'Balance' \| 'Turnovers'` | Определяет состав виртуальных таблиц; механизм `properties` уже round-trip-ится через YAML (как `periodicity` в 4.2) |
| Где рождаются ВТ | `yamlLoader.ts` (`buildAccumRegSlices`) | Логика в ядре, webview тонкий — принцип проекта |
| Период-зависимые поля | Чистый core-хелпер `accumPeriodFields(periodicity)` | Набор полей зависит от рантайм-параметра; логика в ядре, webview лишь дозапрашивает |
| Состав `MetaTable.fields` ВТ | Периодичность-**независимая** часть (измерения + развёрнутые ресурсы) | Период-поля добавляются динамически по выбранной периодичности |
| Параметры ВТ в модели | Расширение `VirtualParams` | Те же экшены reducer (`SET_VIRTUAL_PARAMS`), что и срезы 4.2 |
| Диспетчеризация генератора | По 3-му сегменту `fullName` (вид ВТ) | Без новых полей модели; `fullName` уже несёт вид ВТ |
| Развёртка `Обороты` для вида Обороты | Только `<R>Оборот` (по-1С) | Регистр вида Обороты не имеет прихода/расхода |

## 4. Метаданные: вид регистра → состав виртуальных таблиц

### 4.1 Парсер `accumulationRegister.ts`

Сейчас вид регистра не читается. Прочитать `RegisterType` из `Properties` и сохранить:

```ts
const registerType = nodeText(childByLocalName(props, 'RegisterType')) || 'Balance';
return {
  version: 1,
  kind: 'РегистрНакопления',
  name,
  fullName,
  uuid,
  properties: { registerType }, // 'Balance' (Остатки) | 'Turnovers' (Обороты)
  fields,
};
```

`Balance` ≙ вид Остатки, `Turnovers` ≙ вид Обороты. При отсутствии узла — умолчание
`Balance` (вид по умолчанию для регистра накопления). `ParsedObject.properties` уже
существует (`Record<string, unknown>`) — новых типов парсера не нужно.

### 4.2 Тип `VirtualTableInfo` (`src/core/metadata/types.ts`)

Расширить объединение `slice`:

```ts
export interface VirtualTableInfo {
  slice: 'СрезПервых' | 'СрезПоследних' | 'Обороты' | 'Остатки' | 'ОстаткиИОбороты';
  baseFullName: string; // 'РегистрНакопления.РегистрНакопленияОст'
}
```

`MetaTable.virtual?` остаётся как в 4.2.

### 4.3 `yamlLoader.ts` — `buildAccumRegSlices`

По образцу `buildInfoRegSlices`. Для `kind === 'РегистрНакопления'`:

- вид Остатки (`registerType === 'Balance'`) → три ВТ: `Остатки`, `Обороты`,
  `ОстаткиИОбороты`;
- вид Обороты (`registerType === 'Turnovers'`) → одна ВТ: `Обороты`.

Каждая ВТ — `MetaTable`:

- `kind: 'РегистрНакопления'` (та же группа дерева);
- `name: '<Имя>.<ВидВТ>'`, `fullName: 'РегистрНакопления.<Имя>.<ВидВТ>'`;
- `virtual: { slice: <ВидВТ>, baseFullName: obj.fullName }`;
- `fields` — **периодичность-независимая** часть: измерения (копируются как есть) +
  развёрнутые ресурсы.

**Развёртка ресурса `<R>`** (по эталону конструктора 1С):

| ВТ | Поля ресурса `<R>` |
|---|---|
| `Остатки` | `<R>Остаток` |
| `Обороты`, регистр вида Остатки | `<R>Оборот`, `<R>Приход`, `<R>Расход` |
| `Обороты`, регистр вида Обороты | `<R>Оборот` |
| `ОстаткиИОбороты` | `<R>НачальныйОстаток`, `<R>КонечныйОстаток`, `<R>Оборот`, `<R>Приход`, `<R>Расход` |

Развёрнутые ресурсы наследуют тип исходного ресурса базы (обычно `Число`). Порядок полей ВТ:
сначала измерения, затем развёрнутые ресурсы (период-поля добавляются динамически на
слое webview, см. §6). Таблица `Остатки` период-полей не имеет.

## 5. Период-зависимые поля — `src/core/query/accumVirtualFields.ts`

**Ключевое решение.** Состав полей виртуальных таблиц `Обороты` и `ОстаткиИОбороты`
зависит от выбранного параметра `Периодичность`. Логика — в новом чистом core-модуле;
webview лишь дозапрашивает поля по текущей периодичности.

```ts
export function accumPeriodFields(periodicity: string | undefined): MetaField[];
```

| Периодичность | Добавляемые поля (в этом порядке) |
|---|---|
| (пусто) / `Период` | — |
| `Запись` | `Период`, `Регистратор`, `НомерСтроки` |
| `Регистратор` | `Период`, `Регистратор` |
| `Секунда`, `Минута`, `Час`, `День`, `Неделя`, `Месяц`, `Квартал`, `Год`, `Декада`, `Полугодие` | `Период` |
| `Авто` | `ПериодСекунда`, `ПериодМинута`, `ПериодЧас`, `ПериодДень`, `ПериодНеделя`, `ПериодДекада`, `ПериодМесяц`, `ПериодКвартал`, `ПериодПолугодие`, `ПериодГод`, `Регистратор`, `НомерСтроки` |

Типы: все `Период*` — `Дата`, `НомерСтроки` — `Число`, `Регистратор` — ссылочный
(`[{}]`). Неизвестное значение трактуется как «пусто» (поля не добавляются).

Применяется только к `Обороты`/`ОстаткиИОбороты`. Для `Остатки` хелпер не вызывается.

## 6. Дерево метаданных и панель «Поля» (webview)

- Дерево: ВТ-строки попадают в группу «Регистры накопления» отдельными строками рядом
  с базовым регистром (`РегистрНакопленияОст.Обороты`, `…Остатки`, `…ОстаткиИОбороты`).
  Тот же drag-payload `{ kind: 'table', tableFullName }`, спец-отрисовки не требуется —
  как срезы в 4.2.
- Панель «Поля»: для выбранной ВТ-накопления вида `Обороты`/`ОстаткиИОбороты` доступные
  поля = `accumPeriodFields(virtual.periodicity)` ++ `MetaTable.fields`. Для `Остатки`
  и срезов РС — как сейчас (`MetaTable.fields`). При смене `Периодичности` набор полей
  пересчитывается. Уже выбранные период-поля, исчезающие при смене периодичности, не
  удаляются автоматически (пользователь убирает их вручную) — край вне объёма итерации.

## 7. `QueryModel` (`src/core/query/queryModel.ts`)

Расширить `VirtualParams` обратносовместимо (срезы РС из 4.2 используют `period`/
`condition` и не затрагиваются):

```ts
export interface VirtualParams {
  period?: string;       // срез РС, Остатки РН
  startPeriod?: string;  // НачалоПериода (Обороты, ОстаткиИОбороты)
  endPeriod?: string;    // КонецПериода
  periodicity?: string;  // Период|Запись|Регистратор|Секунда|…|Авто
  fillMethod?: string;   // Движения|ДвиженияИГраницыПериода (ОстаткиИОбороты)
  condition?: string;
}
```

`SelectedTable.virtual?` и `SelectedField.expression?` — как в 4.2.

## 8. Генератор `sdblGenerator.ts`

### 8.1 Псевдонимы

Как в 4.2: 3-сегментный `fullName` (`РегистрНакопления.X.Обороты`) → базовый псевдоним
= склейка сегментов 2 и 3 без точки (`XОбороты`). Коллизии — суффикс-счётчик.

### 8.2 Источник-виртуальная таблица — диспетчеризация по виду ВТ

Вид ВТ определяется по 3-му сегменту `fullName`. Позиционные параметры:

| ВТ | Позиционные параметры |
|---|---|
| `СрезПервых` / `СрезПоследних` | `(Период, Условие)` (как 4.2) |
| `Остатки` | `(Период, Условие)` |
| `Обороты` | `(НачалоПериода, КонецПериода, Периодичность, Условие)` |
| `ОстаткиИОбороты` | `(НачалоПериода, КонецПериода, Периодичность, МетодДополнения, Условие)` |

`Периодичность` и `МетодДополнения` вставляются как голые слова SDBL (`Авто`,
`ДвиженияИГраницыПериода`), не как параметры. Правило пустых позиций — как в 4.2:
хвостовые пустые позиции отбрасываются, пустые позиции в середине остаются пустыми
между запятыми; все позиции пусты → вызов без скобок.

Эталоны текста запроса (из требований к итерации):

```sql
-- Обороты
ВЫБРАТЬ
    РегистрНакопленияОстОбороты.Измерение1 КАК Измерение1,
    РегистрНакопленияОстОбороты.Ресурс1Оборот КАК Ресурс1Оборот,
    РегистрНакопленияОстОбороты.Ресурс1Приход КАК Ресурс1Приход,
    РегистрНакопленияОстОбороты.Ресурс1Расход КАК Ресурс1Расход
ИЗ
    РегистрНакопления.РегистрНакопленияОст.Обороты(&Нач, &Кон, Авто, Измерение1 = &Пар) КАК РегистрНакопленияОстОбороты

-- Остатки
ВЫБРАТЬ
    РегистрНакопленияОстОстатки.Измерение1 КАК Измерение1,
    РегистрНакопленияОстОстатки.Ресурс1Остаток КАК Ресурс1Остаток
ИЗ
    РегистрНакопления.РегистрНакопленияОст.Остатки(&Период, Измерение1 = &Пар) КАК РегистрНакопленияОстОстатки

-- ОстаткиИОбороты
ВЫБРАТЬ
    РегистрНакопленияОстОстаткиИОбороты.НомерСтроки КАК НомерСтроки,
    РегистрНакопленияОстОстаткиИОбороты.Регистратор КАК Регистратор,
    РегистрНакопленияОстОстаткиИОбороты.ПериодГод КАК ПериодГод,
    РегистрНакопленияОстОстаткиИОбороты.Измерение1 КАК Измерение1,
    РегистрНакопленияОстОстаткиИОбороты.Ресурс1НачальныйОстаток КАК Ресурс1НачальныйОстаток,
    РегистрНакопленияОстОстаткиИОбороты.Ресурс1КонечныйОстаток КАК Ресурс1КонечныйОстаток,
    РегистрНакопленияОстОстаткиИОбороты.Ресурс1Оборот КАК Ресурс1Оборот,
    РегистрНакопленияОстОстаткиИОбороты.Ресурс1Приход КАК Ресурс1Приход,
    РегистрНакопленияОстОстаткиИОбороты.Ресурс1Расход КАК Ресурс1Расход
ИЗ
    РегистрНакопления.РегистрНакопленияОст.ОстаткиИОбороты(&НачалоПериода, &КонецП, Авто, ДвиженияИГраницыПериода, Измерение1 = &Пар) КАК РегистрНакопленияОстОстаткиИОбороты
```

### 8.3 Поля

Без изменений к 4.2: обычное поле — `<alias>.<path> [КАК <alias_поля>]`; произвольное
поле (`expression` задано) — `<expression> КАК <alias>` с автогеном псевдонима.

## 9. Окно «Параметры виртуальной таблицы» (webview)

`VirtualTableParamsDialog` становится параметричным по виду ВТ (`virtual.slice`):

| Вид ВТ | Поля окна |
|---|---|
| срез РС / `Остатки` | `Период` (текст) + `Условие` (текст + «…») |
| `Обороты` | `НачалоПериода`, `КонецПериода` (текст), `Периодичность` (`<select>`), `Условие` |
| `ОстаткиИОбороты` | + `МетодДополнения` (`<select>`) |

- `Периодичность` — выпадающий список: (пусто), `Период`, `Запись`, `Регистратор`,
  `Секунда`, `Минута`, `Час`, `День`, `Неделя`, `Месяц`, `Квартал`, `Год`, `Декада`,
  `Полугодие`, `Авто`.
- `МетодДополнения` — выпадающий список: (пусто), `Движения`, `ДвиженияИГраницыПериода`.
- `Условие` — текстовый ввод + кнопка «…», открывающая окно «Произвольное выражение»
  (источник полей — поля выбранной ВТ; имена неквалифицированные, как в 4.2 для условия).
- «ОК» → `SET_VIRTUAL_PARAMS { tableId, params }`; «Отмена» закрывает без изменений.

Списки значений `Периодичность`/`МетодДополнения` выносятся константами в core
(`accumVirtualFields.ts`), чтобы переиспользоваться диалогом и хелпером полей.

## 10. Состояние webview (`queryStore.ts`)

Новых экшенов не требуется: `SET_VIRTUAL_PARAMS { tableId; params: VirtualParams }` уже
пишет произвольный `VirtualParams`; `ADD_TABLE` уже проставляет `virtual: {}` у таблиц с
маркером `virtual`. Окно «Произвольное выражение» и `ADD_EXPRESSION_FIELD` — из 4.2.

## 11. Тесты (TDD)

### 11.1 core

- `accumulationRegister`: `RegisterType` → `properties.registerType`; отсутствие узла →
  `'Balance'`.
- `yamlLoader`: регистр вида Остатки → база + 3 ВТ (`Остатки`/`Обороты`/
  `ОстаткиИОбороты`) с корректными `fullName`/`virtual`/развёрткой ресурсов; регистр
  вида Обороты → база + 1 ВТ (`Обороты`) только с `<R>Оборот`; проверка состава
  измерений и развёрнутых ресурсов.
- `accumVirtualFields`: `accumPeriodFields` для каждой периодичности (пусто/`Период` →
  пусто; `Запись`; `Регистратор`; представитель из `Секунда…Полугодие`; `Авто`).
- `sdblGenerator`: четыре эталона из §8.2; правило пустых позиций (хвостовые/средние);
  псевдоним `XОбороты`/`XОстатки`/`XОстаткиИОбороты`.

### 11.2 webview

В стиле существующих тестов: `VirtualTableParamsDialog` рендерит корректный набор полей
по виду ВТ; селекты `Периодичность`/`МетодДополнения` содержат нужные значения и пишут
их в параметры по «ОК»; панель «Поля» показывает период-поля по выбранной периодичности
для `Обороты`/`ОстаткиИОбороты`.
