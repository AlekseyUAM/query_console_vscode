# Фаза 6.13 — стандартные vs произвольные условия связи (скобки `ПО` + галочка «Произвольное»)

## Контекст и открытие

Класс расхождений «скобки условий `ПО`» (`ПО (a=b)` ¦ `ПО a=b`) в 6.12 был ошибочно
помечен неустранимым: гипотеза «оборачивать по разрешимости операндов по схеме» опровергнута.
Пользователь дал **истинное правило** (с подтверждением скриншотами конструктора):

> При соединении двух таблиц **стандартные** условия связи **не** заключаются в скобки,
> **произвольные** — заключаются. Стандартное условие — то, что задаётся мышкой в редакторе
> связи: `[Поле Таблицы1] [оператор =,<,>,…] [Поле Таблицы2]`. Всё прочее (`Поле = &Параметр`,
> константа, функция, оба операнда одной таблицы, **перестановка операндов** —
> `joined.поле = seed.поле`) — произвольное (галочка «Произвольное»), печатается в скобках.

Перестановка операндов **не меняет смысл**, но переводит условие в «произвольное»: конструктор
НЕ нормализует порядок операндов, а классифицирует условие как-есть.

Это **полностью выводится из модели** (без метаданных): нужны только псевдонимы источников
соединения. Эмпирика по корпусу (1976 валидных, все конъюнкты `ПО`):

| Дискриминатор «стандартное» | Точность |
|---|---|
| rhs — поле `joined`, lhs — поле любой др. таблицы, оп сравнения, чистые поля | 90.0% |
| **rhs — поле `joined`, lhs — поле `seed` (затравки цепочки)** | **95.6%** |

Остаток ~4% — многошаговые цепочки и временные затравки (`ВТ_*`), где конструктор
реконструирует дерево соединений иначе; уточняется субагентом по оракулу (гейт — ноль
регрессий), несведённое — документируется.

## Правило (реализация)

Для каждого соединения известны `seedTableId` (затравка, левая по тексту) и `joinedTableId`
(присоединяемая). Условие `ПО` разбивается на **верхнеуровневые `И`-конъюнкты**. Каждый
конъюнкт классифицируется:

- **STANDARD (custom=false, без скобок):** конъюнкт — бинарное сравнение
  `<seedAlias>.<путь> <cmp> <joinedAlias>.<путь>`, где `cmp ∈ {=,<>,<,>,<=,>=}`, оба
  операнда — чистые точечные поля, левый принадлежит затравке, правый — присоединяемой.
- **ARBITRARY (custom=true, в скобках):** всё остальное — параметр/константа/функция в
  операнде, перестановка (`joined … seed`), оба операнда одной таблицы, `ИЛИ`/`НЕ`/`ВЫБОР`,
  многострочное выражение.

Составное условие рендерится поконъюнктно: `ПО <c1>\n\t\tИ <c2>`, каждый `ci` = `(expr)` при
custom иначе `expr`.

## Модель

`Join` несёт **список** условий-конъюнктов вместо одиночного условия:
`conditions: JoinCondition[]`, где `JoinCondition = { custom: boolean; leftTableId?; leftPath?;
operator?; rightTableId?; rightPath?; expression?; }`. Стандартный конъюнкт хранит
left/op/right; произвольный — `expression` (дословный текст) + `custom=true`. Обратная
совместимость: соединения из UI с одним условием эквивалентны `conditions=[одно]`. Поля
`leftPath/operator/rightPath/custom/expression` верхнего уровня `Join` сохраняются как
зеркало `conditions[0]` для существующего UI, либо мигрируются (на усмотрение реализации,
с зелёными тестами).

## Вебвью

Вкладка «Связи» (`ConnectionsTab`) уже имеет столбец «П.» (Произвольное, фаза 5.5).
При **открытии существующего запроса** (обратный разбор) галочки «Произвольное» должны
проставляться по `conditions[i].custom`. Контракт сообщений (`messages.ts`) и `queryStore`
прокидывают разобранную модель в UI как есть — нужно лишь убедиться, что per-conjunct
`custom` доходит до строки таблицы связей и рендерит галочку.

## Критерий приёмки

1. `npm run accept:oracle`: принято строго растёт от **1717**, ноль регрессий ранее принятых
   (класс скобок `ПО` — крупнейший остаток, ожидается заметный прирост).
2. `npm run test:unit` зелёный; курируемые фикстуры `test/fixtures/oracle/*.json` на
   стандарт/произвольное/перестановку/составное.
3. Вебвью: открытие запроса со смешанными условиями показывает корректные галочки
   «Произвольное» (e2e или ручная проверка).
4. Несведённый остаток дискриминатора (если есть) — задокументирован, приёмка только растёт.
