# Конструктор запросов 1С для VS Code — дизайн MVP

- **Дата:** 2026-06-01
- **Статус:** утверждён к реализации (вертикальный срез)
- **Источник требований:** `DESCRIPTION.md`

## 1. Контекст и цель

VSIX-расширение для VS Code — визуальный конструктор запросов 1С (аналог
«Конструктора запроса» из Конфигуратора/EDT), работающий с конфигурацией 1С,
выгруженной в файлы (`src/cf`: `*.xml` — метаданные/формы, `*.bsl` — код).

Полный продукт повторяет классический конструктор с вкладками: Таблицы и поля,
Связи, Группировка, Условия, Дополнительно, Объединения/Псевдонимы, Порядок,
Итоги, Индекс, Построитель, Пакет запросов; плюс двунаправленность —
генерация текста запроса и обратный разбор существующего текста в конструктор.

Это слишком много для одной итерации. Проект декомпозируется на 4 подсистемы:

1. **Слой метаданных** — парсинг `src/cf` в модель «таблицы → поля → типы → связи».
2. **Слой запроса (SDBL)** — генерация текста из модели (и в будущем — обратный разбор).
3. **UI конструктора** — webview с панелями и вкладками.
4. **Интеграция VS Code** — команда, открытие, вставка результата в код.

Данный документ описывает **первый вертикальный срез (MVP)**, проходящий сквозь
все 4 слоя. Каждая следующая итерация (вкладки, обратный разбор и т.д.) — свой
отдельный спек.

## 2. Ключевые архитектурные решения

| Решение | Выбор | Обоснование |
|---|---|---|
| Стратегия первой итерации | Вертикальный срез | Раньше всего проверяет архитектуру и интеграцию end-to-end |
| Отношение к `vscode-1c-platform-tools` | Отдельное расширение, свой парсер метаданных | Независимость; чистые границы |
| UI-стек webview | React + TypeScript | Богатая экосистема компонентов, хорошо тестируется Playwright |
| Направление работы с текстом | Только генерация (модель → текст) | Снимает из MVP сборку tree-sitter в рантайме; обратный разбор — позже |
| Загрузка метаданных | Пред-индекс в JSON-кэш | Быстрый старт UI; разовый парсинг тяжёлой выгрузки |
| Архитектура | «Тонкий webview» (логика в extension host) | Парсер и генератор — pure-TS модули, тестируются в Node (обязательный TDD) |
| tree-sitter-bsl в MVP | Только как тест-оракул валидности | Усиливает TDD; заранее обкатывает WASM-интеграцию для будущего обратного разбора |

## 3. Граница MVP

**В составе:**

- Команда `1С: Конструктор запроса` открывает webview-панель.
- Вкладка **«Таблицы и поля»** — 3 панели:
  - *База данных*: дерево из кэша. Для MVP — узлы **Справочники** и **Документы**,
    их объекты, поля-реквизиты + стандартные поля (Ссылка, Код, Наименование,
    ПометкаУдаления и т.п.). Раскрытие ссылочных полей на 1 уровень.
  - *Таблицы*: выбранные таблицы (кнопки `>` `<`).
  - *Поля*: выбранные поля (кнопки `>` `<`).
- Кнопка **«Запрос»/OK** → генерируется `ВЫБРАТЬ … ИЗ …` и **вставляется в активный
  редактор** (или копируется в буфер, если редактора нет).
- Несколько таблиц в списке (без визуальных связей — `ИЗ Т1, Т2`).

**НЕ в составе (следующие итерации, каждая — свой спек):** вкладки Связи,
Группировка, Условия, Дополнительно, Объединения/Псевдонимы, Порядок, Итоги,
Пакет запросов; обратный разбор текста (tree-sitter); drag&drop (в MVP — кнопки);
регистры, планы видов характеристик и прочие виды таблиц.

## 4. Компоненты и структура репозитория

Четыре изолированных модуля; три из них — pure-TS (тестируются в Node без VS Code).

```
query_console_vscode/
  package.json                 # манифест расширения (contributes.commands)
  src/
    extension/                 # СЛОЙ VS Code (тонкий)
      extension.ts             # activate(): регистрация команды
      panel.ts                 # WebviewPanel, мост postMessage
      insertResult.ts          # вставка текста в активный редактор
    core/                      # PURE-TS, без vscode
      metadata/
        types.ts               # модель метаданных (см. §5.1)
        cfParser.ts            # src/cf XML → MetadataModel
        cacheBuilder.ts        # MetadataModel → metadata-cache.json
        cacheLoader.ts         # чтение кэша
      query/
        queryModel.ts          # модель конструктора (см. §5.2)
        sdblGenerator.ts       # QueryModel → текст SDBL
    webview/                   # React + TS (СЛОЙ UI)
      main.tsx
      App.tsx
      components/
        DbTreePanel.tsx        # «База данных»
        TablesPanel.tsx        # «Таблицы»
        FieldsPanel.tsx        # «Поля»
        TabsBar.tsx            # вкладки (в MVP активна одна)
      state/queryStore.ts      # состояние выбора (QueryModel в webview)
      bridge.ts                # типобезопасный обмен с host
    shared/
      messages.ts              # контракт сообщений host↔webview
  test/                        # юнит-тесты ядра + Playwright e2e + фикстуры
```

**Контракт между слоями** сосредоточен в `shared/messages.ts`. Ни webview не знает
про файлы, ни `core` не знает про React/vscode. `cfParser`, `sdblGenerator`,
`queryModel` — изолированные модули под прямое юнит-тестирование.

## 5. Модель данных

Имена сущностей — русские, как в синтаксисе запросов 1С (идут прямо в текст).

### 5.1. Модель метаданных (`core/metadata/types.ts`)

```ts
type FieldKind = 'standard' | 'attribute';

interface MetaField {
  name: string;            // "Наименование", "Валюта"
  kind: FieldKind;
  types: MetaType[];
}

interface MetaType {
  primitive?: 'Строка' | 'Число' | 'Булево' | 'Дата';
  ref?: { kind: TableKind; name: string };
}

type TableKind = 'Справочник' | 'Документ'; // MVP

interface MetaTable {
  kind: TableKind;
  name: string;            // "Валюты"
  fullName: string;        // "Справочник.Валюты" — для ИЗ
  fields: MetaField[];     // стандартные + реквизиты
}

interface MetadataModel {
  version: 1;
  tables: MetaTable[];
}
```

- **Стандартные поля** добавляются по виду объекта из фиксированных шаблонов
  (Справочник → Ссылка, Код, Наименование, ПометкаУдаления, Предопределённый, …;
  Документ → Ссылка, Номер, Дата, Проведён, ПометкаУдаления, …).
- **Реквизиты** — из `<Attribute><Properties><Name>/<Type>`. Маппинг типов:
  `xs:string→Строка`, `xs:decimal→Число`, `xs:boolean→Булево`,
  `xs:dateTime→Дата`, `cfg:CatalogRef.X→{ref:{Справочник,X}}`,
  `cfg:DocumentRef.X→{ref:{Документ,X}}`.
- **Раскрытие ссылочных полей** в дереве делается на лету по `ref` на 1 уровень;
  в кэше не материализуется (избегаем циклов и раздувания).

Формат XML выгрузки (подтверждён на `src/cf/Catalogs/Валюты.xml`): объект лежит
как `Имя.xml` рядом с папкой `Имя/`; реквизиты — в
`<Attribute><Properties><Name>…</Name><Type><v8:Type>…</v8:Type></Type>`.

### 5.2. Модель запроса (`core/query/queryModel.ts`)

```ts
interface SelectedTable {
  id: string;            // uid экземпляра в запросе
  fullName: string;      // "Справочник.Валюты"
  alias?: string;        // псевдоним (в MVP опционально)
}

interface SelectedField {
  tableId: string;       // ссылка на SelectedTable.id
  path: string;          // "Наименование" или "Валюта.Код"
  alias?: string;        // КАК … (в MVP опционально)
}

interface QueryModel {
  tables: SelectedTable[];
  fields: SelectedField[];
}
```

Модель плоская и сериализуемая: это и полезная нагрузка сообщения `generate`, и
вход генератора, и фикстура юнит-тестов. Следующие итерации добавляют сюда
`conditions`, `joins`, `groupBy`, `orderBy` — MVP-форма остаётся стабильным ядром.

**Почему две модели:** метамодель отвечает «что существует», модель запроса — «что
выбрал пользователь». Генератор зависит только от `QueryModel`.

## 6. Поток данных host ↔ webview

```
Команда → extension.ts → panel.ts
   1) cacheLoader: есть кэш? нет → cfParser(src/cf) → cacheBuilder → пишет кэш
   2) создаёт WebviewPanel, грузит React-бандл
   webview → host:  { type:'ready' }
   host → webview:  { type:'metadataTree', tables }
   (раскрытие ссылки) webview → host: { type:'expandRef', ref }
                      host → webview: { type:'refFields', ref, fields }
   (кнопка Запрос)    webview → host: { type:'generate', model }
                      host: sdblGenerator(model) → text
                      host → webview: { type:'generatedText', text }   // предпросмотр
                      host: insertResult(text) → вставка в редактор
```

### 6.1. Контракт сообщений (`shared/messages.ts`)

```ts
type HostMsg =
  | { type: 'metadataTree'; tables: MetaTable[] }
  | { type: 'refFields'; ref: RefId; fields: MetaField[] }
  | { type: 'generatedText'; text: string };

type WebviewMsg =
  | { type: 'ready' }
  | { type: 'expandRef'; ref: RefId }
  | { type: 'generate'; model: QueryModel };
```

### 6.2. Владение состоянием

| Состояние | Владелец |
|---|---|
| `MetadataModel` (все таблицы/поля) | host |
| Дерево «База данных» (read-only копия) | webview |
| `QueryModel` (выбор пользователя) | webview (`queryStore`) |
| Сгенерированный текст | host генерирует → webview показывает |

### 6.3. Решения потока

- **`ready`-рукопожатие:** host шлёт `metadataTree` только после готовности webview —
  нет гонки с монтированием React.
- **Раскрытие ссылок по запросу (`expandRef`)** — кэш компактный, циклы ссылок не
  разворачиваются заранее.
- **Генерация — в host** (единственный экземпляр `sdblGenerator`, тестируемый в Node).

## 7. Генератор SDBL (`core/query/sdblGenerator.ts`)

Чистая функция `generate(model: QueryModel): string`.

### 7.1. Правила (MVP)

| Аспект | Правило |
|---|---|
| Язык | Русский синтаксис (`ВЫБРАТЬ`, `ИЗ`, `КАК`) |
| Псевдоним таблицы | Нет явного — генерируем из имени (`Справочник.Валюты`→`Валюты`); конфликт → суффикс (`Валюты`, `Валюты1`) |
| Источник поля | `<алиасТаблицы>.<path>` (`Валюты.Наименование`, `Валюты.Валюта.Код`) |
| Список полей | По одному на строку, отступ таб, запятая в конце кроме последней |
| `ИЗ` | `<fullName> КАК <алиас>`; несколько таблиц — через запятую |
| Псевдоним поля | `КАК <alias>` только если задан |
| Пустой выбор | Нет таблиц или полей → возвращает `''` |

### 7.2. Пример

Вход:
```json
{
  "tables": [{ "id": "t1", "fullName": "Справочник.Валюты" }],
  "fields": [
    { "tableId": "t1", "path": "Код" },
    { "tableId": "t1", "path": "Наименование" },
    { "tableId": "t1", "path": "ЗагружаетсяИзИнтернета" }
  ]
}
```

Выход:
```
ВЫБРАТЬ
	Валюты.Код,
	Валюты.Наименование,
	Валюты.ЗагружаетсяИзИнтернета
ИЗ
	Справочник.Валюты КАК Валюты
```

Генерация детерминирована (побайтово), что делает строковые тесты надёжными.
Текст строится по секциям (`ВЫБРАТЬ`/`ИЗ`); будущие вкладки добавляют секции
`ГДЕ`/`СГРУППИРОВАТЬ ПО`/`УПОРЯДОЧИТЬ ПО`/`ИТОГИ` в фиксированном порядке SDBL.

## 8. Тестирование (TDD обязателен)

| Уровень | Что покрывает | Инструмент | vscode |
|---|---|---|---|
| Юнит — генератор | `sdblGenerator`: фикстура → эталонный текст + `assertValidSdbl` (sdbl-WASM, парсинг без ошибок) | Vitest/Jest | нет |
| Юнит — метаданные | `cfParser`: мини-`src/cf` фикстуры → `MetadataModel`; `cacheBuilder`/`cacheLoader` round-trip | Vitest/Jest | нет |
| E2E — webview | открытие панели, дерево, перенос таблицы/поля, «Запрос» → ожидаемый текст | Playwright | да |

- **Тест-оракул:** хелпер `assertValidSdbl(text)` грузит `tree-sitter-sdbl.wasm` через
  `web-tree-sitter`, парсит, утверждает `!tree.rootNode.hasError`.
- **Источник WASM:** скрипт собирает `tree-sitter-sdbl.wasm` из
  `tmp/tree-sitter-bsl` (`npm run build:wasm:sdbl`) и **вендорит копию в
  `test/fixtures/`** (коммитится). Тесты стабильны без `tmp/` и в CI. Готового WASM
  в репо `tree-sitter-bsl` нет — собирается из грамматики `grammars/sdbl`.
- **Фикстуры метаданных** — маленькие рукотворные XML (1–2 справочника, 1 документ,
  ссылочное поле), а не вся `src/cf`: быстрые, детерминированные тесты.

## 9. Обработка ошибок

| Ситуация | Поведение |
|---|---|
| `src/cf` не найдена | Пустое дерево + баннер «Не найдена выгрузка конфигурации»; команда не падает |
| Битый/неизвестный XML | Объект пропускается, лог в output-канал; остальное дерево грузится |
| Неизвестный тип поля | Поле с типом «—», участвует в выборе (имя важнее типа) |
| Пустой выбор при генерации | `''`; host показывает `showInformationMessage`, не вставляет |
| Нет активного редактора | Текст в буфер обмена + уведомление |

## 10. Кэш метаданных

- **Путь:** `context.globalStorageUri`; имя файла = хэш абсолютного пути к `src/cf`
  (разные конфигурации не конфликтуют).
- **Источник пути к выгрузке:** настройка `queryConsole.metadataPath`; по умолчанию —
  корень открытой папки, если виден `Configuration.xml`.
- **Инвалидация:** сравнение `mtime` самого свежего файла в `src/cf` с `mtime` кэша;
  выгрузка новее → перепарсинг. Несовпадение `version` схемы → кэш игнорируется.

## 11. Среда разработки (Dev Container)

Реализована отдельно (вне MVP-кода конструктора), файлы в `.devcontainer/`:

- Контейнер node:22 с Claude Code CLI и tree-sitter-cli; работа под `node`.
- Claude Code в режиме `bypassPermissions` (только внутри контейнера) — все действия
  без подтверждений, безопасно за счёт изоляции.
- Соседние репозитории `tree-sitter-bsl` и `vscode-1c-platform-tools` копируются в
  `tmp/` (`initializeCommand`, на хосте).
- MCP-серверы 1С доступны через `host.docker.internal` (правка `.mcp.json` +
  `--add-host=host.docker.internal:host-gateway`).

## 12. Что НЕ делаем в этой итерации

Вкладки Связи/Группировка/Условия/Дополнительно/Объединения/Порядок/Итоги/Пакет
запросов; обратный разбор текста запроса через tree-sitter; drag&drop; регистры и
прочие виды таблиц; псевдонимы/итоги в UI. Каждое — отдельный спек поверх
стабильного ядра `QueryModel` и контракта сообщений.
