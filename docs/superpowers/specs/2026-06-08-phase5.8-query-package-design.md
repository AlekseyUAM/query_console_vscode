# Фаза 5.8 — Вкладка «Пакет запросов» (дизайн)

ТЗ: `tmp/пакет запросов.md`. Скриншоты: `tmp/console_screenshots/Screenshot_20260608_111334.png`
(список пакетов), `_111506/_111556` (временная таблица), `_111712/_111802` (уничтожение).

## Цель

Пакетный запрос — последовательность независимых запросов, разделённых `;` и строкой-
комментарием из 80 `/`. Каждый запрос пакета сам по себе — полноценный документ
конструктора (со своими таблицами/полями/связями/группировкой/объединениями и т.д.).
Боковые вкладки переключают активный запрос пакета; вкладка «Пакет запросов» показывает
их список с панелью инструментов.

## Двухуровневая модель

Уже существует **слой объединения** (фаза 5.4): `queryList`/`activeQuery`/`savedQueries`
в `QueryState` — это участники `ОБЪЕДИНИТЬ` **одного** запроса пакета. Пакет — это
**внешний** слой над ним: список таких объединительных документов.

```
Пакет (;-разделение)
└── Запрос пакета i  ≡  Документ объединения (ОБЪЕДИНИТЬ)
    └── Участник j   ≡  QueryModel (ВЫБРАТЬ … ИЗ … )
```

Активный запрос пакета живёт в существующих плоских полях + `queryList`/`activeQuery`/
`savedQueries` (слой 5.4 не трогаем). Неактивные запросы пакета лежат снимками в новом
`batchSaved`. Так весь код 5.0–5.7 продолжает работать «внутри» активного запроса пакета.

## Состояние (`src/webview/state/queryStore.ts`)

```ts
/** Снимок одного запроса пакета = полное состояние его документа объединения. */
export interface BatchSnapshot {
  queryList: QueryMeta[];
  activeQuery: number;
  /** Working set каждого участника объединения (без null — активный заполнен из плоских полей). */
  savedQueries: SavedQuery[];
}

export interface QueryState {
  // …существующее (queryList/activeQuery/savedQueries = активный запрос пакета)…
  /** Индекс активного запроса пакета. */
  activeBatch: number;
  /** Снимки запросов пакета; слот активного = null (живёт в queryList/savedQueries/плоских полях). */
  batchSaved: (BatchSnapshot | null)[];
}
```

`initialState`: `activeBatch: 0`, `batchSaved: [null]` (один запрос пакета). Число
запросов пакета = `batchSaved.length`.

### Снимок/восстановление запроса пакета

- `snapshotActiveBatch(state): BatchSnapshot` — собрать текущий документ объединения:
  `savedQueries` со слотом `activeQuery`, заполненным `snapshotActive(state)`; плюс
  `queryList`, `activeQuery`.
- `restoreBatch(state, snap): Partial<QueryState>` — при `null` вернуть пустой документ
  (`queryList: [{name:'Запрос 1', distinct:false}]`, `activeQuery: 0`, `savedQueries:[null]`,
  плоские поля по умолчанию через `restoreSaved(state, null)`). Иначе восстановить
  `queryList`/`activeQuery` из снимка, `savedQueries` с занулённым активным слотом и
  плоские поля из `snap.savedQueries[snap.activeQuery]`.

### Имя запроса пакета (производное)

По первому участнику объединения (`savedQueries[0]` / плоские поля при `activeQuery===0`)
i-го запроса пакета:

- `queryType==='createTemp'|'appendTemp'` и непустой `tempTableName` → имя = `tempTableName`;
- `queryType==='dropTemp'` → имя = `- ${tempTableName}` (или `- ` при пустом);
- иначе → `Запрос пакета ${i+1}`.

Хелпер `batchMemberName(state, i): string`.

### Экшены

```ts
| { type: 'ADD_BATCH_QUERY' }              // снимок активного → новый пустой запрос пакета → активен
| { type: 'SET_ACTIVE_BATCH'; index }      // снимок активного → восстановить целевой
| { type: 'REMOVE_BATCH_QUERY'; index }    // нельзя удалить последний; пересчёт activeBatch
| { type: 'MOVE_BATCH_QUERY'; index; dir: 'up' | 'down' }  // перестановка соседних снимков
```

Семантика — зеркало `ADD_QUERY`/`SET_ACTIVE_QUERY`/`REMOVE_QUERY` слоя объединения, но на
`batchSaved`/`activeBatch` и со снимком целого документа объединения через
`snapshotActiveBatch`/`restoreBatch`. `MOVE_BATCH_QUERY`: предварительно снять активный в
`batchSaved[activeBatch]`, переставить элементы `batchSaved`, обновить `activeBatch` (чтобы
указывал на тот же запрос), затем восстановить активный.

## Ядро: документ и генератор

`src/core/query/batchModel.ts` (новый):

```ts
import type { QueryDocument } from './unionModel';
/** Пакет запросов: последовательность документов объединения. */
export interface BatchDocument { members: QueryDocument[]; }
```

`src/core/query/sdblGenerator.ts` — `generateBatch(batch: BatchDocument): string`:

- сгенерировать каждый член через `generateDocument`, отбросить пустые строки;
- соединить разделителем `SEP = '\n;\n\n' + '/'.repeat(80) + '\n'`;
- 0 членов → `''`; 1 член → ровно `generateDocument(members[0])` (без `;` и разделителя) —
  поэтому весь существующий вывод (golden 4.5, тесты 5.x) остаётся **байт-в-байт**.

Эталон (ТЗ, 2 запроса пакета):

```
ВЫБРАТЬ
	Валюты.Ссылка КАК Ссылка
ИЗ
	Справочник.Валюты КАК Валюты
;

////////////////////////////////////////////////////////////////////////////////
ВЫБРАТЬ
	Анкета.ВерсияДанных КАК ВерсияДанных
ИЗ
	Документ.Анкета КАК Анкета
```

Уничтожение ВТ (`queryType==='dropTemp'`) генерируется существующим путём `generate` как
`УНИЧТОЖИТЬ <ВТ>` — отдельным членом пакета (см. ТЗ, пример с тремя членами).

`assembleBatch(state): BatchDocument` (в `queryStore.ts`): для каждого i — `{ members:
assembleMembers(state) }` при `i===activeBatch`, иначе документ из `batchSaved[i]`
(`queryList[j].name/distinct` + `buildModelFromFlat(savedQueries[j])`).

## Webview

- `TabsBar`: добавить «Пакет запросов» последней вкладкой (после «Итоги»). «Построитель»
  (5.9) встаёт перед ней.
- **`BatchTab` (новый)** — рендерится при `activeTab === 'Пакет запросов'`. Панель
  инструментов: «⊕ Добавить» (`ADD_BATCH_QUERY`), «✕ Удалить» (`REMOVE_BATCH_QUERY`,
  блокирована при единственном), «↑»/«↓» (`MOVE_BATCH_QUERY`). Колонка `Запрос` — список
  `batchMemberName(state, i)`; двойной клик по строке → `SET_ACTIVE_BATCH`; выделение
  активной строки. Стиль — как `UnionsTab`.
- **Боковая полоса** (`App`): переключить привязку с участников объединения на запросы
  пакета. `showSideTabs = batchSaved.length > 1 && activeTab !== 'Пакет запросов'`; строки
  — `batchMemberName(state, i)`; клик → `SET_ACTIVE_BATCH`. (Полоса переключения участников
  объединения убирается — переключение участника остаётся во вкладке «Объединения/
  Псевдонимы» через выбор строки; осознанное изменение относительно 5.4.)
- **Видимые вкладки при `dropTemp`.** Если у активного запроса (плоское `queryType`)
  `=== 'dropTemp'`, оставить только `['Дополнительно', 'Пакет запросов']` (эталон —
  скриншот `_111802`). При прочих типах — обычный список (+ «Связи»/«Построитель» по
  условиям).
- **Генерация/вставка.** `App.handleShowQuery` и `FieldsPanel` (кнопка «ОК») переходят с
  `generateDocument({ members: assembleMembers(state) })` на
  `generateBatch(assembleBatch(state))`. `FieldsPanel` получает готовый текст пропом
  (`queryText: string`), форматирует `formatAsBslString` и вставляет.
