# Фаза 7.9 — Доработки UI (вторая итерация): рекурсивный конструктор подзапроса, синонимы источников, валидация на ОК

Дата: 2026-06-19. Продолжение [Подфазы 8](../../PHASE_7.md) (закрыта коммитом
`6fb16c0`). Пользователь переопределяет смысл пунктов 7.8.8 / 7.8.9 и добавляет
новые 7.8.10–7.8.16. Нумерация пунктов сохранена пользовательской.

## Контекст

Конструктор запроса — webview (`src/webview/App.tsx`, reducer
`src/webview/state/queryStore.ts`), генератор/парсер SDBL байт-фиделити заперты на
оракул (фазы 6.x). Источники выбираются перетаскиванием из дерева метаданных;
`SelectedTable` уже несёт опциональный `alias` (явный псевдоним) и `subquery`
(источник-подзапрос). `defaultTableAlias()` выводит отображаемый псевдоним.
Текущая дедупликация в `ADD_TABLE`/`ADD_FIELD` — по `fullName`/`(tableId,path)`:
повторы молча отбрасываются.

## Пункты и решения

### 7.8.12 — Список «Таблицы» показывает синонимы

**Сейчас:** строка выбранной таблицы рисует `t.fullName` («Справочник.Валюты»).
**Надо:** рисовать псевдоним (`defaultTableAlias(t)` → «Валюты», «Валюты1»).
**Решение:** в `TablesPanel` заменить `{t.fullName}` на `{defaultTableAlias(sel)}`;
дерево метаданных (левая панель) не трогаем. `title`=fullName для подсказки.

### 7.8.13 — Дубли таблиц из метаданных с синонимом

**Сейчас:** `ADD_TABLE` при совпадении `fullName` возвращает state (no-op).
**Надо:** разрешить повтор; каждому следующему дублю — синоним `[Синоним][N]`,
N с 1 (`Валюты`, `Валюты1`, `Валюты2`). 1С использует синоним без разделителя.
**Решение:** `ADD_TABLE` всегда добавляет новую `SelectedTable`. Если базовый
псевдоним (`defaultTableAlias` без явного alias) уже занят среди выбранных таблиц —
назначить `alias = base + k` (k с 1, пропуская занятые). Генератор печатает
`Справочник.Валюты КАК Валюты1`. Поля/связи/прочее адресуются по `tableId` —
не ломается.

### 7.8.11 — Дубли реквизита в «Поля» с синонимом

**Сейчас:** `ADD_FIELD`/`ADD_FIELD_WITH_TABLE` при совпадении `(tableId,path)`
возвращают state (no-op).
**Надо:** разрешить повтор перетаскивания одного поля; каждому следующему дублю —
псевдоним колонки `[Синоним][N]` (N с 1). Синоним колонки = автопсевдоним поля
(последний сегмент пути). Первый — без явного alias (`Код`), второй — `alias=Код1`.
**Решение:** в `ADD_FIELD_WITH_TABLE` (drag-источник реквизита) убрать ранний
возврат на дубль: считать число уже выбранных полей с тем же `(tableId, base)` и,
если >0, задать `alias = base + count`. `base` = последний сегмент `fieldPath`.
Генератор печатает `Валюты.Код КАК Код1`. (`ADD_FIELD` из кнопочного пути
сохраняет прежнюю дедупликацию — повтор через drag.)

### 7.8.16 — Двойной клик по синониму таблицы добавляет все её поля (с дублями)

**Надо:** двойной клик по строке выбранной таблицы добавляет ВСЕ её поля в «Поля»,
даже если они уже есть (дубли разрешены, синонимы по 7.8.11).
**Решение:** в `TablesPanel` обработчик `onDoubleClick` строки → `onAddAllFields(id)`.
В `App` диспатчит новое действие `ADD_ALL_FIELDS_DUP { tableId }` (или расширение
`ADD_ALL_FIELDS_WITH_TABLE` с флагом `allowDup`), которое добавляет каждое поле
таблицы как новую колонку с синонимом по правилу 7.8.11 (не пропуская существующие).

### 7.8.9 — Удалить колонку «Тип значения» из окна «Временная таблица»

**Сейчас:** `TempTableDialog` — таблица «Имя поля | Тип значения | ✕»; `type`
хранится и преобразуется в `MetaType[]`.
**Надо:** удалить колонку «Тип значения» полностью (вне скоупа).
**Решение:** `TempTableField` → `{ name: string }`; убрать `<select>`, заголовок
«Тип значения», `TEMP_TABLE_TYPES`/`tempFieldTypes` использование в действии.
`ADD_TEMP_TABLE` принимает `fields: { name: string }[]`, синтетические колонки
`types: []`. Обновить `queryStore.phase78.test.ts`.

### 7.8.14 — Двойной клик по синониму временной таблицы переоткрывает окно

**Надо:** двойной клик по синониму ВТ открывает окно «Временная таблица»,
заполненное (имя + поля).
**Решение:** пометить источник-ВТ флагом `SelectedTable.tempTable?: true` (ставит
`ADD_TEMP_TABLE`). Двойной клик по такому источнику → открыть `TempTableDialog` с
`initial = { name: defaultTableAlias(sel), fields }` (поля из синтетической
метатаблицы `state.tables`). ОК → `UPDATE_TEMP_TABLE { tableId, name, fields }`:
переименовать (fullName/alias), заменить колонки синтетической метатаблицы,
обрезать `selectedFields`, ссылающиеся на исчезнувшие пути.

### 7.8.8 — Полноценный рекурсивный конструктор вместо текстового окна подзапроса

**Сейчас:** `SubqueryDialog` — textarea с ручным текстом подзапроса; по ОК текст
парсится.
**Надо:** заменить на ПОЛНОЦЕННЫЙ рекурсивный конструктор (та же UI), плюс
переименовать кнопку `⊂З` → `ВЗ` (по аналогии с `ВТ`).
**Решение:** извлечь тело конструктора в переиспользуемый компонент
`ConstructorView` (вкладки + панели + нижняя панель + модалки), владеющий
СОБСТВЕННЫМ `useReducer`. `App` становится тонкой обёрткой (мост к хосту,
загрузка/индикатор, рендер `ConstructorView` верхнего уровня).

`ConstructorView` props:
- `metadataTables: MetaTable[]`, `expandedRefs: Map`, `onExpandRef(ref)` — общие
  метаданные приходят сверху (вложенный конструктор НЕ перезапрашивает метаданные);
- `initialDoc?: QueryDocument` — предзаполнение (для правки существующего подзапроса);
- `nested?: boolean` — режим вложенного: нижняя панель «ОК/Отмена» зовёт
  `onOk(doc)/onCancel` (а не хостовый insert/cancel); скрыта вкладка «Пакет запросов»
  (подзапрос — один документ объединения, не пакет);
- `onOk(doc: QueryDocument)`, `onCancel()` — для вложенного режима.

Извлечение модели вложенного: `assembleMembers(state)` → `{ members }`.
Предзаполнение: на mount `SET_METADATA(metadataTables)` + (если `initialDoc`)
`LOAD_BATCH({ members: [initialDoc] })`. Синхронизация `expandedRefs`: проп
`expandedRefs` + эффект, дозаписывающий новые записи во внутренний reducer
(`SET_REF_FIELDS`); `onExpandRef` пробрасывает запрос наверх к мосту.

Кнопка «ВЗ» открывает модалку с вложенным `ConstructorView`; по ОК —
`ADD_SUBQUERY_TABLE` с собранным `doc` (как сейчас, но `doc` из конструктора, а не
из парсинга текста). Старый `SubqueryDialog`/`parseError` удаляются.

### 7.8.15 — Двойной клик по синониму вложенного запроса переоткрывает конструктор

**Надо:** двойной клик по синониму подзапроса открывает конструктор запроса,
заполненный соответствующим образом.
**Решение:** двойной клик по источнику с `sel.subquery` → открыть вложенный
`ConstructorView` с `initialDoc = sel.subquery`. ОК → `UPDATE_SUBQUERY_TABLE
{ tableId, subquery, columns }`: заменить `sel.subquery`, пересчитать колонки
синтетической метатаблицы (`deriveUnionColumns`), обрезать исчезнувшие поля.

### 7.8.10 — Валидация запроса при нажатии ОК

**Сейчас:** ОК всегда вставляет сгенерированный текст (`handleInsert(batchText)`).
**Надо:** при ОК проверять корректность; при некорректном — выдавать ошибку и НЕ
сохранять.
**Решение (уточнено по ревью):** критерий корректности должен быть РОВНО ТАКИМ ЖЕ,
как при открытии конструктором из текста. Открытие из текста (`App.loadModel`)
разбирает входной текст через `parseBatch` и открывает запрос, если разбор удался.
Поэтому открытие из текста и проверка при «ОК» используют ЕДИНУЮ функцию
`tryParseBatch(text)` (`core/query/validateBatch.ts`) — общий источник правды:
запрос корректен ⟺ `parseBatch` его разбирает (не бросает). `validateBatchText`
поверх неё даёт `{ ok }`/`{ ok:false, error }`; пустой текст разбирается в пустой
пакет (как и при открытии из текста), отдельного спец-случая «пустой запрос» нет.
`App` (кнопка ОК) валидирует `batchText`; при `ok:false` показывает баннер
[data-testid=ok-error] и не постит `insertText` (кнопка и так заблокирована на
пустом `batchText`). Глубокая семантическая валидация имён полей по метаданным —
вне скоупа (риск ложных срабатываний на навигации/виртуальных полях) И вне паритета
с открытием из текста (которое тоже её не делает); фиксируем как ограничение.

## Границы и риски

- Рекурсивный конструктор (7.8.8) — самый рискованный рефактор: извлечение App-тела
  в `ConstructorView` не должно менять байт-вывод генератора (тесты 6.x). Делается
  как чистое извлечение + параметризация; верхнеуровневый рендер эквивалентен
  прежнему App.
- Синонимы меняют ВЫВОД генератора только для НОВЫХ действий пользователя (дубли);
  разбор существующих запросов (парсер ставит alias только при явном `КАК`) не
  затрагивается — round-trip фиделити сохраняется.
