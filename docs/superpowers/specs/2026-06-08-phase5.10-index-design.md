# Фаза 5.10 — Вкладка «Индекс» (дизайн)

## Контекст

Условная вкладка конструктора 1С, которая появляется, когда на вкладке
«Дополнительно» выбран **Тип запроса = Создание ВТ** (`ПОМЕСТИТЬ`). Позволяет описать
индексы создаваемой временной таблицы и сгенерировать предложение
`ИНДЕКСИРОВАТЬ ПО` / `ИНДЕКСИРОВАТЬ ПО НАБОРАМ`.

ТЗ: `tmp/индекс.md`. Эталоны текста — скриншоты
`tmp/console_screenshots/Screenshot_20260608_135721.png` (НАБОРАМ) и
`…_135828.png` (ПО). Это продолжение фазы 5.3 «Дополнительно», где вкладка «Индекс»
была явно отложена «За рамками».

## Поведение (из ТЗ + скриншоты)

Вкладка состоит из трёх списков и двух тулбаров:

1. **«Индексы»** (слева) — список индексов. Колонки:
   - **Имя** — назначается автоматически `Индекс <порядковый номер>` (с 1),
     **предопределено и не редактируется**.
   - **Уникальный** — галочка, признак уникальности индекса.
   Тулбар над списком: ⊕ добавить индекс · ⧉ добавить копированием · ✕ удалить ·
   ↑ ↓ переместить. Выделение строки задаёт «текущий индекс».

2. **«Поля»** (середина) — поля выборки текущего запроса (с вкладки «Таблицы и поля»),
   которые **ещё не входят** в текущий (выделенный) индекс. Поле можно перетащить в
   правый список или перенести кнопками `>` (выбранное) / `>>` (все).

3. **«Поля выделенного индекса»** (справа) — поля текущего индекса, в порядке.
   Тулбар: ↑ ↓ переместить поле. Кнопки между списками `<` (убрать выбранное) /
   `<<` (убрать все) возвращают поля в средний список.

Одно и то же поле выборки может входить в несколько индексов одновременно (см.
скриншот: `Ссылка` в Индекс 1 и доступно для Индекс 2).

Поле адресуется по **псевдониму выборки** (как в УПОРЯДОЧИТЬ ПО / ИТОГИ):
`selectAliasFor(model, tableId, path)` — явный `alias` поля, иначе последний сегмент
пути. В тексте индекса выводится только псевдоним, без префикса таблицы.

## Текст запроса (эталоны)

Секция дописывается **в самом конце** запроса, после блока `ИЗ` (и после
УПОРЯДОЧИТЬ/ИТОГИ, если они есть), с **пустой строкой-разделителем** (`\n\n`).

Выбор формы — **по количеству непустых индексов**:

- **Ровно один индекс** → `ИНДЕКСИРОВАТЬ ПО`, затем каждое поле с отступом в один таб,
  запятая после всех, кроме последнего:

  ```
  ИНДЕКСИРОВАТЬ ПО
  	Ссылка,
  	Наименование
  ```

  Уникальность одиночного индекса в тексте **не выражается** (синтаксис
  `ИНДЕКСИРОВАТЬ ПО` не имеет ключевого слова `УНИКАЛЬНО`) — следуем ТЗ: одна таблица →
  `ИНДЕКСИРОВАТЬ ПО`.

- **Несколько индексов** → `ИНДЕКСИРОВАТЬ ПО НАБОРАМ`, открывающая `(`, по одному
  набору на индекс, закрывающая `)`. Набор: `\t(` + поля через `,\n\t`, закрывающая `)`
  приклеена к последнему полю, затем ` УНИКАЛЬНО` если индекс уникален. Между наборами —
  запятая после всего набора (включая `УНИКАЛЬНО`):

  ```
  ИНДЕКСИРОВАТЬ ПО НАБОРАМ
  (
  	(Ссылка),
  	(ПометкаУдаления,
  	Наименование) УНИКАЛЬНО
  )
  ```

**Пустые индексы** (без полей) пропускаются. Если непустых индексов нет — секция не
выводится. Секция выводится **только** при `queryType === 'createTemp'` (даже если в
модели остался `indexing` от прежнего типа запроса — генератор его игнорирует).

## Модель данных

`src/core/query/queryModel.ts` — новые типы и поле:

```ts
/** Один индекс временной таблицы. Имя («Индекс N») производное от позиции, не хранится. */
export interface QueryIndex {
  /** Колонка «Уникальный» — индекс содержит только уникальные записи. */
  unique: boolean;
  /** Поля индекса в порядке; адресуются по (tableId, path), как Order/Totals. */
  fields: FieldRef[];
}

export interface Indexing {
  indexes: QueryIndex[];
}
```

В `QueryModel` добавляется `indexing?: Indexing;` (рядом с `totals`, `builder`).
`FieldRef` уже существует (`{ tableId; path }`).

## Генератор SDBL

`src/core/query/sdblGenerator.ts`:

- Новая экспортируемая функция `renderIndex(indexing: Indexing | undefined, model: QueryModel): string[]`
  по алгоритму выше. Возвращает `[]`, если: `indexing` отсутствует, `queryType !== 'createTemp'`,
  или нет непустых индексов.
- В `generate()` — после блока `renderTotals` дописать:
  ```ts
  const indexLines = renderIndex(model.indexing, model);
  if (indexLines.length > 0) out += '\n\n' + indexLines.join('\n');
  ```
- Поле набора: `selectAliasFor(model, f.tableId, f.path)`.

## Состояние webview (`queryStore.ts`)

Индекс принадлежит **одному** `QueryModel` (тому, что с `ПОМЕСТИТЬ`), наравне с
`order`/`totals`. Изменения:

- `QueryState`: `indexing: Indexing` (плоское поле активного запроса).
- `SavedQuery`: `indexing: Indexing`.
- `initialState()`: `indexing: { indexes: [] }`.
- `snapshotActive` / `restoreSaved` (включая default-ветку при `null`) /
  `buildModelFromFlat`: пробросить `indexing`.
- Пруны при удалении: в `REMOVE_FIELD` и `REMOVE_TABLE` удалить поле из всех
  `indexing.indexes[*].fields` (как делается для `order`/`totals`); пустые индексы при
  этом **сохраняются** (пользователь мог их создать намеренно).

Действия (`QueryAction`) и редьюсер:

- `ADD_INDEX` — добавить пустой индекс `{ unique: false, fields: [] }`.
- `COPY_INDEX; index` — добавить копию указанного индекса (глубокая копия `fields`).
- `REMOVE_INDEX; index`.
- `MOVE_INDEX; index; dir: 'up' | 'down'`.
- `SET_INDEX_UNIQUE; index; unique`.
- `ADD_INDEX_FIELD; index; tableId; path` — добавить, если ещё не входит в этот индекс.
- `ADD_ALL_INDEX_FIELDS; index` — добавить все поля выборки, которых ещё нет в индексе
  (порядок — как в `model.fields`; источник полей передаётся в действии списком
  `fields: FieldRef[]`, чтобы редьюсер не зависел от формы поля выборки).
- `REMOVE_INDEX_FIELD; index; tableId; path`.
- `CLEAR_INDEX_FIELDS; index` — убрать все поля индекса.
- `MOVE_INDEX_FIELD; index; tableId; path; dir: 'up' | 'down'`.

Все мутации индексов иммутабельны (новые массивы), как остальные секции.
