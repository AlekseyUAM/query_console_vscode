# Спек — Фаза 6.9. Группировка и секция «ИМЕЮЩИЕ»

Дата: 2026-06-11. Опирается на 6.7 (оракул). Принцип: спек → план → TDD.

## 1. Цель

Закрыть область группировки против конструктора 1С:

1. **Пустая строка перед `СГРУППИРОВАТЬ ПО`.** Конструктор отделяет секцию группировки
   пустой строкой; наш генератор — нет. Из-за этого **0 из 92** валидных запросов с
   группировкой совпадают с конструктором.
2. **Секция `ИМЕЮЩИЕ`** (фильтр по агрегатам после группировки) — модель её не знает,
   все **36** запросов с `ИМЕЮЩИЕ` отклонены (33 не парсятся, 3 расходятся).

## 2. Раскладка (подтверждено оракулом)

- Перед `СГРУППИРОВАТЬ ПО` — ровно одна пустая строка (и при наличии `ГДЕ`, и сразу
  после `ИЗ`). Перед `ГДЕ` пустой строки НЕТ (подтверждено: 1337 принятых).
- `ИМЕЮЩИЕ` идёт сразу за блоком `СГРУППИРОВАТЬ ПО`, тоже с предшествующей пустой
  строкой; ключевое слово на своей строке, условия с отступом `\t`, как у `ГДЕ`:
  ```
  СГРУППИРОВАТЬ ПО
  	ВидыПроверок.Ссылка

  ИМЕЮЩИЕ
  	КОЛИЧЕСТВО(ВидыПроверок.СвойстваОбъекта.Ссылка) = 0
  ```
- Порядок секций: … ГДЕ → (пусто) СГРУППИРОВАТЬ ПО → (пусто) ИМЕЮЩИЕ → (пусто)
  УПОРЯДОЧИТЬ → ИТОГИ → ИНДЕКСИРОВАТЬ.

## 3. Модель

`QueryModel.having?: Condition[]` — переиспользуем тип `Condition` (как у `ГДЕ`).
Условия `ИМЕЮЩИЕ` — это сравнения агрегатов (`КОЛИЧЕСТВО(…) = 0`, `СУММА(…) > 100`),
которые `trySimpleCondition` не распознаёт как простое поле, поэтому они сохраняются как
`custom`-выражения и выводятся дословно. Многострочный реиндент сложных условий — 6.10.

## 4. Парсер

- Обобщить `splitConditionSegments` стоп-множеством ключевых слов (для `ГДЕ` —
  `{СГРУППИРОВАТЬ, ИМЕЮЩИЕ, УПОРЯДОЧИТЬ, ИТОГИ, ИНДЕКСИРОВАТЬ, АВТОУПОРЯДОЧИВАНИЕ, ДЛЯ}`).
- `parseHaving`: после `ИМЕЮЩИЕ` — те же сегменты по верхнеуровневому `И`, до
  `УПОРЯДОЧИТЬ`/`ИТОГИ`/`ИНДЕКСИРОВАТЬ`/`ДЛЯ`/eof.
- В `parseQuery` разобрать `ИМЕЮЩИЕ` сразу после `СГРУППИРОВАТЬ ПО`, перед
  `УПОРЯДОЧИТЬ`.

## 5. Генератор

- В `buildQueryBlock`: если `groupingLines` непусты — добавить перед ними пустую строку.
- `renderHaving(having)` → `['', 'ИМЕЮЩИЕ', '\t<c0>', '\tИ <c1>', …]` (ведущая пустая
  строка, далее как `renderConditions`, но ключевое слово `ИМЕЮЩИЕ`). Размещается сразу
  после `groupingLines`.

## 6. Критерии приёмки

- Пустая строка перед `СГРУППИРОВАТЬ ПО` — растёт число принятых по оракулу (часть из 69
  расходящихся группировок).
- `ИМЕЮЩИЕ` парсится и генерируется; растёт число принятых (часть из 36).
- Вся `npm run test:unit` зелёная (обновить ожидания группировочных тестов/фикстур под
  пустую строку); новые фикстуры `test/fixtures/oracle/*.json` для группировки и
  `ИМЕЮЩИЕ`.

## 7. Вне 6.9

Многострочный реиндент сложных условий `ИМЕЮЩИЕ`/`ГДЕ` и `ВЫБОР` — 6.10. Бара́е поле
группировки, квалифицируемое конструктором по схеме, — общий метаданный остаток (как в
R3).
