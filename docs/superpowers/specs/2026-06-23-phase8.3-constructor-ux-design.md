# Фаза 8.3 — доработки конструктора запроса (UX + корректность + производительность)

Дата: 2026-06-23. Источник требований: ручное тестирование конструктора на реальных
запросах (`tmp/1.bsl`, эталон ИТОГИ `tmp/1с/Снимок экрана_20260623_211010.png`).

Принцип фазы (как и вся Фаза 8): доработки **поверх** канонического конвейера
`parseBatch → QueryModel → generateBatch`. Золотой оракул и регрессия корпуса обязаны
остаться байт-в-байт (проверено: `test:unit` 1304/1304 без изменений).

## 8.3.1 — кнопки Вверх/Вниз на «Объединения/Псевдонимы»

В «Списке полей» не было управления порядком колонок объединения. Колонки объединения
**позиционны** (i-я колонка = i-е скалярное поле `model.fields` каждого участника),
поэтому перемещение колонки — позиционный своп i-го и соседнего поля **во всех
участниках**. Новое действие reducer `MOVE_UNION_COLUMN { index, dir }`: своп
`selectedFields` активного запроса и `savedQueries[*].selectedFields` остальных. UI:
выбор строки-колонки + кнопки ↑/↓ (выделение следует за перемещаемой строкой).

## 8.3.2 — вкладка «Итоги»: заполнение, перетаскивание, выбор функции

Три дефекта:
1. **Неверное заполнение при открытии.** Распарсенный простой агрегат
   `Количество(Наименование)` даёт `TotalField { tableId:'', path:'', func:'Количество',
   operandAlias:'Наименование', expression:'Количество(Наименование)' }`. UI подписывал
   итоговое поле через `labelFor(tableId, path)` → пусто. Исправлено: подпись берётся из
   `operandAlias` (`totalFieldLabel`).
2. **Нельзя перетащить поле в список итоговых.** Дроп фильтровался «только числовые»
   (`isNumericField`). Снято: Количество/Максимум/Минимум применимы и к нечисловым.
3. **Поле «Выражение» должно быть выбором функции.** Заменили текстовый ввод на
   выпадающий список: Количество, Количество различные, Максимум, Минимум
   (`КоличествоРазличных` рендерится как `КОЛИЧЕСТВО(РАЗЛИЧНЫЕ …)`). Нестандартные
   функции (Сумма/Среднее) из распарсенного запроса сохраняются доп. опцией;
   агрегаты-выражения (ВЫБОР…, параметр) без `func` показываются текстом (read-only).

Адресация итоговых полей переведена с `(tableId, path)` на **индекс**
(`REMOVE_TOTAL_FIELD { index }`, `SET_TOTAL_FIELD_FUNC { index, func }`): у
распарсенных агрегатов `(tableId, path)` пусты и неуникальны. Новое поле из UI:
`func:'Количество'`, `operandAlias` = псевдоним колонки выборки; генератор печатает
канонически через `wrapAggregate` (без сырого `expression`). Каскады
`REMOVE_TABLE`/`REMOVE_FIELD` сохранены (фильтр по `tableId`/`path`, которые у
добавленных из UI полей заданы).

## 8.3.3 — убрать подсказки «Перетащите …»

Удалены пустые состояния «Перетащите поле сюда…» (Условия), «Перетащите поля из
списка…» (Порядок, Построитель). Подсказка «Нет полей…» в Построителе сохранена.

## 8.3.4 — список «Запросы пакета» занимает всё пространство

`BatchTab`: панель списка была фиксированной ширины (`width: 320`). Переведена на
`flex: 1, minWidth: 0`.

## 8.3.5 — поля-выражения показываются текстом выражения, а не синонимом

В `FieldsPanel` поле с произвольным выражением подписывалось псевдонимом
(`f.alias ?? f.expression`). Синоним при сборке запроса в конструкторе ещё не известен,
поэтому показываем **начало текста выражения** (`ВЫБОР КОГДА …`), схлопнув пробелы,
в одну строку с многоточием и полным текстом в `title`.

## 8.3.6 — производительность на больших запросах

Главная причина «торможения» — лишние полные `generateBatch` по всему пакету на каждом
ре-рендере:
- `ConstructorView`: переменная `batchText` (строка 123) **вообще не использовалась** —
  полная генерация всего пакета впустую на каждом ре-рендере (смена вкладки, открытие
  диалога, фокус, drag). Удалена.
- `ConstructorView`: `assembleMembers`/`deriveUnionColumns`/`batchNames` и вложенный
  `nestedBatchText` обёрнуты в `useMemo` по `state`/`nestedState` — не пересчитываются
  на ре-рендерах от локального UI-состояния.
- `App`: `batchText` обёрнут в `useMemo([state, preserveComments])` — не пересобирается
  на ре-рендерах от баннеров ошибки/загрузки и тулбара кэша.

## 8.3.7 — перетаскиваемые границы панелей/колонок

Новый переиспользуемый компонент `ResizeHandle` (`onResize(delta)`, ось x/y, захват
мыши на `window`). Применён к границам списков:
- окно «Произвольное выражение» (`ExpressionBuilder`): ширина списка «Поле» и высота
  поля ввода;
- вкладки: «Таблицы и поля» (3 панели), Условия, Порядок, Итоги, Построитель,
  Объединения/Псевдонимы, Группировка, Индексы. «Связи» — одна панель (нечего двигать).

Ширины хранятся в локальном `useState` каждой вкладки (сбрасываются при перемонтаже).
