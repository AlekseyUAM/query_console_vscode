# Фаза 5.3 — Вкладка «Дополнительно» (дизайн)

ТЗ: `tmp/дополнительно.md`. Скриншоты: `…_220120.png` (Первые), `…_220627.png`
(Создание ВТ), `…_221117.png` (Блокировать → ДЛЯ ИЗМЕНЕНИЯ).

## Цель

Управление префиксом выборки и хвостом запроса:
- **Выборка записей**: `ПЕРВЫЕ n`, `РАЗЛИЧНЫЕ` (Без повторяющихся), `РАЗРЕШЕННЫЕ`.
- **Тип запроса**: Выборка данных | Создание ВТ (`ПОМЕСТИТЬ`) | Добавление
  (`ДОБАВИТЬ`) | Уничтожение (`УНИЧТОЖИТЬ`), с именем временной таблицы.
- **Блокировать данные** → `ДЛЯ ИЗМЕНЕНИЯ` со списком таблиц.

## Модель (`src/core/query/queryModel.ts`)

```ts
export interface Selection {
  top?: number;        // ПЕРВЫЕ n (undefined/0 — нет)
  distinct?: boolean;  // РАЗЛИЧНЫЕ
  allowed?: boolean;   // РАЗРЕШЕННЫЕ
}
export type QueryType = 'select' | 'createTemp' | 'appendTemp' | 'dropTemp';

export interface QueryModel {
  // …
  selection?: Selection;
  queryType?: QueryType;       // по умолчанию 'select'
  tempTableName?: string;      // для createTemp/appendTemp/dropTemp
  lockForUpdate?: string[];    // ДЛЯ ИЗМЕНЕНИЯ — полные имена таблиц (Справочник.Валюты)
}
```

## Генератор SDBL

Порядок секций (полный): `ВЫБРАТЬ <модиф> <поля>` → `ПОМЕСТИТЬ|ДОБАВИТЬ <ВТ>` → `ИЗ`
→ `ГДЕ` → `СГРУППИРОВАТЬ ПО` → `ДЛЯ ИЗМЕНЕНИЯ`.

1. **Модификаторы ВЫБРАТЬ.** Первая строка: `ВЫБРАТЬ` + при наличии (в этом порядке)
   ` РАЗРЕШЕННЫЕ`, ` РАЗЛИЧНЫЕ`, ` ПЕРВЫЕ ${top}`. Напр. `ВЫБРАТЬ ПЕРВЫЕ 2`,
   `ВЫБРАТЬ РАЗЛИЧНЫЕ`, `ВЫБРАТЬ РАЗРЕШЕННЫЕ РАЗЛИЧНЫЕ ПЕРВЫЕ 2`.
2. **ПОМЕСТИТЬ/ДОБАВИТЬ.** При `queryType==='createTemp'` — строка `ПОМЕСТИТЬ <имя>`
   между полями и `ИЗ`; при `appendTemp` — `ДОБАВИТЬ <имя>`. Имя пустое → секция не
   добавляется (но тип учитывается; если имени нет — считаем обычной выборкой).
3. **УНИЧТОЖИТЬ.** При `queryType==='dropTemp'` весь запрос — единственная строка
   `УНИЧТОЖИТЬ <имя>` (без ВЫБРАТЬ/ИЗ). Обрабатывается в начале `generate` (до
   проверок на наличие таблиц/полей). Пустое имя → `''`.
4. **ДЛЯ ИЗМЕНЕНИЯ.** При непустом `lockForUpdate` — в конце:
   ```
   <предыдущая строка>

   ДЛЯ ИЗМЕНЕНИЯ
   	Справочник.Валюты
   ```
   Перед `ДЛЯ ИЗМЕНЕНИЯ` — **пустая строка** (как в эталоне ТЗ). Каждая таблица — с
   таб-отступом, полным именем (как сохранено в `lockForUpdate`).

Эталоны — `tmp/дополнительно.md` (строки 13-17, 36-41, 59-66). Отсутствие/пустота всех
новых полей → вывод байт-в-байт как раньше.

## Webview

- Вкладка «Дополнительно» в `App` (вместо placeholder), компонент `AdditionalTab`.
- Группа **Выборка записей**: чекбокс «Первые» + числовое поле (активно при чекбоксе),
  чекбоксы «Без повторяющихся» (`distinct`), «Разрешенные» (`allowed`).
- Группа **Тип запроса**: радиокнопки (Выборка данных / Создание ВТ / Добавление /
  Уничтожение). Поле «Имя временной таблицы» активно для трёх ВТ-режимов.
- Чекбокс **Блокировать получаемые данные…** → разблокирует два списка: «Таблицы»
  (выбранные таблицы запроса) и «Таблицы для изменения». Перетаскивание/кнопки между
  ними формируют `lockForUpdate` (полные имена). При снятии галочки `lockForUpdate`
  очищается.
- Состояние в `queryStore`: `selection`, `queryType`, `tempTableName`, `lockForUpdate`,
  `lockEnabled` (UI-флаг галочки). Экшены: `SET_SELECTION_TOP`, `SET_SELECTION_DISTINCT`,
  `SET_SELECTION_ALLOWED`, `SET_QUERY_TYPE`, `SET_TEMP_TABLE_NAME`, `SET_LOCK_ENABLED`,
  `ADD_LOCK_TABLE`, `REMOVE_LOCK_TABLE`.
- Прокидывание в `generate(...)` (Запрос / ОК): `selection`, `queryType`,
  `tempTableName`, `lockForUpdate`.

## Не входит

`ИНДЕКСИРОВАТЬ ПО` (вкладка Индекс при ВТ), параметры блокировки уровня изоляции,
автоудаление таблиц из `lockForUpdate` при удалении таблицы из выборки.

## Тестирование

- Unit генератора: каждый модификатор и комбинация; ПОМЕСТИТЬ/ДОБАВИТЬ перед ИЗ;
  УНИЧТОЖИТЬ как единственная строка; ДЛЯ ИЗМЕНЕНИЯ с пустой строкой-разделителем и
  полным именем; совместимость с ГДЕ/группировкой (порядок); пустые поля не меняют
  вывод. `assertValidSdbl`.
- Unit queryStore: новые экшены.
- Оракул `validate_query` — оркестратор.
