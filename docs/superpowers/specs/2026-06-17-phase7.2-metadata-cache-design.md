# Фаза 7.2. Ускорение загрузки метаданных (консолидированный кэш) — спек

← [PHASE_7](../../PHASE_7.md) · [Дорожная карта](../../ROADMAP.md)

Дата: 2026-06-17.

## 1. Проблема (с замером)

При открытии конструктора метаданные грузятся через `loadMetadataFromYaml(cfYamlDir)`,
который **на каждое открытие** читает и парсит **~4505 отдельных YAML-файлов** (25 MB)
библиотекой `yaml`. Замер на реальной выгрузке (`tmp/parser_data/cf`, 6899 таблиц):

```
YAML load:        16263 ms   ← парсинг 4505 YAML-файлов
single JSON load:   232 ms   ← один JSON.parse того же MetadataModel (8.43 MB)
speedup:           70.1x
```

Оба симптома пользователя объясняются этим: и дерево метаданных, и текст запроса
(`loadModel` в `panel.ts` отправляется **после** `await metadataReady`) ждут ~16 с.

## 2. Решение: один консолидированный JSON-кэш модели

Парсить YAML дорого, `JSON.parse` готового `MetadataModel` — дёшево. Строим полную
модель один раз и сериализуем в **единственный** файл `model-cache.json` рядом с
каталогом `cf/`. На последующих открытиях читаем+парсим этот один файл.

Инвалидация — по mtime (как в существующем `cacheLoader.ts` для XML-пути): скан
`newestMtime(cfYamlDir)` стоит ~70 мс (замерено) — пренебрежимо против 16 с. Кэш
свежий, если: файл существует, `cacheVersion` совпадает с текущим, и mtime кэша
≥ newest mtime YAML-дерева. Иначе — пересобрать из YAML и перезаписать кэш.

Итог на горячем пути: скан mtime (~70 мс) + `JSON.parse` (~232 мс) ≈ **300 мс против
16 с (~50x)**.

### Свойства

- **Самовосстановление.** Для уже распарсенных выгрузок (без `model-cache.json`)
  первое открытие платит 16 с один раз, пишет кэш, дальше быстро.
- **Автоинвалидация.** Кнопка «Обновить кэш» / авто-парсинг перезаписывают YAML →
  их mtime новее кэша → кэш пересобирается на следующем открытии. Ручных шагов нет.
- **Версионирование формата.** Константа `MODEL_CACHE_VERSION`; бамп при изменении
  формата `MetadataModel` или логики `loadMetadataFromYaml` форсит пересборку
  устаревшего кэша (защита от схемы старой версии расширения).
- **Best-effort запись.** Если запись кэша не удалась (ro-fs и т.п.) — модель уже
  посчитана и возвращается; следующее открытие просто снова посчитает.

## 3. Где живёт

Новый pure-TS модуль `src/core/metadata/modelCache.ts`:

```ts
export const MODEL_CACHE_VERSION = 1;
export function modelCachePath(cfYamlDir: string): string; // dirname(cfYamlDir)/model-cache.json
export function loadMetadataCached(cfYamlDir: string): MetadataModel;
```

`panel.ts` (`loadMetadata`): ветка «YAML существует» зовёт `loadMetadataCached(cfYamlDir)`
вместо `loadMetadataFromYaml(cfYamlDir)`; добавляем тайминг в OutputChannel.

Кэш лежит в `dirname(cfYamlDir)` (= `outPath`), а скан mtime идёт по `cfYamlDir` —
кэш не попадает в собственный скан, самоссылки нет.

## 4. Вне области

`loadMetadataFromYaml` (источник истины — остаётся), парсер YAML, генератор, корпусный
гейт, формат YAML на диске — не трогаем. `loadModel` остаётся за `metadataReady`
(после фикса ~300 мс это уже не проблема; не усложняем порядок сообщений).

## 5. Приёмка

- Юнит-тесты `modelCache`: build-on-miss, cache-hit (возврат содержимого кэша, не
  YAML), инвалидация по mtime, инвалидация по `cacheVersion`.
- На реальной выгрузке второе открытие < ~0.5 с (против ~16 с).
- `npm run test:unit` зелёный; `npm run build:extension` OK.
