# Подфаза 7.8 — доработки UI конструктора (дизайн)

← [PHASE_7.md](../../PHASE_7.md)

Продолжение доработок UI поверх готового конструктора (7.5–7.7). Девять независимых
пунктов: ускорение открытия, поведение вкладки «Таблицы и поля», видимость вкладок,
два новых источника (вложенный запрос / временная таблица).

## Пункты и решения

### 7.8.1 — тёплый JSON-кэш после «Обновить кэш»
**Симптом.** Первое открытие конструктора каждую сессию очень долгое.
**Причина.** «Обновить кэш» (`refreshCache`) вызывает `parseConfiguration`, который
переписывает YAML (новый mtime) и тем самым инвалидирует `model-cache.json`. Следующее
открытие платит холодный разбор YAML (~13 с). Сам консолидированный кэш Подфазы 2 НЕ
перестраивался при обновлении.
**Решение.** Экспортировать `rebuildModelCache(cfYamlDir)` (ядро `modelCache.ts`) —
безусловная пересборка модели из YAML + запись `model-cache.json` через общий
`writeModelCache` (формат идентичен `loadMetadataCached`). `panel.ts` вызывает его сразу
после `parseConfiguration` в обработчике `refreshCache`. Следующее открытие — тёплое.

### 7.8.2 — открывать сразу заполненным
**Симптом.** При открытии текста запроса видно пустой конструктор, затем он заполняется.
**Решение.** Хост шлёт `init { hasInitialQuery }` ДО `metadataTree`. Вебвью держит
оверлей «Загрузка конструктора…» (zIndex поверх всего), пока: нет входного запроса —
до `metadataTree`; есть входной запрос — до `loadModel`. Конструктор монтируется под
оверлеем (состояние уже заполнено редьюсером к моменту снятия оверлея) — мигания нет.

### 7.8.3 — отдельное окно
**Решение.** Настройка `queryConsole.openInNewWindow` (default `true`). После
`createPanel` (webview становится активным редактором) выполняем штатную команду
`workbench.action.moveEditorToNewWindow`. На платформах без поддержки (старый VS Code,
web) ошибка гасится — остаёмся во вкладке. Фича VS Code 1.85+.

### 7.8.4 — «+» в списке «Поля»
**Симптом.** Кнопка «+» не работает.
**Причина.** Была включена только при фокусе таблицы (`focusedSelectedTableId !== null`).
**Решение.** Включаем при наличии ≥1 выбранной таблицы; открываем «Произвольное
выражение» с полями ВСЕХ таблиц (`qualifiedFieldsAllTables`); по ОК — новое
поле-выражение (`ADD_EXPRESSION_FIELD`, привязка к фокусной/первой таблице). e2e-тест.

### 7.8.5 — двойной клик по полю
**Решение.** Двойной клик по строке поля открывает «Произвольное выражение»,
предзаполненное текстом выражения (или квалифицированным путём `Alias.Поле`). По ОК —
правка поля НА МЕСТЕ через `SET_FIELD_EXPRESSION` (поле становится выражением, второго
поля не создаётся). e2e-тест.

### 7.8.6 — перетаскивание таблицы в «Поля» = все поля
**Симптом.** В «Поля» можно перетащить только отдельный реквизит.
**Решение.** `FieldsPanel.handleDrop` обрабатывает `kind:'table'` → `onDropTable`;
App резолвит поля метаданных и шлёт `ADD_ALL_FIELDS_WITH_TABLE` (создаёт источник при
необходимости, дедуплицирует). Строки списка «Таблицы» делаем `draggable` (payload
`kind:'table'`), чтобы перенос работал и из дерева метаданных, и из списка таблиц.
e2e-тест.

### 7.8.7 — видимость вкладок
**Симптом.** Вкладки сливаются в один цвет/панель.
**Решение.** Классический сегментный вид (`TabsBar`): разделители между вкладками,
утопленный фон неактивных, приподнятый фон + верхний акцент (`focusBorder`) у активной.
Хуки `data-testid="tabsbar"`/`data-tab` сохранены.

### 7.8.8 — кнопка «Вложенный запрос» в списке «Таблицы»
**Решение.** Кнопка `⊂З` открывает окно «Вложенный запрос» (MVP — отдельный редактор
текста подзапроса; полноценный рекурсивный конструктор — будущая работа). По ОК текст
разбирается `parseBatch`, колонки берутся `deriveUnionColumns`, добавляется источник
`SelectedTable.subquery` + синтетическая метатаблица его колонок
(`ADD_SUBQUERY_TABLE`). Генератор уже умеет источники-подзапросы (Фаза 6.15) →
`(ВЫБРАТЬ …) КАК ВложенныйЗапрос`.

### 7.8.9 — кнопка «Временная таблица» в списке «Таблицы»
**Решение.** Кнопка `ВТ` открывает окно «Временная таблица» (имя + сетка полей
{Имя поля, Тип значения}; типы — `Строка/Число/Дата/Булево`). По ОК — `ADD_TEMP_TABLE`:
синтетическая метатаблица + источник; генерируется `ИЗ <ВТ> КАК <ВТ>`. См. референс
`tmp/1с/Снимок экрана_2026-06-18_20-12-31.png`.

## Представление синтетических источников (7.8.8/7.8.9)
Источник-подзапрос и описание ВТ нуждаются в списке колонок для панелей. Колонки
резолвятся по `fullName` из `state.tables`. Добавляем синтетическую `MetaTable` с видом
`ТабличнаяЧасть` — он НЕ входит в `GROUP_KINDS` дерева метаданных (`DbTreePanel`),
поэтому источник не засоряет левое дерево, но его колонки доступны в `TablesPanel`/
`fieldsForTable`/перетаскивании как у обычной таблицы. Имена источников уникализируются
(`base`, `base2`, …).
