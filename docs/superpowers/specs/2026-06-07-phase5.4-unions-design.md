## Цель

Несколько подзапросов, объединяемых через `ОБЪЕДИНИТЬ [ВСЕ]`. Документ запроса
становится списком подзапросов; колонки выборки выравниваются **по псевдониму поля**:
совпал псевдоним → одна строка-колонка; нет соответствия в подзапросе → `NULL`.
Псевдоним (`КАК`) выводится только у первого подзапроса; остальные — позиционно, без
`КАК`.

## Принцип: колонки выводятся из псевдонимов полей

Колонка объединения **детерминированно выводится** из полей подзапросов по их
псевдониму — отдельного редактируемого хранилища колонок нет.

```ts
// src/core/query/unionModel.ts (новый)
export interface UnionMember {
  name: string;       // «Запрос 1»
  distinct: boolean;  // «Без дупликатов» → ОБЪЕДИНИТЬ (а не ОБЪЕДИНИТЬ ВСЕ) ПЕРЕД этим членом
  model: QueryModel;  // полноценный подзапрос (таблицы/поля/группировка/условия/доп.)
}

export interface UnionColumn {
  alias: string;                 // псевдоним колонки (КАК у первого члена)
  cells: (string | null)[];      // длина = members.length; выражение поля или null→NULL
}

export interface QueryDocument { members: UnionMember[]; }
```

**Псевдоним поля члена** (для совпадения колонок и для `КАК` первого члена):
`field.alias ?? lastSegment(field.path)`. **Выражение ячейки**: `Псевдоним.Поле`
(как обычное поле выборки данного члена; учитываются произвольные поля — `expression`).
Поля ТЧ в объединениях не поддерживаются (за рамками).

`deriveUnionColumns(members): UnionColumn[]`:
1. Порядок колонок = псевдонимы в порядке появления: сперва поля члена 0, затем новые
   псевдонимы из члена 1 и т.д.
2. Для каждой колонки `cells[i]` = выражение поля члена i с этим псевдонимом, иначе
   `null`.

## Генератор (`src/core/query/sdblGenerator.ts`)

Рефактор: выделить построение блока запроса в переиспользуемую функцию, принимающую
**готовые строки полей** (чтобы объединение подменяло список `ВЫБРАТЬ`). Существующая
`generate(model)` сохраняет поведение байт-в-байт (все 400+ тестов зелёные).

`generateDocument(doc: QueryDocument): string`:
- `members.length === 0` → `''`.
- `members.length === 1` → `generate(members[0].model)` (обычный путь, без объединения,
  полная поддержка 5.1–5.3).
- иначе:
  - `columns = deriveUnionColumns(members)`.
  - Для каждого члена i строки полей ВЫБРАТЬ из колонок: `expr = col.cells[i] ?? 'NULL'`;
    элемент = `i === 0 ? \`${expr} КАК ${col.alias}\` : expr`. Запятые как обычно.
  - Остальная часть блока члена (ПЕРВЫЕ/РАЗЛИЧНЫЕ, ПОМЕСТИТЬ, ИЗ+источники, ГДЕ,
    СГРУППИРОВАТЬ ПО, ДЛЯ ИЗМЕНЕНИЯ) — из `member.model` через общий построитель блока.
  - Члены соединяются разделителем: перед членом i (i≥1) — `\n\nОБЪЕДИНИТЬ ВСЕ\n\n` или
    `\n\nОБЪЕДИНИТЬ\n\n`, если `members[i].distinct === true`.

Эталоны (точно, из `tmp/объединения.md`): блок с `NULL КАК Наименование` + `ДЛЯ
ИЗМЕНЕНИЯ` + `ОБЪЕДИНИТЬ ВСЕ` + второй блок с `NULL` без `КАК` (строки 22-39);
после сопоставления (строки 44-59); после переименования псевдонима (строки 63-78);
после смены порядка (строки 82-97).

## Webview store (`src/webview/state/queryStore.ts`)

Многозапросность через **механизм подмены активного запроса** (минимальная инвазивность
к 5.0–5.3): существующее «плоское» состояние = рабочий набор АКТИВНОГО подзапроса.
Добавляются:
```ts
queryList: { name: string; distinct: boolean }[];   // все запросы (вкл. активный)
activeQuery: number;
savedQueries: (SavedQuery | null)[];                // снимок каждого запроса; активный слот null (живёт в плоском состоянии)
```
`SavedQuery` — сериализуемый срез плоского состояния (selectedTables, selectedFields,
tabSectionFields, grouping, conditions, selection, queryType, tempTableName,
lockForUpdate). Init: один запрос «Запрос 1», `activeQuery=0`.

Хелпер `assembleMembers(state): UnionMember[]` — собирает членов: для активного индекса
берёт плоское состояние, иначе `savedQueries[i]`; `model` строится как в текущих путях
генерации.

Экшены:
- `ADD_QUERY` — снимок активного → `savedQueries`, добавить «Запрос N» (distinct=false),
  переключить активный на него, очистить плоское состояние.
- `REMOVE_QUERY; index`, `SET_ACTIVE_QUERY; index` (снимок старого, загрузка нового),
  `RENAME_QUERY; index; name`, `SET_QUERY_DISTINCT; index; distinct`.
- `SET_COLUMN_ALIAS; alias; newAlias` — переименовать псевдоним колонки: обновить
  `field.alias` у поля с этим псевдонимом во ВСЕХ членах, где колонка есть (включая
  снимки и активный). Так колонка остаётся слитой; `КАК` выводится только у первого.
- (если выполнимо) `MOVE_COLUMN; alias; dir` — изменить порядок: переставить поле во
  всех членах; и `SET_COLUMN_CELL; alias; memberIndex; path` — сопоставить поле
  ячейке `<Отсутствует>` (задать псевдоним этого поля = alias колонки). Если сложно —
  допустимо отметить как ограничение в отчёте.

Тесты на ключевые экшены (add/remove/switch query сохраняют состояние; rename alias;
distinct).

## Webview UI (`src/webview/App.tsx`, `src/webview/components/UnionsTab.tsx` новый)

- **Боковые вкладки запросов** (правый край, вертикально): «Запрос 1», «Запрос 2», …,
  активный подсвечен; клик → `SET_ACTIVE_QUERY`. Показывать только при `>1` запросе
  (как в скриншоте `…_222016.png`). Доступны на всех вкладках конструктора, чтобы
  активный запрос можно было строить через Таблицы/Группировку/Условия/Дополнительно.
- **UnionsTab** (вкладка «Объединения/Псевдонимы»):
  - Левый список «Список запросов»: колонки Имя (редактируется → `RENAME_QUERY`), Без
    дупликатов (чекбокс → `SET_QUERY_DISTINCT`). Тулбар: добавить (`ADD_QUERY`), удалить
    (`REMOVE_QUERY`).
  - Правая таблица «Список полей»: первая колонка «Имя поля» (псевдоним, редактируется →
    `SET_COLUMN_ALIAS`; при некорректном псевдониме — сообщение, см. ниже), далее по
    колонке на каждый запрос со значением ячейки (`Псевдоним.Поле`) или «<Отсутствует>».
    Строки = `deriveUnionColumns(assembleMembers(state))`. По возможности — стрелки
    порядка и выбор поля для `<Отсутствует>`.
  - Валидация псевдонима: должен начинаться с буквы и содержать только буквы/цифры/`_`
    (regex `/^[A-Za-zА-Яа-яЁё_][A-Za-zА-Яа-яЁё0-9_]*$/`). Иначе — не применять и показать
    сообщение «Псевдонимы полей должны начинаться с буквы и могут содержать только
    буквы, цифры, и символ '_'» (скриншот `…_222545.png`).
- Генерация (Запрос / ОК): использовать `generateDocument(assembleMembers(state))`
  вместо `generate(...)`. При одном запросе результат идентичен текущему.

## Не входит

Поля ТЧ в объединениях; пересечение/разность; горизонтальные объединения; полное
повторение всех микровзаимодействий 1С (drag между запросами). Reorder/remap — по
возможности (см. выше).

## Тестирование

- Unit `unionModel`/генератор: `deriveUnionColumns` (совпадение по псевдониму, порядок,
  NULL); `generateDocument` для 1 члена (= generate), 2 членов (эталоны ТЗ),
  ОБЪЕДИНИТЬ vs ОБЪЕДИНИТЬ ВСЕ (distinct), переименование псевдонима. `assertValidSdbl`.
- Существующие тесты генератора — без регрессий (рефактор блока прозрачен).
- Unit queryStore: экшены запросов/псевдонимов.
- Оракул `validate_query` на объединённом тексте — оркестратор.
