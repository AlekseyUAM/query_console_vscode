## Цель

Вкладка «Условия»: список условий отбора → секция `ГДЕ`. Условие либо простое
(`Поле Оператор Параметр`), либо произвольное (`П.` включено → произвольное выражение
через то же окно ExpressionBuilder, что и для полей).

## Модель (`src/core/query/queryModel.ts`)

```ts
export type ConditionOperator = '=' | '<>' | '>' | '>=' | '<' | '<=' | 'В' | 'МЕЖДУ' | 'ПОДОБНО';

export interface Condition {
  /** П. — произвольное выражение. */
  custom: boolean;
  // простое условие:
  tableId?: string;
  path?: string;
  operator?: ConditionOperator;  // по умолчанию '='
  param?: string;                // по умолчанию '&<ИмяПоля>'
  // произвольное:
  expression?: string;           // полный текст выражения
}

export interface QueryModel {
  // …
  conditions?: Condition[];
}
```

## Генератор SDBL

Секция `ГДЕ` рендерится **после `ИЗ`+источники и ПЕРЕД `СГРУППИРОВАТЬ ПО`** (порядок
языка: ВЫБРАТЬ → ИЗ → ГДЕ → СГРУППИРОВАТЬ ПО). Рендерить только при наличии хотя бы
одного «годного» условия.

- Текст одного условия:
  - простое: `Псевдоним.Поле <operator> <param>` (alias из общей карты; operator по
    умолчанию `=`; param по умолчанию `&<Поле>` — последний сегмент path).
  - произвольное (`custom`): `expression` как есть (trim). Пустое произвольное условие
    пропускается.
- Сборка:
  ```
  ГДЕ
  	<условие1>
  	И <условие2>
  ```
  Первое условие с одним таб-отступом, последующие — `\tИ <условие>`.

Эталон (ТЗ):
```
ГДЕ
	Валюты.Код = &Код
	И Валюты.Наименование = &Наименование
```

При отсутствии условий вывод не меняется (байт-в-байт).

## Webview

- Вкладка «Условия» в `App` (заменяет placeholder).
- `ConditionsTab` (новый компонент):
  - Левая панель «Поля»: поля выбранных таблиц (как простой список `Псевдоним.Поле`;
    раскрытие ссылочных — необязательно для 5.2). Перетаскивание поля в список условий
    создаёт простое условие (`=`, param `&<Поле>`).
  - Правая таблица «Условия»: колонки **Номер** (1..n авто), **П.** (чекбокс →
    `custom`), **Условие**. Для простого условия в строке: текст `Псевдоним.Поле`,
    выпадающий список оператора, поле ввода параметра. Для произвольного: текст
    выражения + кнопка «…» открывает `ExpressionBuilder` (доступные поля —
    `Псевдоним.Поле` всех выбранных таблиц, qualified). Тулбар: добавить/удалить.
- Состояние в `queryStore` (`conditions: Condition[]`), экшены: `ADD_CONDITION`
  (из перетаскивания поля), `REMOVE_CONDITION`, `SET_CONDITION_CUSTOM`,
  `SET_CONDITION_OPERATOR`, `SET_CONDITION_PARAM`, `SET_CONDITION_EXPRESSION`.
- `conditions` прокидывается в `generate(...)` в обоих путях (Запрос / ОК).

## Не входит

`ИЛИ`, скобки/группы условий, `В ИЕРАРХИИ`, валидация псевдонима параметра, раскрытие
ссылочных полей в дереве условий, `ИМЕЮЩИЕ`.

## Тестирование

- Unit генератора: одно/несколько простых условий (`И`), произвольное условие,
  порядок ГДЕ относительно СГРУППИРОВАТЬ ПО, пустые условия игнорируются, отсутствие
  условий не меняет вывод. `assertValidSdbl` на результате.
- Unit queryStore: экшены условий.
- Валидация сгенерированного `ГДЕ`-текста через `validate_query` (оракул) — делает
  оркестратор.
