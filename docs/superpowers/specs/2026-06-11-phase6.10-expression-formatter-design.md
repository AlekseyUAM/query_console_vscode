# Спек — Фаза 6.10. Форматер произвольных выражений

Дата: 2026-06-11. Опирается на 6.7 (оракул). Принцип: спек → план → TDD.

## 1. Проблема

Конструктор 1С применяет к произвольным выражениям (условия `ГДЕ`/`ИМЕЮЩИЕ`, условия
соединения `ПО`, поля выборки) собственный «красивый вывод» с переносами и отступами по
дереву операторов. Мы храним такие выражения как сырой текст и отдаём почти дословно —
отсюда бо́льшая часть оставшихся **437 расхождений**.

## 2. Реверс-инжиниринг правил (по оракулу)

### Булевы цепочки

- **Чистая цепочка `И`** (без `ИЛИ`) форматируется просто, без скобок, отступ 1 таб —
  это мы уже умеем (такие запросы приняты):
  ```
  ГДЕ
  	a
  	И b
  	И c
  ```
- **Смешанные `И`/`ИЛИ`** разворачиваются по приоритету и оборачиваются в скобки. Отступ
  растёт с глубиной вложения оператора; `И` глубже `ИЛИ`:
  ```
  ГДЕ a И b ИЛИ c   →
  	(a
  				И b
  			ИЛИ c)
  ```
  ```
  ГДЕ (a ИЛИ b) И c →
  	(a
  			ИЛИ b)
  	И c
  ```
  (Точные счётчики табов: верхний операнд группы — 1 таб с `(`; `ИЛИ` — 3 таба; `И`
  внутри — 4 таба. Алгоритм отступа — по уровню в дереве разбора выражения; уточняется
  серией пробо́в оракула в плане.)

### ВЫБОР (CASE)

`ВЫБОР … КОГДА … ТОГДА … ИНАЧЕ … КОНЕЦ` раскладывается по строкам с отступом
(`КОГДА`/`ТОГДА`/`ИНАЧЕ`/`КОНЕЦ` на своих строках). Точная раскладка — пробами.

### Пробелы и скобки

- Нет пробела перед `(` у вызовов функций и операторов списков (`В(…)`, `В ИЕРАРХИИ(…)`,
  `ЗНАЧЕНИЕ(…)`, `ЕСТЬNULL(…)`); после запятой — один пробел.
- Минимизация/нормализация скобок по правилам конструктора (отдельные конъюнкты могут
  получать/терять скобки — см. R5 в 6.8 для условий `ПО`).

## 3. Архитектура

Новый модуль `src/core/query/exprFormatter.ts`:

```ts
// Разбор произвольного выражения SDBL в AST и печать в каноническом виде 1С.
export function formatExpression(raw: string, baseIndent: number): string;
```

- **Лексер выражения** — переиспользовать `sdblLexer.tokenize` (он уже знает строки,
  числа, параметры, идентификаторы, ключевые слова).
- **Парсер выражения (Pratt/рекурсивный спуск)** по приоритетам: `ИЛИ` < `И` < `НЕ` <
  сравнения (`= <> < > <= >= В МЕЖДУ ПОДОБНО ЕСТЬ`) < аддитивные < мультипликативные <
  унарные < первичные (литералы, поля, вызовы, `ВЫБОР`, скобки, подзапрос-плейсхолдер).
- **Принтер** — воспроизводит отступы/скобки/пробелы конструктора (правила §2),
  параметризован базовым отступом секции.

Интеграция: `renderConditions`/`renderHaving`/`renderJoinCondition` и выражения-поля
выборки вызывают `formatExpression` вместо дословной вставки сырого текста — но **только
для выражений, где это безопасно** (см. §5).

## 4. Где подключать

- `ГДЕ`, `ИМЕЮЩИЕ`: каждый сегмент-условие (между верхнеуровневыми `И`) — если он
  содержит `ИЛИ`/`ВЫБОР`/скобочную структуру, печатать форматтером; чистые простые —
  как сейчас.
- `ПО` (условия соединения) — то же.
- Поля выборки с `expression` (в т.ч. `ВЫБОР`).

## 5. Риск регрессий и стратегия

Форматтер затрагивает широкий класс уже принятых выражений. Стратегия — строго
оракул-управляемая и без регрессий:

1. Реализуем по одному классу выражений (сначала смешанные `И`/`ИЛИ`, затем `ВЫБОР`,
   затем спорные скобки), меряя `node out/cli/oracleAcceptCli.js` после каждого шага.
2. После каждого шага сверяем множество принятых: **ни один принятый запрос не должен
   стать отклонённым**. Если шаг даёт регрессии — откатываем/сужаем.
3. Курируемые фикстуры `test/fixtures/oracle/*.json` на каждый класс.

## 6. Критерии приёмки

- Растёт число принятых по оракулу за счёт `mismatch` с `ИЛИ`/`ВЫБОР`/скобками; без
  регрессий принятых.
- `formatExpression` покрыт юнит-тестами по классам (булевы, CASE, вложенность, пробелы).
- Вся `npm run test:unit` зелёная.

## 7. Вне 6.10

Подзапросы в источнике `ИЗ` и после `В` — 6.11 (форматтер выражений их только печатает
как вложенный блок, разбор источника-подзапроса — там).

## 8. Замечание о масштабе

Это самая объёмная и тонкая итерация фазы 6: точные правила отступов конструктора
нетривиальны (приоритет-зависимый отступ, специфические счётчики табов) и вычитываются
итеративно по оракулу. Реализация — строго инкрементальная, с защитой от регрессий на
каждом шаге.
