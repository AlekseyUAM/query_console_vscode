# Phase 4.4 — Виртуальные таблицы регистров бухгалтерии: дизайн

**Дата:** 2026-06-07
**Фаза:** 4.4 (см. [ROADMAP](../../ROADMAP.md))
**Статус:** утверждён

Прямое продолжение машинерии виртуальных таблиц [фазы 4.3](2026-06-03-phase4-accum-virtual-tables-design.md)
(регистры накопления) на **регистры бухгалтерии**. Те же швы: парсер → `properties` →
`yamlLoader` эмитит виртуальные таблицы → `VirtualParams` → диспетчеризация генератора →
окно «Параметры виртуальной таблицы». Окно «Произвольное выражение», каталог функций и
хелпер период-полей `accumPeriodFields` переиспользуются без изменений.

Все правила выведены из реальных эталонов конструктора 1С в `tmp/meta1c/`
(`РегистрБухгалтерии<Имя><ВидВТ><Периодичность>.txt`) для двух регистров:
`РегистрБухгалтерии1` (корреспондентский) и `РегистрБухгалтерии2` (некорреспондентский).
Фикстуры `src/cf/` соответствуют этим эталонам — TDD ведётся напрямую против них.

---

## 1. Цель

Дать конструктору работу с **виртуальными таблицами регистров бухгалтерии**:

- `Остатки`, `Обороты`, `ОстаткиИОбороты`, `ДвиженияССубконто` — у любого регистра;
- `ОборотыДтКт` — дополнительно у регистра с признаком `Корреспонденция`;
- развёртку ресурсов, счетов и субконто по виду ВТ;
- зависимость состава полей `Обороты`/`ОборотыДтКт`/`ОстаткиИОбороты` от `Периодичности`
  (переиспользует `accumPeriodFields`);
- параметры ВТ в окне «Параметры виртуальной таблицы» (включая `Периодичность` и
  `МетодДополнения`);
- генерацию текста запроса с вызовом виртуальной таблицы.

Попутно **исправляется псевдоним виртуальной таблицы** на 1С-точный (имя объекта) — это
затрагивает существующие эталоны/тесты регистров сведений (4.2) и накопления (4.3).

## 2. Не входит в 4.4

- Разворот **небалансовых** измерений в `ИзмерениеДт`/`ИзмерениеКт` (в эталонах нет такого
  измерения; все измерения фикстур `Balance=true` и копируются плоско).
- Параметры-субконто в окне параметров ВТ (позиционные слоты `Субконто`/`СубконтоДт`/
  `СубконтоКт`/`КорСубконто` остаются пустыми).
- Виртуальные таблицы регистра расчёта.
- Валидация выражений и обратный разбор текста запроса (фаза 6).

## 3. Ключевые решения

| Решение | Выбор | Обоснование |
|---|---|---|
| Признак корреспонденции | `properties.correspondence: boolean` (из `Correspondence`) | Определяет состав ВТ (`ОборотыДтКт`), поля счёта (`СчетДт/СчетКт` vs `Счет`) и арность `Обороты` |
| План счетов и субконто | парсер `chartOfAccounts.ts` читает `MaxExtDimensionCount` + `ExtDimensionTypes` в `properties` | `yamlLoader` резолвит число субконто `N` и вид субконто по ссылке регистра на план счетов |
| Где рождаются ВТ | `yamlLoader.ts` (`buildAccountingRegSlices`) | Логика в ядре, webview тонкий — принцип проекта |
| Период-зависимые поля | переиспользование `accumPeriodFields(periodicity)` | Эталоны РБ совпадают с регистрами накопления (Период/Запись/Регистратор/…/Авто) |
| Развёртка ресурса/счёта/субконто | в `buildAccountingRegSlices` | Период-независимая часть `MetaTable.fields`; период-поля добавляет webview |
| Псевдоним ВТ | имя объекта (`КАК РегистрБухгалтерии1`) | Реальный эталон 1С; текущая склейка `Имя+Вид` — расхождение, исправляется глобально |
| Рендер источника | диспетчеризация по виду регистра (`РегистрБухгалтерии` vs `РегистрНакопления`) | У РБ **фиксированная арность** (хвостовые пустые позиции сохраняются), у РН — отбрасываются |
| Арность `Обороты` | 8 (corr) / 6 (non-corr) | Генератор читает `correspondence`, проброшенный на выбранную таблицу |

## 4. Эталоны: правила состава полей

`N` = `MaxExtDimensionCount` плана счетов (в фикстурах `N = 3`). `<изм>` — измерения,
скопированные плоско. `R` — каждый ресурс базы.

### 4.1 Базовая (реальная) таблица

Эталоны `РегистрБухгалтерии1.txt` / `РегистрБухгалтерии2.txt`. Порядок полей:

- **corr:** `Период, Регистратор, НомерСтроки, Активность, СчетДт, СчетКт, <изм>, <ресурсы>, <реквизиты>`
- **non-corr:** `Период, Регистратор, НомерСтроки, Активность, ВидДвижения, Счет, <изм>, <ресурсы>, <реквизиты>`

Субконто в базовой таблице **нет**.

### 4.2 Развёртка ресурса `R` по виду ВТ

| ВТ | Колонки `R` |
|---|---|
| `Остатки` | `RОстаток, RОстатокДт, RОстатокКт, RРазвернутыйОстатокДт, RРазвернутыйОстатокКт` |
| `Обороты` (corr и non-corr) | `RОборот, RОборотДт, RОборотКт` |
| `ОборотыДтКт` | `RОборот` |
| `ОстаткиИОбороты` | `RНачальныйОстаток, RНачальныйОстатокДт, RНачальныйОстатокКт, RНачальныйРазвернутыйОстатокДт, RНачальныйРазвернутыйОстатокКт, RОборот, RОборотДт, RОборотКт, RКонечныйОстаток, RКонечныйОстатокДт, RКонечныйОстатокКт, RКонечныйРазвернутыйОстатокДт, RКонечныйРазвернутыйОстатокКт` |
| `ДвиженияССубконто` | `R` (без развёртки) |

### 4.3 Блок счёта и субконто

| ВТ | Блок |
|---|---|
| `Остатки`, `ОстаткиИОбороты` | `Счет, Субконто1..N` |
| `Обороты` corr | `Счет, Субконто1..N, <изм>, КорСчет, КорСубконто1..N` |
| `Обороты` non-corr | `Счет, Субконто1..N, <изм>` |
| `ОборотыДтКт` (corr) | `СчетДт, СубконтоДт1..N, СчетКт, СубконтоКт1..N, <изм>` |
| `ДвиженияССубконто` corr | `СчетДт, (СубконтоДтi, ВидСубконтоДтi)×N, СчетКт, (СубконтоКтi, ВидСубконтоКтi)×N` |
| `ДвиженияССубконто` non-corr | `Счет, (Субконтоi, ВидСубконтоi)×N` |

### 4.4 Полный порядок полей ВТ

1. **период-поля** = `accumPeriodFields(periodicity)` (только `Обороты`/`ОборотыДтКт`/
   `ОстаткиИОбороты`; у `Остатки` периодичности нет; у `ДвиженияССубконто` —
   фиксированные `Период, Регистратор, НомерСтроки, Активность`);
2. **блок счёта/субконто** (§4.3);
3. **измерения** `<изм>` плоско (кроме `Обороты` corr, где измерения стоят **между**
   `Субконто1..N` и `КорСчет`, и `ОборотыДтКт`, где измерения после `СубконтоКт1..N`);
4. **развёрнутые ресурсы** (§4.2);
5. **реквизиты** — только в `ДвиженияССубконто`;
6. **`ВидДвижения`** — только `ДвиженияССубконто` non-corr, в самом конце.

## 5. Метаданные

### 5.1 Парсер `accountingRegister.ts`

Читать `Correspondence` и `ChartOfAccounts` из `Properties`; собрать поля базовой таблицы
в 1С-порядке (§4.1). Имена счетов и `ВидДвижения` — новые стандартные поля:

```ts
const correspondence = nodeText(childByLocalName(props, 'Correspondence')) === 'true';
const chartRef = nodeText(childByLocalName(props, 'ChartOfAccounts')); // 'ChartOfAccounts.ПланСчетов1'
// порядок: Период, Регистратор, НомерСтроки, Активность,
//   corr → СчетДт, СчетКт; non-corr → ВидДвижения, Счет;
//   затем dimensions, resources, attributes
return { version: 1, kind: 'РегистрБухгалтерии', name, fullName, uuid,
  properties: { correspondence, chartOfAccounts: chartRef }, fields };
```

Тип `Счет`/`СчетДт`/`СчетКт`/`КорСчет` — ссылка на `ПланСчетов.<имя>` (из `chartRef`).
`ВидДвижения` — `{ kind: 'unknown' }`.

### 5.2 Парсер `chartOfAccounts.ts`

Добавить чтение в `properties`:

```ts
const maxExtDimensionCount = Number(nodeText(childByLocalName(props, 'MaxExtDimensionCount')) || '0');
const extDimensionTypes = nodeText(childByLocalName(props, 'ExtDimensionTypes')); // 'ChartOfCharacteristicTypes.ВидыСубконто'
// properties: { maxExtDimensionCount, extDimensionTypes }
```

Поля плана счетов (реальная таблица) — без изменений.

### 5.3 Тип `VirtualTableInfo` (`types.ts`)

```ts
export interface VirtualTableInfo {
  slice: 'СрезПервых' | 'СрезПоследних' | 'Обороты' | 'Остатки' | 'ОстаткиИОбороты'
       | 'ОборотыДтКт' | 'ДвиженияССубконто';
  baseFullName: string;
  correspondence?: boolean; // регистр бухгалтерии: арность/состав Обороты, наличие ОборотыДтКт
}
```

### 5.4 `yamlLoader.ts` — `buildAccountingRegSlices`

Пред-скан плана счетов: из `index.objects` собрать карту
`'ПланСчетов1' → { n: maxExtDimensionCount, vidName: <имя ПВХ> }` (читая YAML планов счетов).

Для `kind === 'РегистрБухгалтерии'`:

- разрешить `N` и вид субконто по `properties.chartOfAccounts`;
- `corr = properties.correspondence`;
- измерения = поля базы `kind === 'dimension'`; ресурсы = `kind === 'resource'`;
  реквизиты = `kind === 'attribute'`;
- собрать период-независимый состав каждой ВТ (§4.2–4.4, без период-полей);
- эмитить `MetaTable` (`kind: 'РегистрБухгалтерии'`, `name: '<Имя>.<ВидВТ>'`,
  `fullName: 'РегистрБухгалтерии.<Имя>.<ВидВТ>'`, `virtual: { slice, baseFullName, correspondence }`):
  `Остатки`, `Обороты`, `ОстаткиИОбороты`, `ДвиженияССубконто` — всегда; `ОборотыДтКт` —
  если `corr`.

Хелперы развёртки: счёт+субконто, КорСчёт+КорСубконто, ресурс по виду ВТ.
Типы: `Субконто*`/`КорСубконто*` — `{}` (составной); `ВидСубконто*` — ссылка на
`ПланВидовХарактеристик.<vidName>`; `Счет*`/`КорСчет` — ссылка на `ПланСчетов.<имя>`.

## 6. Период-зависимые поля

Без нового кода: `accumPeriodFields(periodicity)` (фаза 4.3) даёт тот же набор. Применяется
к `Обороты`/`ОборотыДтКт`/`ОстаткиИОбороты`; для `Остатки` и `ДвиженияССубконто` не
вызывается (у `ДвиженияССубконто` стандартные период-поля — часть `MetaTable.fields`).

## 7. `QueryModel` (`queryModel.ts`)

Расширить `VirtualParams` обратносовместимо:

```ts
export interface VirtualParams {
  period?: string;
  startPeriod?: string;
  endPeriod?: string;
  periodicity?: string;
  fillMethod?: string;
  condition?: string;
  // регистр бухгалтерии:
  accountCondition?: string;      // УсловиеСчета
  corrAccountCondition?: string;  // УсловиеКорСчета (Обороты corr)
  accountDtCondition?: string;    // УсловиеСчетаДт (ОборотыДтКт)
  accountKtCondition?: string;    // УсловиеСчетаКт (ОборотыДтКт)
  order?: string;                 // Порядок (ДвиженияССубконто)
  top?: string;                   // Первые (ДвиженияССубконто)
  correspondence?: boolean;       // проброшен с метаданных при добавлении таблицы
}
```

`defaultTableAlias`: для виртуальной таблицы возвращать **имя объекта** (`parts[1]`), как для
обычных таблиц — убрать склейку `parts[1] + parts[2]`. Коллизии (база + ВТ того же
регистра) разрешает существующий суффикс-счётчик.

## 8. Генератор `sdblGenerator.ts`

### 8.1 Псевдонимы

Через `defaultTableAlias` (см. §7) — имя объекта для всех ВТ. Существующие эталоны/тесты
4.2/4.3 обновляются под новый псевдоним.

### 8.2 Источник-виртуальная таблица — диспетчеризация по виду регистра

Вид регистра — 1-й сегмент `fullName`. Для `РегистрНакопления`/`РегистрСведений` — как в
4.2/4.3 (хвостовые пустые позиции отбрасываются). Для **`РегистрБухгалтерии`** —
**фиксированная арность**: всегда полный список позиций; скобки только если задан хоть один
параметр (иначе вызов без скобок).

Позиционные массивы (пустые слоты `''`):

| ВТ | Позиции |
|---|---|
| `Остатки` | `[period, accountCondition, '', condition]` |
| `Обороты` corr | `[startPeriod, endPeriod, periodicity, accountCondition, '', condition, corrAccountCondition, '']` |
| `Обороты` non-corr | `[startPeriod, endPeriod, periodicity, accountCondition, '', condition]` |
| `ОборотыДтКт` | `[startPeriod, endPeriod, periodicity, accountDtCondition, '', accountKtCondition, '', condition]` |
| `ОстаткиИОбороты` | `[startPeriod, endPeriod, periodicity, fillMethod, accountCondition, '', condition]` |
| `ДвиженияССубконто` | `[startPeriod, endPeriod, condition, order, top]` |

`periodicity`/`fillMethod` вставляются как голые слова SDBL (`Авто`, `ДвиженияИГраницыПериода`).
`corr` для `Обороты` берётся из `virtual.correspondence`. Пустой слот `''` между значениями
выводится пустым между запятыми; полный список сохраняется до последней позиции (без
отбрасывания хвоста).

### 8.3 Поля

Без изменений к 4.2/4.3: обычное поле — `<alias>.<path> [КАК <alias_поля>]`; произвольное —
`<expression> КАК <alias>`.

## 9. Окно «Параметры виртуальной таблицы» (webview)

`VirtualTableParamsDialog` расширяется по виду ВТ РБ (`virtual.slice` + `correspondence`):

| Вид ВТ | Поля окна |
|---|---|
| `Остатки` | `Период`, `УсловиеСчета`, `Условие` |
| `Обороты` | `НачалоПериода`, `КонецПериода`, `Периодичность`, `УсловиеСчета`, `Условие` (+ `УсловиеКорСчета` для corr) |
| `ОборотыДтКт` | `НачалоПериода`, `КонецПериода`, `Периодичность`, `УсловиеСчетаДт`, `УсловиеСчетаКт`, `Условие` |
| `ОстаткиИОбороты` | `НачалоПериода`, `КонецПериода`, `Периодичность`, `МетодДополнения`, `УсловиеСчета`, `Условие` |
| `ДвиженияССубконто` | `НачалоПериода`, `КонецПериода`, `Условие`, `Порядок`, `Первые` |

Выпадающие списки `Периодичность`/`МетодДополнения` — `PERIODICITY_VALUES`/`FILL_METHOD_VALUES`
(уже в `accumVirtualFields.ts`). Поля-условия — текст + кнопка «…» (окно «Произвольное
выражение», источник полей — поля выбранной ВТ). Срезы РС и ВТ РН — как раньше. «ОК» →
`SET_VIRTUAL_PARAMS`.

## 10. Дерево метаданных и панель «Поля»

- Дерево: ВТ РБ — строками рядом с регистром (`РегистрБухгалтерии1.Остатки`, `…ОборотыДтКт`
  и т.д.), как срезы/ВТ в 4.2/4.3; тот же drag-payload.
- Панель «Поля»: для `Обороты`/`ОборотыДтКт`/`ОстаткиИОбороты` доступные поля =
  `accumPeriodFields(virtual.periodicity)` ++ `MetaTable.fields`; для `Остатки`/
  `ДвиженияССубконто` — `MetaTable.fields`. При смене `Периодичности` набор пересчитывается.

## 11. Состояние webview (`queryStore.ts`)

Новых экшенов не требуется: `SET_VIRTUAL_PARAMS` пишет произвольный `VirtualParams`;
`ADD_TABLE` проставляет `virtual: {}` у ВТ. Добавить проброс `correspondence` из
`MetaTable.virtual` в `SelectedTable.virtual` при добавлении ВТ РБ.
