# Спек — Фаза 6.8. Верность существующей модели против конструктора

Дата: 2026-06-11. Опирается на 6.7 (golden-оракул). Принцип: спек → план → TDD.

## 1. Цель

Свести расхождения `generateBatch(parseBatch(input)) !== query_text` для конструкций,
которые **уже представимы** текущей моделью (не требуют расширения AST). Источник
истины — `tmp/query1c/oracle/golden.jsonl`; прогресс меряется
`node out/cli/oracleAcceptCli.js`.

Базовая точка (после 6.7): принято **870**, mismatch **945**, parse-exception 161,

## 2. Правила (по убыванию измеренного импакта)

### R1. Автопсевдоним простого поля выборки  *(измерено: +231 принято)*

Конструктор всегда даёт простому полю выборки псевдоним = последний сегмент пути, если
явный не задан: `Таблица.Ссылка` → `Таблица.Ссылка КАК Ссылка`. Агрегаты без явного
псевдонима — без изменений.

Место: `sdblGenerator.buildFieldLines` — для не-агрегатного поля без `f.alias`
подставлять `КАК <последний сегмент path>`. Согласуется с `selectAliasFor`
(УПОРЯДОЧИТЬ/ИТОГИ уже так адресуют поля). Затрагивает ~16 ручных тестов
`sdblGenerator.test.ts` — обновить ожидания. `sdblGolden` (buildSelectAllModel задаёт
alias явно) и `sdblParser` не затрагиваются.

### R2. ПРАВОЕ СОЕДИНЕНИЕ сохраняется

Сейчас `JoinKind` = `inner|left|full`, правое нормализуется перестановкой источников в
ЛЕВОЕ (`renderFrom`, `swap = !leftAll && rightAll`). Конструктор **сохраняет** ПРАВОЕ.
Нужно: добавить `'right'` в `JoinKind`, хранить признак правого в `Join`, генератор
рендерит `ПРАВОЕ СОЕДИНЕНИЕ` без перестановки источников; парсер маппит
`ПРАВОЕ СОЕДИНЕНИЕ` в right. Закрывает часть not-idempotent и mismatch по соединениям.

### R3. Квалификация поля в УПОРЯДОЧИТЬ ПО

`УПОРЯДОЧИТЬ ПО ДатаВерсии` → конструктор `УПОРЯДОЧИТЬ ПО <ТаблицаПоля>.ДатаВерсии`,
когда поле порядка — реальное поле таблицы, а не псевдоним выборки. Сейчас
`renderOrder`/`selectAliasFor` выводят псевдоним. Правило конструктора: если поле
порядка совпадает с полем источника (не вычисляемый псевдоним выборки) — выводить
`<псевдонимТаблицы>.<path>`. Требует в парсере резолва поля порядка к таблице.

### R4. Пробел перед скобкой у `В ИЕРАРХИИ`/функций

`В ИЕРАРХИИ (…)` → `В ИЕРАРХИИ(…)` (без пробела). Аналогично прочим конструкциям, где
конструктор не ставит пробел перед `(`. Место: рендер условий / нормализация выражений.

### R5. Скобки вокруг простых условий ГДЕ

Случаи `(X = ЛОЖЬ` vs `X = ЛОЖЬ`: конструктор снимает/добавляет внешние скобки у
условий по своим правилам. Уточняется по примерам из mismatch после R1–R4.
