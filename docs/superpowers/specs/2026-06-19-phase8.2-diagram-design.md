# Фаза 8.2 — кнопка «Диаграмма»: mermaid-визуализация текущего запроса

← [Дорожная карта](../../ROADMAP.md) · [Фаза 8](../../PHASE_8.md)

Статус: спек. Опирается на двунаправленное ядро Фаз 6–7 и модель пакета
(`BatchDocument` → `QueryDocument` → `QueryModel`). Новый код стоит **в стороне** от
канонического конвейера генерации/разбора: золотой оракул (`oracleGolden.test.ts`) и
регрессия корпуса 1976 запросов (`corpusRegression.test.ts`) не затрагиваются.

## Цель

Рядом с кнопкой «Обновить кэш» в шапке конструктора добавить кнопку-дропдаун
**«Диаграмма ▾»** с четырьмя пунктами. Выбор пункта строит mermaid-текст текущего
запроса и открывает его во встроенном Markdown-preview VS Code. За «красоту» отвечает
стороннее расширение (`bierner.markdown-mermaid`), которое дорисовывает mermaid-блоки в
превью; если его нет — превью всё равно открывается (показывает сырой mermaid) и
предлагается установка.

## Решения (зафиксированы при брейншторминге)

| Вопрос | Решение |
|--------|---------|
| Что показывать | Все 4 типа диаграмм через выпадающее меню |
| Как рендерить | Делегировать стороннему расширению (`bierner.markdown-mermaid`) через встроенный Markdown-preview |
| Расширение не установлено | Проверять и предлагать установку; превью всё равно открывать |
| Подача | Один пункт меню → превью одной выбранной диаграммы |

## Четыре типа диаграмм

`DiagramKind = 'packageFlow' | 'joins' | 'unions' | 'fields'`.

| Тип | Область | Что показывает | Граф |
|-----|---------|----------------|------|
| `packageFlow` | весь пакет (`BatchDocument`) | узел на каждый запрос пакета; рёбра — поток ВТ: `ПОМЕСТИТЬ X` → последующий запрос, чья таблица ссылается на `X` | `graph TD` |
| `joins` | активный запрос | таблицы (`ИЗ`) как узлы, `СОЕДИНЕНИЯ` как рёбра с подписью типа (ЛЕВОЕ/ВНУТРЕННЕЕ/ПОЛНОЕ) и условием | `graph LR` |
| `unions` | активный запрос | участники `ОБЪЕДИНИТЬ [ВСЕ]` как параллельные ветки, сходящиеся в один результат | `graph TD` |
| `fields` | активный запрос | дерево «запрос → выбранные поля / группировки / условия / порядок / итоги» | `graph TD` |

«Активный запрос» — запрос пакета, который сейчас открыт в конструкторе (индекс берётся
из состояния webview). `packageFlow` всегда охватывает весь пакет.

## Архитектура (3 слоя)

### 1. Ядро (pure-TS, TDD) — `src/core/query/mermaidDiagram.ts` (новый)

Чистая функция модель → mermaid-текст. Не знает про VS Code/webview/файлы.

```ts
export type DiagramKind = 'packageFlow' | 'joins' | 'unions' | 'fields';
export function buildDiagram(
  batch: BatchDocument,
  kind: DiagramKind,
  activeIndex: number,
): string;
```

Внутри — четыре генератора (по типу) + диспетчер. Правила:

- **Идентификаторы узлов** синтетические (`n0`, `n1`, …); подписи (имена таблиц, ВТ,
  поля, условия) — экранируются: спецсимволы mermaid (`"`, `[`, `]`, `{`, `}`, `|`,
  `<`, `>`, переводы строк) заменяются на безопасные, подпись оборачивается в кавычки.
  Кириллица в подписях допустима как есть.
- **Устойчивость**: `buildDiagram` **никогда не бросает** (как `commentBinder`). На
  пустом/некорректном вводе или неизвестном `kind` возвращает валидный mermaid с
  единственным плейсхолдер-узлом «Пустой запрос», чтобы превью не было пустым.
- `packageFlow`: связь «производитель → потребитель ВТ» определяется по `queryType`
  (`createTemp`/`appendTemp` + `tempTableName` = производитель) и по `tables[*].fullName`
  последующих запросов, ссылающихся на это имя ВТ. `dropTemp` (`УНИЧТОЖИТЬ`) — отдельный
  узел/пометка, без исходящих рёбер.
- `joins`: ребро на каждый `Join`; подпись типа из `JoinKind`
  (`inner`→ВНУТРЕННЕЕ, `left`→ЛЕВОЕ, `full`→ПОЛНОЕ) + `condition` (если задано).
  Узлы — `tables` активного запроса по `id`; таблицы без соединений показываются
  изолированными узлами.
- `unions`: ветка на каждый `UnionMember`; подпись ребра — `ОБЪЕДИНИТЬ` (по
  `member.distinct === true`) или `ОБЪЕДИНИТЬ ВСЕ` (`distinct === false`). Один общий
  узел-результат.
- `fields`: корень-запрос → группы-узлы по секциям (Поля, Группировка, Условия,
  Порядок, Итоги), под каждой — листья. Пустые секции опускаются.

### 2. Контракт — `src/shared/messages.ts`

Новое сообщение webview → host (mermaid генерится в webview — ядро туда импортируется,
как `generateBatch`; host остаётся «тонким»):

```ts
| { type: 'showDiagram'; kind: DiagramKind; mermaid: string; title: string }
```

`HostMsg` не меняется. Протокол вставки/обновления кэша/загрузки не затрагивается.

### 3. Расширение — `src/extension/diagramPreview.ts` (новый) + обработчик в `panel.ts`

`openDiagram(context, title, mermaid)`:

1. Оборачивает mermaid в markdown: `# ${title}\n\n` + блок ```` ```mermaid … ``` ````.
2. Пишет во временный файл в `context.globalStorageUri` (один файл на `kind`,
   перезаписывается — рабочая копия и репозиторий не засоряются). Каталог при
   необходимости создаётся.
3. Проверяет `vscode.extensions.getExtension('bierner.markdown-mermaid')`; если не
   найдено — `vscode.window.showInformationMessage('Для красивого отображения диаграммы
   установите расширение Markdown Preview Mermaid Support', 'Установить')`; по кнопке
   «Установить» — `vscode.commands.executeCommand('workbench.extensions.installExtension',
   'bierner.markdown-mermaid')`. Превью открывается в любом случае.
4. Открывает встроенное превью: `vscode.commands.executeCommand('markdown.showPreview',
   uri)`.

Обработчик в `panel.ts` (`else if (msg.type === 'showDiagram')`) вызывает `openDiagram`.

### UI — `src/webview/App.tsx`

В `cacheToolbar` после кнопки «Обновить кэш» (до галочки «Сохранять комментарии», у
которой `marginLeft:auto`) — кнопка-дропдаун **«Диаграмма ▾»**: свой маленький компонент
с раскрывающимся списком 4 пунктов (не нативный `<select>`, чтобы совпадать со стилем
кнопок VS Code; стиль `BTN`). Пункты: «Поток пакета», «Схема соединений», «Объединения»,
«Поля/структура». По клику пункта:

```ts
const mermaid = buildDiagram(assembled, kind, activeIndex);
postToHost({ type: 'showDiagram', kind, mermaid, title });
```

`assembled` — уже считаемый `assembleBatch(state)`; `activeIndex` — индекс активного
запроса пакета из состояния.

## Краевые случаи / обработка ошибок

- Пустой запрос / нет таблиц → плейсхолдер-узел, превью не пустое.
- Спецсимволы в идентификаторах 1С → экранирование подписей (см. правила ядра).
- Расширение не установлено → превью открывается (сырой mermaid) + предложение установки.
- Неизвестный `kind` → плейсхолдер (defensive).

## Тестирование

- **Unit (Node, TDD)** для `mermaidDiagram.ts` — golden-вывод каждого из 4 типов на
  репрезентативных моделях: пакет с ВТ (`packageFlow`), запрос с соединениями (`joins`),
  объединение (`unions`), запрос с полями/группировкой/условиями (`fields`). Плюс тесты:
  экранирование спецсимволов в подписях; устойчивость к пустому вводу и неизвестному
  `kind` (не бросает, валидный mermaid).
- Слой host/webview (запись файла, prompt установки, открытие превью) — минимальная
  логика по существующим паттернам, без vscode-моков.
- `oracleGolden` / `corpusRegression` — без изменений (новый код вне конвейера).

## Чего НЕ делаем (YAGNI)

- Не рендерим mermaid сами (выбрана делегация стороннему расширению).
- Не добавляем расширение в `extensionDependencies`/рекомендации — только runtime-prompt.
- Не открываем все 4 диаграммы одновременно — одна выбранная.
- Не настраиваем темы/зум mermaid вручную — это делает стороннее расширение/превью.
