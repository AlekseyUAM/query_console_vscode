## Цель

Добавить вкладку «Связи»: пользователь задаёт соединения между выбранными таблицами.
Секция `ИЗ` рендерится как дерево соединений
(`<Таблица1> КАК A <ВИД> СОЕДИНЕНИЕ <Таблица2> КАК B ПО <условие>`) вместо простого
списка таблиц через запятую. Вкладка видна только при наличии **более одной** таблицы.

## Модель (`src/core/query/queryModel.ts`)

```ts
/** Вид соединения после нормализации (правое сводится к левому перестановкой). */
export type JoinKind = 'inner' | 'left' | 'full';

export interface Join {
  /** Таблица 1 (слева в UI). */
  leftTableId: string;
  /** Таблица 2 (справа в UI). */
  rightTableId: string;
  /** «Все» у таблицы 1 — все элементы таблицы 1 сохраняются. */
  leftAll: boolean;
  /** «Все» у таблицы 2 — все элементы таблицы 2 сохраняются. */
  rightAll: boolean;
  /** «П.» — произвольное условие связи. */
  custom: boolean;
  /** Простое условие: поле таблицы 1. */
  leftPath?: string;
  /** Оператор сравнения, по умолчанию '='. */
  operator?: ConditionOperator;
  /** Простое условие: поле таблицы 2. */
  rightPath?: string;
  /** Произвольное условие — полный текст выражения. */
  expression?: string;
}

export interface QueryModel {
  // …существующее…
  joins?: Join[];
}
```

`joins` опционально — при отсутствии/пустом массиве генерация `ИЗ` байт-в-байт как
сейчас (список через запятую).

## Вид соединения из галочек «Все»

| leftAll | rightAll | Вид          | SDBL                                   |
|---------|----------|--------------|----------------------------------------|
| нет     | нет      | внутреннее   | `ВНУТРЕННЕЕ СОЕДИНЕНИЕ`                 |
| да      | нет      | левое        | `ЛЕВОЕ СОЕДИНЕНИЕ`                      |
| нет     | да       | правое→левое | `ЛЕВОЕ СОЕДИНЕНИЕ` (таблицы переставлены) |
| да      | да       | полное       | `ПОЛНОЕ СОЕДИНЕНИЕ`                     |

**Нормализация правого соединения.** При `(!leftAll && rightAll)` в выводе таблицы
меняются местами: источником-«затравкой» становится `rightTableId`, присоединяемой —
`leftTableId`, вид — `ЛЕВОЕ`. Текст условия `ПО` при этом **не меняется** (он построен
по псевдонимам и от порядка таблиц не зависит — см. эталон `…_103429.png`:
`ИЗ Справочник.ВариантыОтветовАнкет … ЛЕВОЕ СОЕДИНЕНИЕ Справочник.Валюты … ПО Валюты.Ссылка = ВариантыОтветовАнкет.ИмяПредопределенныхДанных`).

## Условие связи

- **Простое** (`custom=false`): `<aliasLeft>.<leftPath> <operator> <aliasRight>.<rightPath>`
  (по умолчанию оператор `=`). Псевдонимы — из общей карты `resolveAliases`.
- **Произвольное** (`custom=true`): `(<expression>)` — текст оборачивается в скобки
  (эталон `…_103509.png`: `ПО (Валюты.Ссылка = &Труляля)`). Пустое выражение → связь
  пропускается.

## Генератор SDBL (`src/core/query/sdblGenerator.ts`)

Новый хелпер `renderFrom(model, aliases): string[]` — строки после `ИЗ`.
`buildQueryBlock` заменяет текущий `tableLines` на `renderFrom(...)`.

1. **Нет активных связей** (`!model.joins?.length`) → текущее поведение: каждая таблица
   `\t<renderSource> КАК <alias>` через запятую (последняя без запятой).
2. **Есть связи** — строим левоассоциативную цепочку:
   - Нормализуем каждую связь (перестановка при правом соединении).
   - Затравка цепочки — `leftTableId` первой связи:
     ```
     	<источник> КАК <aliasLeft>
     ```
   - Для каждой связи добавляем (с отступом в два таба):
     ```
     		<ВИД> СОЕДИНЕНИЕ <источник> КАК <aliasRight>
     			ПО <условие>
     ```
   - Таблицы, не участвующие ни в одной связи, дописываются после цепочки отдельными
     источниками через запятую (`\t<источник> КАК <alias>`). Последняя строка цепочки
     получает запятую, если за ней следуют такие таблицы.

   Формат — **детерминированный канонический**, валидность проверяется
   `validate_query`. Точное воспроизведение пробелов 1С-конструктора не требуется;
   приоритет — валидность + структура (отступы как в эталонах ТЗ: 1 таб у затравки,
   2 таба у `<ВИД> СОЕДИНЕНИЕ`, 3 таба у `ПО`).

   Линейная цепочка покрывает все эталоны ТЗ (2 таблицы) и типовые случаи. Произвольные
   топологии (>2 таблиц, ветвление, дизъюнктные группы связей) — best-effort линейной
   цепочкой; результат остаётся валидным SDBL.

## Webview

- `TabsBar` — принять список видимых вкладок (`tabs: string[]`) вместо константы;
  `App` вычисляет видимость: «Связи» в списке только при
  `selectedTables.length > 1`, сразу после «Таблицы и поля». При скрытии активной
  вкладки «Связи» (удалили таблицу) `App` переключает `activeTab` на «Таблицы и поля».
- `ConnectionsTab` (новый): таблица «Связи» с колонками `№`, `Таблица 1`, `Все`,
  `Таблица 2`, `Все`, `П.`, `Условие связи`. Тулбар с кнопкой «+» (добавить связь) и
  «✕» (удалить). Новая связь по умолчанию: первые две таблицы выборки,
  `leftAll/rightAll/custom=false`, `operator='='`, поля пустые.
  - `Таблица 1`/`Таблица 2` — выпадающие списки по выбранным таблицам (значение —
    `tableId`, подпись — псевдоним).
  - `Все` — два чекбокса.
  - `П.` — чекбокс произвольного условия.
  - `Условие связи`: при `custom=false` — три контрола (выпадающий список полей
    таблицы 1, выпадающий оператор, выпадающий список полей таблицы 2); при `custom=true` —
    текст выражения + кнопка «…», открывающая `ExpressionBuilder` с полями всех таблиц.
- Состояние `joins` в `queryStore`; экшены: `ADD_JOIN`, `REMOVE_JOIN`,
  `SET_JOIN_TABLE` (side: 'left'|'right'), `SET_JOIN_ALL` (side), `SET_JOIN_CUSTOM`,
  `SET_JOIN_FIELD` (side), `SET_JOIN_OPERATOR`, `SET_JOIN_EXPRESSION`.
- Каскад: `REMOVE_TABLE` удаляет связи, ссылающиеся на удалённую таблицу (по
  `leftTableId`/`rightTableId`).
- `joins` добавляется в `SavedQuery`, `snapshotActive`, `restoreSaved`,
  `buildModelFromFlat`, `initialState`.

## Не входит

`ВЫБОР … КОГДА` в условии связи, несколько условий в одной связи через И/ИЛИ (только одно
простое или одно произвольное), валидация полей связи, обратный разбор.
