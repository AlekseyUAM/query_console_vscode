## Цель

Настройка построителя отчёта: дополнительные **доступные** поля для вывода/отбора/
упорядочивания/группировки. В тексте запроса они оборачиваются в фигурные скобки —
динамические секции `{ВЫБРАТЬ …}`, `{ГДЕ …}`, `{УПОРЯДОЧИТЬ ПО …}`, `{ИТОГИ ПО …}`.
Вкладка содержит под-вкладки. В этой итерации — четыре секции данных (Поля, Условия,
Порядок, Итоги).

## Модель (`src/core/query/queryModel.ts`)

```ts
/** Строка построителя: ссылка на поле + «использовать дочерние» (.*) + псевдоним. */
export interface BuilderField {
  /** Готовый текст ссылки: псевдоним выборки (Поля/Порядок/Итоги) или Алиас.Поле (Условия, «Все поля»). */
  ref: string;
  /** «Использовать дочерние» → суффикс `.*` (доступно только для ссылочных полей). */
  child: boolean;
  /** Необязательный псевдоним → ` КАК <alias>`. */
  alias?: string;
}

export interface ReportBuilder {
  fields: BuilderField[];     // {ВЫБРАТЬ …}
  conditions: BuilderField[]; // {ГДЕ …}
  order: BuilderField[];      // {УПОРЯДОЧИТЬ ПО …}
  totals: BuilderField[];     // {ИТОГИ ПО …}
}

export interface QueryModel {
  // …существующее…
  builder?: ReportBuilder;
}
```

Секция построителя **активна**, когда соответствующий список непуст. Пустой/отсутствующий
`builder` → генерация байт-в-байт как сейчас.

## Ссылка на поле (`ref`)

`ref` вычисляется в UI при добавлении строки и хранится готовым текстом — генератор его
не интерпретирует:

- **Поля / Порядок / Итоги** из поля выборки → псевдоним выборки (`selectAliasFor`):
  `Ресурс1Оборот`, `Измерение1`, `Ссылка`.
- **Условия** из поля выборки → квалифицированно `Алиас.Путь`:
  `РегистрНакопленияОборОбороты.Измерение1`, `Валюты.Ссылка`.
- Любая под-вкладка из узла «Все поля» → `Алиас.Поле` (`Валюты.Ссылка`).

Рендер строки: `ref` + (`.*` при `child`) + (` КАК <alias>` при `alias`).

## Генератор SDBL (`src/core/query/sdblGenerator.ts`)

Хелпер `builderBlock(keyword, fields): string[]` — `[] ` при пустом списке, иначе:

```
{ВЫБРАТЬ
	<строка0>,
	<строкаN>}
```

Открывающая строка `{<keyword>`; каждая строка `\t<ref>[.*][ КАК alias]`, запятая после
всех, кроме последней; закрывающая `}` приклеена к последней строке (без переноса).

**Встраивание** (внутри `buildQueryBlock`, отступ/одиночные переносы — как у соседних
секций; эталоны ТЗ):

- `{ВЫБРАТЬ …}` — сразу после строк выборки (`...lines`), до `ПОМЕСТИТЬ`/`ИЗ`.
- `{ГДЕ …}` — после строк `ГДЕ` (реальных условий), до группировки.
- `{УПОРЯДОЧИТЬ ПО …}` — после группировки.
- `{ИТОГИ ПО …}` — последним (после `{УПОРЯДОЧИТЬ ПО}`), до `ДЛЯ ИЗМЕНЕНИЯ`.

Эталоны ТЗ (каждый блок по отдельности):

```
	Валюты.Ссылка КАК Ссылка
{ВЫБРАТЬ
	Ресурс1Оборот КАК труляля,
	Валюты.Ссылка.*}
ИЗ
```
```
	Справочник.Валюты КАК Валюты
{ГДЕ
	Валюты.Ссылка.*,
	РегистрНакопленияОборОбороты.Измерение1}
```
```
	Справочник.Валюты КАК Валюты
{УПОРЯДОЧИТЬ ПО
	Ссылка.*,
	Измерение1 КАК Измерение1ааа}
```
```
	Справочник.Валюты КАК Валюты
{ИТОГИ ПО
	Измерение1,
	Ресурс1Оборот,
	Ссылка.* КАК а11}
```

Блоки построителя относятся к телу запроса → рендерятся **внутри** `buildQueryBlock`
(одиночный перенос, без пустой строки — в отличие от реальных `УПОРЯДОЧИТЬ ПО`/`ИТОГИ`
5.6/5.7). В объединении (`generateDocument`, >1 участник) блоки участника берутся из его
же `model.builder` (тот же `buildQueryBlock`).

> Замечание по `assertValidSdbl`: фигурные секции построителя — расширение синтаксиса
> SDBL, валидатор tree-sitter может их не принимать. Для построительных тестов сверяем
> текст посимвольно с эталонами ТЗ **без** `assertValidSdbl` (как для прочих
> макро-конструкций). Базовые тесты валидности — на запросах без `builder`.

## Webview

- `TabsBar`: добавить «Построитель» перед «Пакет запросов» (после «Итоги»).
- **`BuilderTab` (новый)** — вторичная полоса под-вкладок: `Поля`, `Условия`, `Порядок`,
  `Итоги`. Каждая под-вкладка — двухпанельный экран:
  - слева дерево «Поля»: текущие поля выборки (метка по правилу `ref` под-вкладки) + узел
    «Все поля» с раскрытием таблиц и ссылочных полей (переиспользовать существующий
    источник полей/раскрытие ссылок, как в `OrderTab`/`TotalsTab`);
  - справа список (колонки `Поле` | `И.` | `Псевдоним`): кнопки `>`/`>>`/`<`/`<<`,
    стрелки ↑/↓; чекбокс `И.` («Использовать дочерние», доступен только для ссылочных
    полей) → `child`; правка `Псевдоним` → `alias`.
  - перетаскивание/`>` из дерева → добавить `BuilderField` с вычисленным `ref` в список
    активной под-вкладки.
- Экшены `queryStore`: `ADD_BUILDER_FIELD`, `REMOVE_BUILDER_FIELD`,
  `SET_BUILDER_FIELD_CHILD`, `SET_BUILDER_FIELD_ALIAS` — все с дискриминантом
  `section: 'fields'|'conditions'|'order'|'totals'` и индексом строки. Каскада на удаление
  таблиц/полей нет (построитель ссылается на готовый текст `ref`, независимо от выборки —
  как в эталоне, где есть `Валюты.Ссылка.*` без явного поля выборки).
- `builder` добавляется в `SavedQuery`, `snapshotActive`, `restoreSaved`,
  `buildModelFromFlat`, `initialState`
  (`builder: { fields: [], conditions: [], order: [], totals: [] }`). Так построитель
  переживает переключение участников объединения (5.4) и запросов пакета (5.8).

## Не входит

- Под-вкладка **Таблицы** построителя: необязательные таблицы (флаг «Обязательная» +
  «Номер группы» → группы `{…}` в `ИЗ`) и параметры виртуальных таблиц построителя
  (`{(&Параметр)}`). Нет эталонного текста для группировки необязательных таблиц; высокая
  связность с машинерией ВТ — отдельная будущая под-фаза 5.10.
- Совместная работа реальной секции и одноимённой секции построителя в одном запросе
  (эталоны показывают их по отдельности) — порядок зафиксирован выше, но не покрывается
  отдельными golden-кейсами.
