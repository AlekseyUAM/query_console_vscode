# Phase 4.2 — Виртуальные таблицы регистров сведений + конструктор произвольных выражений: дизайн

**Дата:** 2026-06-03
**Фаза:** 4.2 (см. [ROADMAP](../../ROADMAP.md))
**Статус:** утверждён

Эталоны поведения — скриншоты классического конструктора 1С в `tmp/meta/РегистрСведений`.
Перечень функций языка запросов — [`tmp/1c-query-language.md`](../../../tmp/1c-query-language.md).

---

## 1. Цель

Дать конструктору запросов работу с **виртуальными таблицами периодических регистров
сведений** (`СрезПервых`, `СрезПоследних`) и поддерживающий их UI:

- срезы в дереве метаданных «База данных»;
- окно «Параметры виртуальной таблицы» (для срезов — `Период` + `Условие`);
- окно «Произвольное выражение» (дерево полей + дерево функций языка запросов +
  текстовый результат, drag&drop), переиспользуемое для параметра `Условие` и для
  добавления произвольного поля в блок «Поля»;
- генерацию текста запроса с вызовом виртуальной таблицы и произвольными полями.

Ядро (`QueryModel`, модель метаданных, генератор) остаётся стабильным — расширяется
обратносовместимо, существующее поведение не ломается.

## 2. Не входит в 4.2

- Прочие виртуальные таблицы регистров: `Остатки`, `Обороты`, `ОстаткиИОбороты`,
  движения регистра бухгалтерии с субконто, виртуальные таблицы регистра расчёта.
- Валидация текста выражения (tree-sitter в рантайме — фаза 6).
- Обратный разбор текста запроса (фаза 6).

## 3. Ключевые решения

| Решение | Выбор | Обоснование |
|---|---|---|
| Где рождаются срезы | В `yamlLoader.ts` (слой `core`) | Логика в ядре, webview остаётся тонким — принцип проекта |
| Маркер виртуальной таблицы | `MetaTable.virtual?` | Нужен панели «Таблицы» (активация кнопки) и генератору |
| Параметры среза в модели | `SelectedTable.virtual?` | Наличие = срез с параметрами; параметры позиционные |
| Произвольное поле в модели | `SelectedField.expression?` | Минимум правок в reducer/`FieldsPanel` vs отдельный массив |
| Каталог функций | pure-data модуль в `core` | Статичные данные, тестируются в Node, бандлятся в webview |
| Контракт сообщений | без изменений | Генерация и диалоги — состояние webview; данные уже загружены |

## 4. Метаданные: периодичность → виртуальные таблицы

### 4.1 Парсер `informationRegister.ts`

Сейчас `periodicity` вычисляется локально и теряется. Сохранить её:

```ts
return {
  version: 1,
  kind: 'РегистрСведений',
  name,
  fullName,
  uuid,
  properties: { periodicity: periodicity || 'Nonperiodical' },
  fields,
};
```

`ParsedObject.properties` уже существует (`Record<string, unknown>`), новых типов не нужно.

### 4.2 Тип `MetaTable` (`src/core/metadata/types.ts`)

Добавить опциональный маркер:

```ts
export interface VirtualTableInfo {
  slice: 'СрезПервых' | 'СрезПоследних';
  baseFullName: string; // 'РегистрСведений.ЗамерыОбластиСтатистики'
}

export interface MetaTable {
  kind: TableKind;
  name: string;
  fullName: string;
  fields: MetaField[];
  tabularSections?: MetaTable[];
  virtual?: VirtualTableInfo; // только у таблиц-срезов
}
```

### 4.3 `yamlLoader.ts`

При сборке `MetaTable` для `РегистрСведений`: если
`properties.periodicity` задана и `!== 'Nonperiodical'`, дополнительно эмитить две
таблицы-среза. Для каждого среза:

- `kind: 'РегистрСведений'` (попадает в ту же группу дерева);
- `name: '<Имя>.СрезПервых'` / `'<Имя>.СрезПоследних'` (метка строки в дереве);
- `fullName: 'РегистрСведений.<Имя>.СрезПервых'` / `'…СрезПоследних'`;
- `virtual: { slice, baseFullName }`;
- состав полей среза зависит от режима записи регистра (по эталону конструктора 1С):
  - **подчинённый регистратору** (в базе есть `Регистратор`): `Период`, `Регистратор`,
    `НомерСтроки`, `Активность` + измерения/ресурсы/реквизиты; **без** `ПериодОкончание`;
  - **независимый** (в базе нет `Регистратора`): `Период`, `ПериодОкончание` +
    измерения/ресурсы/реквизиты.
  Измерения/ресурсы/реквизиты — все поля базы, кроме служебных
  `НомерСтроки`/`Активность`/`Период`/`Регистратор`/`ПериодОкончание`.
  Синтетические `Период`/`ПериодОкончание` — тип `Дата`.

Непериодический регистр срезов не получает.

## 5. Дерево метаданных (webview)

`DbTreePanel` группирует строки по `kind`. Срезы с `kind: 'РегистрСведений'` попадают в
группу «Регистры сведений» отдельными строками рядом с базовым регистром:

```
▼ Регистры сведений
    ЗамерыОбластиСтатистики
    ЗамерыОбластиСтатистики.СрезПервых
    ЗамерыОбластиСтатистики.СрезПоследних
```

Срез перетаскивается в блок «Таблицы» как обычная таблица (тот же drag-payload
`{ kind: 'table', tableFullName }`). Специальной отрисовки в дереве не требуется —
маркер `virtual` дереву не нужен.

## 6. `QueryModel` (`src/core/query/queryModel.ts`)

```ts
export interface VirtualParams {
  period?: string;    // напр. '&Период'
  condition?: string; // напр. 'ОбластьСтатистики = &Область'
}

export interface SelectedTable {
  id: string;
  fullName: string;
  alias?: string;
  virtual?: VirtualParams; // присутствует у выбранной таблицы-среза
}

export interface SelectedField {
  tableId: string;
  path: string;
  alias?: string;
  expression?: string; // произвольное выражение; если задано — path игнорируется
}
```

`virtual` на `SelectedTable` ставится при добавлении таблицы-среза в выборку (webview
знает это по `MetaTable.virtual`), даже если параметры ещё не заданы (пустой объект).

## 7. Генератор `sdblGenerator.ts`

### 7.1 Псевдонимы

`resolveAliases` для 3-сегментного `fullName` (`РегистрСведений.X.СрезПоследних`) даёт
базовый псевдоним = склейка сегментов 2 и 3 без точки: `XСрезПоследних`. Для
2-сегментных — как сейчас (сегмент 2). Коллизии разрешаются суффиксом-счётчиком как
сейчас.

### 7.2 Источник-срез

Если у `SelectedTable` есть `virtual`:

- нет ни `period`, ни `condition` → `<fullName> КАК <alias>` (без скобок);
- иначе → `<fullName>(<period>, <condition>) КАК <alias>`, где пустой `period`
  оставляет позицию пустой: только условие → `<fullName>(, <condition>) КАК <alias>`.

Примеры (по скриншотам):

```sql
РегистрСведений.ЗамерыОбластиСтатистики.СрезПоследних КАК ЗамерыОбластиСтатистикиСрезПоследних
РегистрСведений.ЗамерыОбластиСтатистики.СрезПоследних(&Период, ОбластьСтатистики = &Область) КАК ЗамерыОбластиСтатистикиСрезПоследних
```

### 7.3 Поля

- обычное поле: как сейчас (`<alias>.<path> [КАК <alias_поля>]`);
- произвольное поле (`expression` задано): `<expression> КАК <alias>`. Если `alias`
  пуст — автоген `Поле1`, `Поле2`, … (1С требует псевдоним для выражения). Текст
  выражения пишется дословно (поля в нём уже алиас-квалифицированы конструктором
  выражений).

## 8. Окно «Параметры виртуальной таблицы» (webview)

- В тулбар панели «Таблицы» добавляется кнопка «Параметры виртуальной таблицы»,
  активная, когда выделенная (`focusedSelectedTableId`) таблица — срез (по
  `MetaTable.virtual`).
- Компонент `VirtualTableParamsDialog` (модалка):
  - поле **Период** — текстовый ввод, принимает выражение/параметр (`&Период`);
  - поле **Условие** — текстовый ввод + кнопка «…», открывающая «Произвольное
    выражение» (источник полей — поля выбранного среза);
  - «ОК» → reducer-экшен `SET_VIRTUAL_PARAMS { tableId, params }`; «Отмена» закрывает
    без изменений.

## 9. Окно «Произвольное выражение»

### 9.1 Каталог функций — `src/core/query/functionCatalog.ts` (core, pure-data)

Дерево заготовок, состав строго по скриншотам:

- **Функции**
  - Функции работы со строками: `СТРОКА`, `ДЛИНАСТРОКИ`, `ЛЕВ`, `ПРАВ`, `ВРЕГ`, `НРЕГ`,
    `ПОДСТРОКА`, `СОКРЛ`, `СОКРП`, `СОКРЛП`, `СТРНАЙТИ`, `СТРЗАМЕНИТЬ`
  - Функции работы с датами: `ГОД`, `КВАРТАЛ`, `МЕСЯЦ`, `ДЕНЬГОДА`, `ДЕНЬ`, `НЕДЕЛЯ`,
    `ДЕНЬНЕДЕЛИ`, `ЧАС`, `МИНУТА`, `СЕКУНДА`, `НАЧАЛОПЕРИОДА`, `КОНЕЦПЕРИОДА`,
    `ДОБАВИТЬКДАТЕ`, `РАЗНОСТЬДАТ`
  - Функции работы с числами: `ACOS`, `ASIN`, `ATAN`, `COS`, `TAN`, `SIN`, `EXP`,
    `LOG`, `LOG10`, `POW`, `SQRT`, `ОКР`, `ЦЕЛ`
  - Агрегатные функции: `СУММА`, `МИНИМУМ`, `МАКСИМУМ`, `СРЕДНЕЕ`, `КОЛИЧЕСТВО`,
    `КОЛИЧЕСТВО(РАЗЛИЧНЫЕ)`
  - Прочие функции: `ЕСТЬNULL`, `ПРЕДСТАВЛЕНИЕ`, `ПРЕДСТАВЛЕНИЕССЫЛКИ`, `ТИПЗНАЧЕНИЯ`,
    `АВТОНОМЕРЗАПИСИ`, `РАЗМЕРХРАНИМЫХДАННЫХ`, `УНИКАЛЬНЫЙИДЕНТИФИКАТОР`
- **Операторы**
  - Арифметические: `+`, `-`, `*`, `/`
  - Логические: `=`, `<>`, `<`, `<=`, `>`, `>=`, `И`, `ИЛИ`, `НЕ`, `ПОДОБНО`, `В`,
    `В ИЕРАРХИИ`, `МЕЖДУ`, `ЕСТЬ NULL`, `ССЫЛКА`
  - Прочие: `ВЫБОР`, `ВЫРАЗИТЬ`
- **Прочее**: `ДАТАВРЕМЯ`, `ЗНАЧЕНИЕ`, `ТИП`, `СГРУППИРОВАНОПО`

Каждый лист несёт `label` и `template` (текст, вставляемый в результат). Шаблоны
функций — с плейсхолдерами, напр. `ДОБАВИТЬКДАТЕ(<Дата>, <Тип>, <Количество>)`;
операторы — сам символ/ключевое слово (`И`, `=`, `МЕЖДУ`).

Тип:

```ts
export interface FunctionLeaf { label: string; template: string; }
export interface FunctionGroup { label: string; children: (FunctionGroup | FunctionLeaf)[]; }
export const FUNCTION_CATALOG: FunctionGroup; // корень 'Функции языка запросов'
```

### 9.2 Компонент `ExpressionBuilder` (webview, модалка)

Props: список доступных полей (алиас-квалифицированные строки + раскрытие ссылочных
полей), `FUNCTION_CATALOG`, начальный текст. Три области:

- **Поле** (слева) — дерево полей источника; узел «Все поля» раскрывает поля
  ссылочных типов (переиспользует механизм `expandRef`/`expandedRefs`);
- **Функции языка запросов** (справа) — дерево из `FUNCTION_CATALOG`;
- **Результат** (снизу) — `textarea`.

Вставка элемента в результат — double-click и drag&drop: имя поля или `template`
функции вставляется в позицию курсора. «ОК» возвращает текст, «Отмена» — отбрасывает.

**Квалификация имён полей** зависит от точки вызова (по скриншотам):

- для параметра `Условие` поля **неквалифицированные** (`ОбластьСтатистики`) — условие
  пишется внутри скобок виртуальной таблицы, над её собственными колонками;
- для произвольного поля в блоке «Поля» поля **алиас-квалифицированные**
  (`ЗамерыОбластиСтатистикиСрезПоследних.Период`) — выражение попадает в `ВЫБРАТЬ`.

### 9.3 Точки вызова

- кнопка «…» поля `Условие` в «Параметры виртуальной таблицы» → результат пишется в
  `condition`;
- кнопка «+» в тулбаре панели «Поля» → по «ОК» добавляется произвольное поле
  (reducer-экшен `ADD_EXPRESSION_FIELD { tableId, expression }`); источник полей —
  выбранная/сфокусированная таблица выборки.

## 10. Состояние webview (`queryStore.ts`)

Новые экшены reducer:

- `SET_VIRTUAL_PARAMS { tableId; params: VirtualParams }` — записывает `virtual` в
  соответствующий `SelectedTable`;
- `ADD_EXPRESSION_FIELD { tableId; expression; alias? }` — добавляет `SelectedField`
  с `expression`.

`ADD_TABLE` проставляет `virtual: {}` (пустые параметры), если у `MetaTable` есть
маркер `virtual`.

## 11. Тесты (TDD)

### 11.1 core

- `yamlLoader`: периодический РС → база + 2 среза с корректными `fullName`/`virtual`/
  составом полей — независимый (`Период`, `ПериодОкончание`, измерения, ресурсы; без
  `НомерСтроки`/`Активность`/`Регистратор`) и подчинённый регистратору (`Период`,
  `Регистратор`, `НомерСтроки`, `Активность`, измерения, ресурсы; без `ПериодОкончание`);
  непериодический → срезов нет.
- `functionCatalog`: наличие всех групп и листьев, корректные `template`
  (точечно: `ДОБАВИТЬКДАТЕ`, `СУММА`, `И`).
- `sdblGenerator`: срез без параметров (без скобок); срез с обоими параметрами; срез
  только с условием (`(, Условие)`); вывод псевдонима `XСрезПоследних`; произвольное
  поле (`<expr> КАК <alias>`, автоген псевдонима).

### 11.2 webview

В стиле существующих тестов: активация кнопки «Параметры виртуальной таблицы» только
для среза; `VirtualTableParamsDialog` пишет параметры по «ОК»; `ExpressionBuilder`
вставляет поле/шаблон и возвращает текст по «ОК»; «+» в «Поля» добавляет произвольное
поле.
