# Спек — Фаза 6. Обратный разбор текста запроса (двунаправленность)

Дата: 2026-06-10. Источник задач: `tmp/draft.md` (подзадачи 6.1–6.6).
Принцип итерации: спек → план → реализация по TDD. Ядро — pure-TS.

## 1. Цель

Добавить **обратный разбор**: из текста запроса SDBL восстановить визуальную модель
конструктора (`QueryModel` / `QueryDocument` / `BatchDocument`). Это инверсия
`sdblGenerator.generate`/`generateDocument`/`generateBatch`. Двунаправленность даёт:
открыть существующий текст запроса из `.bsl`-файла в конструкторе, отредактировать,
сохранить обратно в то же место (подзадача 6.6).

## 2. Ключевое архитектурное решение: pure-TS парсер, а не tree-sitter в рантайме

ROADMAP первоначально предполагал tree-sitter-bsl (WASM) как рантайм-парсер. В текущем
окружении это **нереализуемо и нежелательно**:

- собрать `tree-sitter-sdbl.wasm` нельзя — CLI несовместим по GLIBC, нет emscripten/docker;
- опубликованный npm-пакет `tree-sitter-bsl@0.1.7` **не содержит** `.wasm`;
- `web-tree-sitter` в проекте — 0.22, а грамматика сгенерирована CLI 0.25 → несовместимость ABI.

Решение: **обратный парсер пишется на pure-TS** (рекурсивный спуск), симметрично
рукописному `sdblGenerator`. Это согласуется с философией проекта («ядро — pure-TS,
тестируется в Node»). Грамматика `tmp/tree-sitter-bsl/grammars/sdbl/grammar.js` и
`node-types.json` используются как **референс** синтаксиса (перечень конструкций,
ключевые слова, приоритеты). `tmp/vscode-1c-platform-tools` — справочно.

tree-sitter остаётся **необязательным тест-оракулом** (`test/helpers/assertValidSdbl.ts`
уже пропускает проверку при отсутствии `.wasm`). MCP `1c-md validate_query` —
дополнительный оракул валидности при сборе корпуса и отладке.

## 3. Контракт парсера

Файлы: `src/core/query/sdblLexer.ts`, `src/core/query/sdblParser.ts`.

```ts
// Лексер: текст → поток токенов (с учётом регистронезависимости ключевых слов,
// кириллических идентификаторов, строк "…", чисел, дат '…', параметров &Имя,
// комментариев //…, разделителя пакета ;).
export function tokenize(text: string): Token[];

// Парсер верхнего уровня. Возвращает батч (пакет) запросов; каждый элемент пакета —
// документ объединения; каждый участник — QueryModel.
export function parseBatch(text: string): BatchDocument;
// Удобные обёртки:
export function parseDocument(text: string): QueryDocument; // один элемент пакета
export function parseQuery(text: string): QueryModel;       // один участник, без ОБЪЕДИНИТЬ
```

### 3.1 Инвариант round-trip (критерий приёмки)

Для **канонически отформатированного** текста (как его печатает генератор):
`generate(parseQuery(text)) === text`. Для произвольного реального текста —
`generate(parseQuery(text))` обязан быть **семантически эквивалентен** (та же модель
после повторного разбора; идемпотентность: `parse(generate(parse(t)))` ≡ `parse(t)`).
Это и есть смысл подзадачи 6.3 «при нажатии Ок сохраняется такой же текст запроса»:
канонизированный, но эквивалентный.

### 3.2 Восстановление `tableId`

Модель адресует поля по `tableId`. Метаданные парсеру **не нужны**: при разборе `ИЗ`
строится карта `alias → tableId` (синтетический `tableId`, напр. `t0,t1,…`), затем
префиксы `Алиас.path` в полях/условиях/порядке/итогах резолвятся в `tableId`+остаток
пути. Префикс, не совпавший ни с одним алиасом, или сложное выражение → трактуется как
произвольное (`expression` у поля / `custom:true` у условия). Имена таблиц (`fullName`)
берутся из источника `ИЗ`; виртуальные таблицы — из `Имя.Срез(параметры)`.

## 4. Покрытие конструкций (что парсер обязан распознавать)

Полный перечень — по эталонам генератора (фазы 0–5.10):

| Секция | Конструкции |
|---|---|
| ВЫБРАТЬ | модификаторы РАЗРЕШЕННЫЕ/РАЗЛИЧНЫЕ/ПЕРВЫЕ N; поля `Алиас.Путь`; псевдонимы `КАК`; агрегаты СУММА/КОЛИЧЕСТВО/КОЛИЧЕСТВО РАЗЛИЧНЫЕ/МАКСИМУМ/МИНИМУМ/СРЕДНЕЕ; произвольные выражения (`expression`); вложенные табличные части `Алиас.ТЧ.(…)` |
| ПОМЕСТИТЬ/ДОБАВИТЬ/УНИЧТОЖИТЬ | `queryType` + `tempTableName` |
| ИЗ | источники, виртуальные таблицы с параметрами (РН Остатки/Обороты/ОстаткиИОбороты, РС срезы, РБ Остатки/Обороты/ОборотыДтКт/ОстаткиИОбороты/ДвиженияССубконто); `КАК`; соединения ВНУТРЕННЕЕ/ЛЕВОЕ/ПРАВОЕ/ПОЛНОЕ … ПО …; перечисление через запятую |
| ГДЕ | простые `Алиас.Путь <оп> &Параметр` (операторы =,<>,>,>=,<,<=,В,МЕЖДУ,ПОДОБНО); произвольные (`custom`), в т.ч. цепочки `И` |
| СГРУППИРОВАТЬ ПО | поля; ГРУППИРУЮЩИМ НАБОРАМ |
| УПОРЯДОЧИТЬ ПО | поля + УБЫВ; АВТОУПОРЯДОЧИВАНИЕ |
| ИТОГИ | агрегаты; ПО + ОБЩИЕ; ИЕРАРХИЯ/ТОЛЬКО ИЕРАРХИЯ; псевдонимы групп |
| ИНДЕКСИРОВАТЬ ПО | одиночный индекс и ПО НАБОРАМ (УНИКАЛЬНО) |
| ДЛЯ ИЗМЕНЕНИЯ | `lockForUpdate` |
| Построитель | блоки `{ВЫБРАТЬ…}`,`{ГДЕ…}`,`{УПОРЯДОЧИТЬ ПО…}`,`{ИТОГИ ПО…}`, суффикс `.*`, `КАК` |
| ОБЪЕДИНИТЬ [ВСЕ] | `QueryDocument.members` (distinct=ОБЪЕДИНИТЬ без ВСЕ) |
| Пакет `;`+`/`×80 | `BatchDocument.members` |

Адресация полей в ПОРЯДКЕ/ИТОГАХ/ИНДЕКСЕ/построителе идёт по псевдониму выборки —
парсер сопоставляет псевдоним обратно с `(tableId,path)` через список полей выборки;
не нашёл — оставляет как есть/`custom`.

## 5. Подзадачи

- **6.1 Сбор корпуса.** CLI `src/cli/extractQueries.ts`: рекурсивно `src/cf/**/*.bsl`;
  находит строковые литералы-запросы (первый значимый токен — ВЫБРАТЬ/ВЫРАЗИТЬ-нет:
  только запросы, начинающиеся ВЫБРАТЬ/УНИЧТОЖИТЬ), убирает префикс продолжения `|`
  (инверсия `formatAsBslString`), валидирует через MCP `validate_query`; успешные →
  `tmp/query1c/<путь-с-разделителем->_<N>.txt`. Имя по образцу из draft.md.
- **6.2 Парсер.** Реализация §3–4 по TDD, послойно (SELECT/FROM → WHERE/JOIN/GROUP →
  ORDER/TOTALS/INDEX/temp/builder/lock → UNION/batch).
- **6.3 Приёмка.** Скрипт `src/cli/acceptQueries.ts`: для каждого файла `tmp/query1c/*.txt`
  `generate(parseQuery(text))`; round-trip-эквивалентность (повторный разбор совпадает).
  Проблемные → копия в `tmp/query1c/errors/`.
- **6.4 Починка.** Разбор причин в `errors/`, правки парсера, повторный прогон 6.3 до
  минимизации `errors/`. Остаточные принципиально-неподдерживаемые конструкции
  документируются в `tmp/query1c/errors/README.md`.
- **6.5 Тесты.** Ключевые тексты → `test/fixtures/queries/*.sdbl`; unit-тесты
  `test/unit/sdblParser.test.ts` со 100% покрытием `sdblParser.ts`/`sdblLexer.ts`
  (`vitest run --coverage`).
- **6.6 Интеграция.** Команда «1С: Конструктор запроса из позиции» по ПКМ в `.bsl`:
  - определить строковый литерал-запрос под курсором (диапазон) → распарсить → открыть
    панель с восстановленной моделью;
  - не внутри запроса → диалог «Не найден текст запроса. Создать новый запрос?» Да/Нет;
    Да → пустой конструктор, Ок вставит в позицию курсора;
  - Ок → текст заменяет исходный диапазон литерала (через `formatAsBslString`).
  Контракт: `HostMsg` пополняется `{type:'loadModel'; doc: BatchDocument}`; webview-стор
  получает действие восстановления из модели (инверсия `buildModelFromFlat`).

## 6. Нефункциональные требования

- Ядро (`sdblLexer`,`sdblParser`) — без зависимостей от vscode/React/fs.
- Зелёные `npm run test:unit` и `npm run build` после каждой задачи.
- Каждая задача — отдельный коммит в `master` (локально).
- Без регрессий golden-сьюта генератора (фазы 0–5.10).

## 7. Вне области

- Полная поддержка произвольных SDBL-выражений с восстановлением структуры (ВЫБОР/ВЫРАЗИТЬ
  внутри простых условий) — они допускаются как `custom`/`expression`, без структурного
  разбора. Структурный разбор подвыражений — за рамками фазы 6.
- Сохранение оригинального форматирования/комментариев исходного текста (round-trip
  канонизирует).
