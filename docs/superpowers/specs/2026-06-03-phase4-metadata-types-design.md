# Phase 4 — Расширение типов метаданных: дизайн

**Дата:** 2026-06-03  
**Фаза:** 4 (см. [ROADMAP](../../ROADMAP.md))  
**Статус:** утверждён

---

## 1. Цель

Расширить конвейер парсера метаданных и загрузчик YAML, чтобы конструктор запросов
поддерживал все 17 типов объектов метаданных 1С, которые образуют запрашиваемые таблицы:

```
КритерииОтбора, ПланыОбмена, Константы, Справочники, Документы,
Последовательности, ЖурналыДокументов, Перечисления,
ПланыВидовХарактеристик, ПланыСчетов, ПланыВидовРасчета,
РегистрыРасчета, БизнесПроцессы, Задачи,
РегистрыСведений, РегистрыНакопления, РегистрыБухгалтерии
```

Справочники, Документы, Константы и Перечисления уже поддержаны в парсере;
Константы и Перечисления добавляются в загрузчик MetaModel в этой фазе.

Виртуальные таблицы регистров (Остатки, Обороты, Срезы и т.д.) — отдельная задача,
в эту фазу не входят.

---

## 2. Ключевые решения

| Решение | Выбор | Обоснование |
|---|---|---|
| Роль поля регистра | Хранить в `category`: `'dimension' \| 'resource'` | Нужно для будущих виртуальных таблиц; дешевле хранить сейчас |
| Структура кода | Один модуль на тип | Консистентно с текущим паттерном (`catalog.ts`, `document.ts`) |
| Стандартные поля регистров | Условно по свойствам XML | Следует паттерну Catalog (Код только если codeLength > 0 и т.д.) |

## 7. Тесты

### 7.1 Парсер — по одному тесту на новый модуль

Каждый тест использует реальный XML из `src/cf` (путь от корня проекта).

Для catalog-like:
- name, fullName, kind
- набор стандартных полей (категория `standard`)
- наличие ТЧ и полей ТЧ

Для register-like:
- name, fullName, kind
- условные стандартные поля (Период, Регистратор — проверить и наличие и отсутствие)
- поля из ChildObjects с правильными category: `'dimension'` / `'resource'` / `'attribute'`

Для simple:
- name, fullName, kind
- набор полей

### 7.2 `attribute.ts` — расширение parseChildObjects

Тест что `<Dimension>` → `category: 'dimension'`, `<Resource>` → `category: 'resource'`.

### 7.3 `yamlLoader.ts` — дополнительные тесты

- Загрузка объекта каждого нового типа из синтетического YAML
- Поле с `category: 'dimension'` → `MetaField.kind: 'dimension'`
- Константа с `types` → MetaTable с одним полем
- Перечисление → MetaTable с полями Ссылка + Порядок
