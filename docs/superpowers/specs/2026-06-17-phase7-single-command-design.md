# Фаза 7. Единая команда «1С: Конструктор запроса» — спек

← [PHASE_7](../../PHASE_7.md) · [Дорожная карта](../../ROADMAP.md)

Дата: 2026-06-17.

## 1. Проблема

Сейчас в меню `.bsl` две команды:

- `1c.queryConstructor` — «1С: Конструктор запроса» — открывает конструктор, но
  **не** разбирает запрос под курсором (только запоминает позицию для вставки).
- `1c.queryConstructorFromCursor` — «1С: Конструктор запроса (из позиции)» — содержит
  всю парсящую логику (`findQueryAt` → `createPanel(..., hit.text)` → `loadModel`), но
  как фича до пользователя не доведена и дублирует основную.

Две кнопки путают пользователя; «(из позиции)» лишняя.

## 2. Целевое поведение

Остаётся **одна** команда `1c.queryConstructor` (`1С: Конструктор запроса`). По ПКМ в
`.bsl`:

1. ищет строковый литерал-запрос под курсором (`findQueryAt`);
2. **найден** — молча разбирает (передаёт `hit.text` как `initialQueryText` и
   `queryRange`/`wrapAsBslString` в `createPanel`), конструктор открывается заполненным;
   при сохранении текст возвращается на место литерала;
3. **не найден** — модальный вопрос **«Не найден текст запроса. Создать новый
   запрос?»** (`Да`/`Нет`); только при `Да` открывается пустой конструктор с
   `queryRange = [offset, offset]`, `wrapAsBslString: true`.

Команда `1c.queryConstructorFromCursor` и её пункт меню **удаляются** (`package.json` —
`commands[]` и `menus.editor/context[]`; `src/extension/extension.ts` — регистрация и
обработчик).

Если активного редактора нет — поведение прежней «из позиции»: предупреждение
«Откройте .bsl файл» и выход.

## 3. Тестируемый шов

Обработчик команды завязан на vscode API (не юнит-тестируется — мока нет). Чистую
логику решения выносим в pure-TS функцию рядом с `findQueryAt`:

```ts
// src/extension/queryConstructorPlan.ts
export type OpenPlan =
  | { kind: 'open'; queryText: string; queryRange: { start: number; end: number } }
  | { kind: 'prompt'; offset: number }; // спросить, потом открыть пустой [offset, offset]

export function planQueryConstructor(source: string, offset: number): OpenPlan;
```

- `findQueryAt` нашёл хит → `{ kind: 'open', queryText: hit.text, queryRange: {start,end} }`.
- не нашёл → `{ kind: 'prompt', offset }`.

`extension.ts` берёт план, и для `prompt` показывает модал; при `Да` зовёт `createPanel`
с пустым `queryRange`. Вся «развилка найден/не найден» покрывается юнит-тестами без
vscode.

## 4. Вне области

Парсер (`parseBatch`), генератор, `createPanel`, формат `SavedEditorState`, корпусный
гейт — не трогаем. Изменение чисто UX/команды; `npm run test:unit` остаётся зелёным.

## 5. Приёмка (`tmp/1.bsl` из PHASE_7)

- ПКМ внутри литерала (строки 1–7) → конструктор открыт заполненным (Таблицы
  `Справочник.Валюты`; Поля `Ссылка`, `Наименование`; Условие `Валюты.Код = &Код`).
