# Фаза 8.2. Исследование семантической валидации запроса через MCP `1c-md.validate_query`

дизайн: [`2026-06-23-phase8.2-validation-research-design.md`](superpowers/specs/2026-06-23-phase8.2-validation-research-design.md)

Дата: 2026-06-23. Конфигурация для проверок — живая база `smallb` (MCP `1c-md`).

## 0. Зачем

Сегодня критерий «открывается ли запрос конструктором» — чисто синтаксический
(`validateBatch.ts → tryParseBatch → parseBatch`: не бросил исключение → открываем).
Парсер не знает метаданных, поэтому **запрос на несуществующую таблицу открывается**.
Эталон из требований — не должен открываться, но открывается:

```
ВЫБРАТЬ
	Валюты.Ссылка КАК Ссылка,
	Валюты.Наименование КАК Наименование
ИЗ
	Справочник.Валюты1 КАК Валюты
		ЛЕВОЕ СОЕДИНЕНИЕ Справочник.БанковскиеСчета КАК БанковскиеСчета
		ПО Валюты.ОсновнаяВалюта = БанковскиеСчета.Ссылка
```

`Справочник.Валюты1` не существует (есть `Справочник.Валюты`).

Исследование характеризует инструмент `validate_query` на **178 проверках** (6 категорий,
параллельные субагенты), чтобы понять, годится ли он «привратником» открытия и где его
границы. **«Открывается»** в отчёте == `{valid:true}`; **«не открывается»** == `{valid:false}`.

### Эталонный пример — прямая проверка

| Текст | valid | Сообщение |
|-------|-------|-----------|
| `…ИЗ Справочник.Валюты1 КАК Валюты…` (как в требовании) | ❌ false | `{(5, 2)}: Таблица не найдена "Справочник.Валюты1"` + маркер `<<?>>` |
| тот же запрос, но `Справочник.Валюты` | ✅ true | Синтаксис запроса корректен |

→ инструмент решает задачу: эталонный «плохой» текст **не открывается**, исправленный — открывается.

## 1. Главный вывод

`validate_query` — это **полноценный парсер платформы 1С + сверка с метаданными базы**,
а не просто синтаксический контроль (несмотря на формулировку в его описании). При ошибке
возвращает позицию `{(строка, столбец)}` и строку-контекст с маркером `<<?>>` перед
проблемным токеном; при успехе — нормализованный `query_text` (готовый канонизатор).

### Что проверяется (→ «не открывается» при нарушении)

- **Существование таблицы** любого типа метаданных → «Таблица не найдена».
- **Существование поля/реквизита/ТЧ** → «Поле не найдено»; несуществующая ТЧ → «Таблица не найдена».
- **Навигация через точку** — только по ссылочным реквизитам; по примитиву (Булево, Перечисление как конечное `.Представление`) — «Поле не найдено».
- **Соответствие префикса типа** фактическому объекту (`Документ.X` для справочника `X` → отказ).
- **Число колонок в ОБЪЕДИНЕНИИ** → «Разное количество полей в объединяемых запросах».
- **Согласованность группировки** — поле вне `СГРУППИРОВАТЬ`/агрегата → «Поле не входит в группу».
- **Значения `ЗНАЧЕНИЕ(Перечисление.X.Y)`** → несуществующее `Y` → «Неверные параметры».
- **Применимость виртуальной таблицы к типу регистра** (Срез у накопления, Остатки у чисто оборотного, Обороты у РС → «Таблица не найдена») и **состав параметров ВТ** (лишний параметр, недопустимая периодичность → «Неверные параметры»).
- **Поля виртуальных таблиц** по фактической структуре (`КоличествоОстаток`, не `Количество`).
- **Колонки временной таблицы**, если ВТ объявлена через `ПОМЕСТИТЬ` ранее в пакете (обращение к невыбранной колонке → «Поле не найдено»).
- **Дубль псевдонима** в списке выборки → «Повторяющийся псевдоним».
- Чистый синтаксис: скобки, запятые, незакрытая кавычка, опечатки ключевых слов и т.п.

### Что НЕ проверяется (→ «открывается», хотя семантически сомнительно)

- **Существование временной таблицы по «голому» имени** (без точки): `ИЗ ДругаяВТ КАК Т`
  трактуется как CTE/подзапрос-источник, существование и поля не сверяются. Проверка
  таблицы метаданных включается только при наличии точки (`Тип.Имя`).
- **Тип значений** параметров `&П` и параметров виртуальных таблиц (число вместо даты — ок).
- **Логика отбора по ресурсу** среза РС (`Цена > 100` в `СрезПоследних` принимается).

### Что НЕ поддерживается синтаксисом этого парсера

- **Скалярный подзапрос `(ВЫБРАТЬ …)` в списке полей** → «Синтаксическая ошибка ВЫБРАТЬ».

### Нюансы нормализации (на validity не влияют)

- Регистронезависимость имён и ключевых слов; поле без префикса при одной таблице авто-дополняется.
- Английский синтаксис `SELECT…AS…FROM` и английские префиксы `Catalog.`/`Document.` принимаются и переводятся в русские.
- **Конфигураторная разметка `{…}`** (`{(&Параметр)}`, `{ГДЕ …}`, `{ВЫБРАТЬ …}`, измерения `{(Поле)}`) **принимается как есть и нормализуется** — удалять её перед валидацией НЕ нужно.
- Пустой ввод, только пробелы, только `//`-комментарий — невалидны (нужен `ВЫБРАТЬ`); ровно один хвостовой `;` допустим, несколько подряд или ведущий — нет.

## 8. Рекомендация для реализации (отдельной подфазой)

Гейтить открытие конструктора и проверку при «ОК» **двухступенчато**:

1. `tryParseBatch` (как сейчас) — синтаксис, быстро, офлайн.
2. при доступном MCP `1c-md` — `validate_query`; `valid:false` → **не открывать**, показать
   `message` (там уже есть позиция `{(строка,столбец)}` и `<<?>>`). При недоступном MCP —
   деградация к прежнему поведению (только синтаксис), чтобы не блокировать офлайн.

Границы, которые остаются на синтаксисе/пользователе (валидатор их пропускает):
существование ВТ по голому имени между пакетами, типы значений `&П` и параметров ВТ,
логика отбора по ресурсу среза. Разметку `{…}` перед отправкой **резать НЕ нужно** —
инструмент её понимает; достаточно снять ведущие `|`.

Реализация двухступенчатого гейта — за рамками этого исследования (только спецификация
[§5 дизайна](superpowers/specs/2026-06-23-phase8.2-validation-research-design.md) и данный отчёт).
