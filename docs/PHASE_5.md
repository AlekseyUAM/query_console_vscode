# Фаза 5. Вкладки конструктора

← [Дорожная карта](ROADMAP.md)

✅ Готово.

Поверх стабильного ядра `QueryModel` и контракта сообщений — **по одной фиче на
вкладку**. Каждая вкладка расширяет `QueryModel` своей секцией, генератор SDBL
дорисовывает соответствующую часть текста в фиксированном порядке языка запросов:

```
ВЫБРАТЬ [РАЗРЕШЕННЫЕ] [РАЗЛИЧНЫЕ] [ПЕРВЫЕ n]
  <поля выборки>            ← Таблицы и поля (5.0), Группировка (5.1)
[ПОМЕСТИТЬ | ДОБАВИТЬ <ВремТаб>]  ← Дополнительно (5.3)
ИЗ <источники> [<СОЕДИНЕНИЕ> … ПО …]  ← Связи (5.5)
[ГДЕ <условия>]              ← Условия (5.2)
[СГРУППИРОВАТЬ ПО …]         ← Группировка (5.1)
[ДЛЯ ИЗМЕНЕНИЯ <таблицы>]    ← Дополнительно (5.3)
[ОБЪЕДИНИТЬ [ВСЕ] <след. запрос>]  ← Объединения/Псевдонимы (5.4)
[УПОРЯДОЧИТЬ ПО …] [АВТОУПОРЯДОЧИВАНИЕ]  ← Порядок (5.6)
[ИТОГИ … ПО …]              ← Итоги (5.7)
{ВЫБРАТЬ …} {ГДЕ …} {УПОРЯДОЧИТЬ ПО …} {ИТОГИ ПО …}  ← Построитель (5.9)
[ИНДЕКСИРОВАТЬ ПО [НАБОРАМ] …]  ← Индекс (5.10, при ПОМЕСТИТЬ)
… ; //// … ; УНИЧТОЖИТЬ …    ← Пакет запросов (5.8)
```

Вкладки конструктора 1С и статус: **Таблицы и поля** (готова, фазы 0–4),
Группировка (5.1), Условия (5.2), Дополнительно (5.3), Объединения/Псевдонимы (5.4),
Связи (5.5), Порядок (5.6), Итоги (5.7), Пакет запросов (5.8), Построитель (5.9),
Индекс (5.10). Технически вкладки реализуются как переключаемые панели в `TabsBar`/`App`,
общий `QueryModel` живёт в `queryStore`.

## 5.1. Вкладка «Группировка»

Секция `СГРУППИРОВАТЬ ПО`. Поля делятся на **поля группировки** и **суммируемые поля**
(с агрегатной функцией). В тексте суммируемые поля оборачиваются функцией
(`СУММА(…)`, `КОЛИЧЕСТВО(РАЗЛИЧНЫЕ …)` и т.д.), поля группировки идут как есть и
перечисляются в `СГРУППИРОВАТЬ ПО`. Функции: для числовых — Сумма, Количество
различных, Количество, Максимум, Минимум, Среднее; для нечисловых — без Сумма/Среднее.
Галочка «Использовать несколько группировок» превращает список в дерево наборов →
`СГРУППИРОВАТЬ ПО ГРУППИРУЮЩИМ НАБОРАМ ((…), (…))`. ТЗ: `tmp/группировка.md`.

- Спек: [`specs/2026-06-07-phase5.1-grouping-design.md`](superpowers/specs/2026-06-07-phase5.1-grouping-design.md)
- План: [`plans/2026-06-07-phase5.1-grouping.md`](superpowers/plans/2026-06-07-phase5.1-grouping.md)

## 5.2. Вкладка «Условия»

Секция `ГДЕ`. Список условий (Номер, П. — произвольное, Условие). Простое условие
строится из поля + оператора + параметра (`Таблица.Поле = &Поле`); признак «П.»
переключает строку в произвольное выражение (то же окно «Произвольное выражение», что
и в полях). Несколько условий объединяются через `И`. ТЗ: `tmp/условия.md`.

- Спек: [`specs/2026-06-07-phase5.2-conditions-design.md`](superpowers/specs/2026-06-07-phase5.2-conditions-design.md)
- План: [`plans/2026-06-07-phase5.2-conditions.md`](superpowers/plans/2026-06-07-phase5.2-conditions.md)

## 5.3. Вкладка «Дополнительно»

Префикс выборки и хвост запроса: **Выборка записей** (Первые n, Без повторяющихся →
`РАЗЛИЧНЫЕ`, Разрешенные → `РАЗРЕШЕННЫЕ`); **Тип запроса** (Выборка данных |
Создание ВТ → `ПОМЕСТИТЬ`, Добавление → `ДОБАВИТЬ`, Уничтожение → `УНИЧТОЖИТЬ`, с
именем временной таблицы); галочка **Блокировать данные** → `ДЛЯ ИЗМЕНЕНИЯ` со списком
таблиц для изменения. ТЗ: `tmp/дополнительно.md`.

Условная закладка **Индекс** (по §35.8 появляется при создании ВТ на «Дополнительно») —
настройка `ИНДЕКСИРОВАТЬ ПО` / `ИНДЕКСИРОВАТЬ ПО НАБОРАМ` с колонкой «Уникальность» —
вынесена в отдельную итерацию 5.10 (см. ниже).

- План: [`plans/2026-06-07-phase5.3-additional.md`](superpowers/plans/2026-06-07-phase5.3-additional.md)

## 5.4. Вкладка «Объединения/Псевдонимы»

Несколько подзапросов, объединяемых через `ОБЪЕДИНИТЬ [ВСЕ]`. Документ запроса
становится списком подзапросов (`QueryDocument`), каждый — самостоятельный `QueryModel`
со своими таблицами/полями/группировкой/условиями. Список запросов (Имя, Без
дупликатов), боковые вкладки переключения активного подзапроса, таблица сопоставления
полей по псевдониму (строки — псевдонимы, колонки — запросы; несопоставленное поле →
`NULL`). ТЗ: `tmp/объединения.md`.

- Спек: [`specs/2026-06-07-phase5.4-unions-design.md`](superpowers/specs/2026-06-07-phase5.4-unions-design.md)
- План: [`plans/2026-06-07-phase5.4-unions.md`](superpowers/plans/2026-06-07-phase5.4-unions.md)

## 5.5. Вкладка «Связи»

Секция `ИЗ` с соединениями. Вкладка видна при наличии более одной таблицы. Список связей
(Таблица 1, «Все», Таблица 2, «Все», «П.», Условие связи): галочки «Все» задают вид
соединения (нет/нет → `ВНУТРЕННЕЕ`, да/нет → `ЛЕВОЕ`, нет/да → `ПРАВОЕ` → сводится к
`ЛЕВОЕ` перестановкой таблиц, да/да → `ПОЛНОЕ`). Простое условие — поле1/оператор/поле2
(`ПО A.Поле = B.Поле`), «П.» переключает на произвольное выражение в скобках
(`ПО (…)`). `ИЗ` рендерится левоассоциативной цепочкой соединений. ТЗ: `tmp/связи.md`.

- Спек: [`specs/2026-06-08-phase5.5-joins-design.md`](superpowers/specs/2026-06-08-phase5.5-joins-design.md)
- План: [`plans/2026-06-08-phase5.5-joins.md`](superpowers/plans/2026-06-08-phase5.5-joins.md)

## 5.6. Вкладка «Порядок»

Секция `УПОРЯДОЧИТЬ ПО`. Выбранные поля переносятся в список сортировки с направлением
(Возрастание → как есть, Убывание → `УБЫВ`); поле адресуется по псевдониму выборки.
Галочка «Автоупорядочивание» → `АВТОУПОРЯДОЧИВАНИЕ`. Секция дописывается после блока
запроса с пустой строкой-разделителем. ТЗ: `tmp/порядок.md`.

- Спек: [`specs/2026-06-08-phase5.6-order-design.md`](superpowers/specs/2026-06-08-phase5.6-order-design.md)
- План: [`plans/2026-06-08-phase5.6-order.md`](superpowers/plans/2026-06-08-phase5.6-order.md)

## 5.7. Вкладка «Итоги»

Секция `ИТОГИ … ПО …`. Группировочные поля (с типом итогов — Элементы / Элементы и
иерархия → `ИЕРАРХИЯ` / Только иерархия → `ТОЛЬКО ИЕРАРХИЯ` — и псевдонимом) и итоговые
поля (числовые, выражение-агрегат по умолчанию `СУММА(…)`). Галочка «Общие итоги» →
`ОБЩИЕ` первым в списке ПО. Два формата: `ИТОГИ <агрегаты> ПО <группировки>` и
`ИТОГИ ПО <группировки>`. ТЗ: `tmp/итоги.md`.

- Спек: [`specs/2026-06-08-phase5.7-totals-design.md`](superpowers/specs/2026-06-08-phase5.7-totals-design.md)

## 5.8. Вкладка «Пакет запросов»

Пакетный запрос — последовательность независимых запросов, разделённых `;` и строкой из
80 `/`. Каждый запрос пакета сам по себе — полноценный документ конструктора (со своими
таблицами/полями/связями/группировкой и **объединениями** 5.4). Двухуровневая модель:
пакет (внешний слой) над документом объединения. Боковые вкладки переключают активный
запрос пакета; вкладка «Пакет запросов» показывает их список (тулбар ⊕/✕/↑/↓, имя
производное: имя ВТ для `ПОМЕСТИТЬ`/`ДОБАВИТЬ`, `- <ВТ>` для `УНИЧТОЖИТЬ`, иначе
«Запрос пакета N»). Запрос-`УНИЧТОЖИТЬ` показывает только вкладки «Дополнительно» и
«Пакет запросов». Генератор `generateBatch` склеивает запросы пакета (один запрос пакета
= прежний вывод байт-в-байт). ТЗ: `tmp/пакет запросов.md`.

- Спек: [`specs/2026-06-08-phase5.8-query-package-design.md`](superpowers/specs/2026-06-08-phase5.8-query-package-design.md)
- План: [`plans/2026-06-08-phase5.8-query-package.md`](superpowers/plans/2026-06-08-phase5.8-query-package.md)

## 5.9. Вкладка «Построитель»

Настройка построителя отчёта: дополнительные **доступные** поля, оборачиваемые в
динамические секции построителя `{ВЫБРАТЬ …}`, `{ГДЕ …}`, `{УПОРЯДОЧИТЬ ПО …}`,
`{ИТОГИ ПО …}`. Под-вкладки Поля/Условия/Порядок/Итоги; в каждой — дерево «Поля»
(поля выборки + «Все поля») и список (колонки `Поле`, `И.` — использовать дочерние `.*`,
`Псевдоним`). Адресация поля: по псевдониму выборки (Поля/Порядок/Итоги) либо
`Алиас.Поле` (Условия, «Все поля»). За рамками 5.9 (→ 5.11): под-вкладка «Таблицы»
построителя — необязательные таблицы (`Обязательная`/`Номер группы`) и параметры ВТ
построителя `{(&Параметр)}` (нет эталонного текста группировки необязательных таблиц).
ТЗ: `tmp/построитель.md`.

- Спек: [`specs/2026-06-08-phase5.9-report-builder-design.md`](superpowers/specs/2026-06-08-phase5.9-report-builder-design.md)
- План: [`plans/2026-06-08-phase5.9-report-builder.md`](superpowers/plans/2026-06-08-phase5.9-report-builder.md)

## 5.10. Вкладка «Индекс»

Условная вкладка: появляется, когда на «Дополнительно» выбран **Тип запроса =
Создание ВТ** (`ПОМЕСТИТЬ`). Описывает индексы временной таблицы → предложение
`ИНДЕКСИРОВАТЬ ПО` (один индекс) либо `ИНДЕКСИРОВАТЬ ПО НАБОРАМ` (несколько индексов, с
ключевым словом `УНИКАЛЬНО` у уникальных наборов). Секция дописывается в самом конце
запроса, после блока `ИЗ`, с пустой строкой-разделителем. Три списка: «Индексы» (имя
`Индекс N` производное, колонка «Уникальный»), «Поля» (поля выборки, ещё не вошедшие в
текущий индекс), «Поля выделенного индекса» (drag&drop + кнопки `>`/`>>`/`<`/`<<`,
порядок ↑↓). Поле адресуется по псевдониму выборки (как Порядок/Итоги). Секция модели
`indexing: { indexes: { unique, fields }[] }`; генератор `renderIndex`. ТЗ:
`tmp/индекс.md`. За рамками: уникальность одиночного индекса (синтаксис
`ИНДЕКСИРОВАТЬ ПО` без `УНИКАЛЬНО`); обратный разбор (фаза 6).
